# Typed IR M2: shared-backend repairs and direct x86-64

Date: 2026-10-21. Kind: implementation and validation record.
Status: direct x86 selection implemented, opt-in. M2 remains open until the
native Linux runtime integration passes. Rosetta is an execution oracle for
adapted generated code, not that Linux acceptance leg or a performance result.

## Integration and shared review

The initial push `d6f8468` included the existing A64 backend and Rosetta probes.
Its [Linux CI run](https://github.com/hyperswine/fprisc/actions/runs/39528948118)
failed because `check_base.py` invoked the native A64 test unconditionally.
The shared selected-IR tests now run on every host; actual backend/runtime
execution is gated separately. `check_typed_ir_a64.py` and
`check_typed_ir_x64.py` call `check_typed_ir_native.py` with an explicit backend.
Linux x86 runs the x86 integration suite; Apple Silicon runs A64. Both are
registered in Base. CI runs them in a named direct-backend step, then passes
`--skip-typed-ir-native` to Base to avoid repeating that completed step.
The Linux x86 step uses `--require-execution`, so a host skip cannot pass CI.

Three defects found during the shared-backend review are repaired:

- Bounds analysis now ends a basic block at every transfer, including a
  conditional branch without a following source label. Previously a
  back-edge before a later fuel reset was grouped with that reset and
  incorrectly reported as finite. The regression was `Just 11` before the
  repair and is now unbounded. A conditional exit bypassing a reset also
  retains its full exit tail. Invalid labels/targets/costs are conservative.
- Selected-IR verification now checks that a fixed-register use has a
  definition, as it already did for an unconstrained use.
- Slot placement rejects load/store callbacks that change flags, control
  flow or calls. The instructions inserted between a comparison and its
  consumer must preserve flags.

The regressions are in `tests/SelectedIR.hs`. A64 selection revision 2
invalidates older bound annotations. Make targets now depend on
`compiler/Codegen/Target/*.hs`, so editing a selector actually rebuilds `fpr`.

## Direct selection

`Codegen/Target/X64.hs` consumes the typed scalar CFG and emits selected
instructions. Shared constraint checking, conservative slot placement,
symbolic frame layout and final native bounds are used by both targets.
`Codegen/Target/Common.hs` owns output records and symbol identity. The x86
path does not generate or parse shared-RISC assembly.

- Two-address operations tie the destination to a source register. Placement
  loads the source from its home first, preserving the original operand for
  arithmetic slow paths.
- Division fixes the dividend/result to `%rax`, declares `%rdx` as the sign
  extension scratch, and excludes both when placing the divisor.
- Multiplication checks hardware overflow and then the language's signed
  63-bit range. Division checks zero first and the 63-bit range afterward.
  Slow paths retag the original operands and call the existing C primitives.
- Calls use SysV's six integer argument registers and `%rax` result. Private
  arguments seven/eight use `fpr_x64_a6/a7` TLS cells. All entry arguments are
  parked before stack checks or fuel ticks can destroy those cells.
- Calls maintain SysV stack alignment. Frames preserve the legacy return
  address/saved-frame-pointer layout; return and tail transfer restore the
  stack from the frame pointer, including after segment growth.
- The hart is read through Linux local-exec TLS at the point of use and
  reloaded after a stack-growth call. No callee-saved integer register is
  used except the saved/restored frame pointer.

Selection is available under the existing `FPR_TYPED_IR_BACKEND=1` or `mixed`
and `FPR_TYPED_IR_STRICT` controls. Cache tags contain `tirbex64-1`, distinct
from earlier unsupported-x86 fallback artifacts. Unsupported-target messages
use the requested target name instead of the shared generator's `rv64` name.

The scope remains hosted Base scalar IR. Shifts are still refused by scalar
lowering, and arities above eight remain legacy. No allocator, default change,
QOS backend, full x86 macOS runtime, or speedup is claimed in this slice.

## Validation and remaining gate

The C oracle now checks 31,689 invocations per mode and 12 exact slow-path
traps, including 64-bit multiplication overflow. Strict direct modes cover
14 functions with scalar workers disabled and 18 with them enabled. The
corpus also includes Bool identity/foreign objects, seven/eight-argument
non-tail calls and recursive rotations, callee-save sentinels, stack alignment,
and deliberately clobbered volatile registers and private argument cells.

Additional mixed binaries substitute legacy callers or legacy callees into
the direct corpus, exercising both directions with the same C oracle. The
unadapted ELF functions are assembled with real TLS relocations before their
Rosetta adaptation. A final baseline repeat checks that enabling the backend
does not contaminate later legacy emission; strict mode must reject an
unsupported high-arity function.

Reproduce locally:

```sh
python3 tests/check_x64_local.py --require-execution
python3 tests/check_typed_ir_a64.py
python3 tests/check_typed_ir_x64.py
```

The local Rosetta harness substitutes Linux TLS and runtime hooks. The native
Linux test uses real `fpr build` executables: whole-unit strict coverage,
legacy/native units, C callers and callees, exact production panic messages,
deep stack growth, one/four harts, cache transitions and mixed selection.
A host skip does not satisfy that gate. The GitHub direct-backend step must pass it
before M2 is closed and M3 allocation/performance work starts.

Validation logs and source identities are recorded in
[`evidence/2026-10-21-typed-ir-m2-x64/`](evidence/2026-10-21-typed-ir-m2-x64/).

Local final run: optimized `make fpr` passed; the expanded Rosetta suite passed
in 15.59 seconds including the build check. The full A64 suite passed again:
20/20 strict-native library functions, 31 independent/differential calls,
100,000-level recursion crossing eight stack segments, one/four harts, cache
transitions, strict fallback and both assembly formats. The Linux x86 entry
correctly reported a host skip on this Mac. No Linux-runtime pass is inferred
from that skip.

## 2026-10-21: native Linux acceptance run

Added 2026-10-21 when the branch was merged to main; the text above was
written before this run and is left as it was.

[GitHub Actions run 39531450292](https://github.com/hyperswine/fprisc/actions/runs/39531450292)
ran on push of `34c3ff9` (this page's commit) and passed: job
"x86-64 (debian trixie)", 30 min 18 s, on a GitHub-hosted x86-64 runner in a
Debian trixie container. Its "Typed IR direct backends (Linux x86-64)" step
ran `tests/check_typed_ir_a64.py` and then
`tests/check_typed_ir_x64.py --require-execution` (27 s). From its log:

- `check_typed_ir_a64.py`: the shared SelectedIR checks passed (x86-64
  constraints and refusals, flag-neutral placement, frame layout,
  conditional-path bounds, the A64 pipeline for Mach-O x28, ELF TLS and Mach-O
  TLV, the direct x64 pipeline, frame ceilings); A64 execution was a host skip,
  as designed on an x86-64 host.
- `check_typed_ir_x64.py --require-execution`, executed natively with real
  `fpr build` executables and the real Linux runtime and TLS (no Rosetta, no
  substituted hooks): `scalarlib` 20/20 functions native under strict mode;
  31 calls equal to the legacy binary and to independent arithmetic; C calls
  native code and is called back; deep recursion crossed 9 stack segments;
  one and four harts; cache transitions off/on/off/mixed/off; mixed mode on
  the M1 fixture; x86-64 ELF with real TLS relocations assembles. Summary
  line: selected vocabulary, whole-unit and mixed native emission with exact
  results and traps, C interoperability, segment growth, harts, cache
  transitions, strict mode, bounds: PASS.

The same job's `check_base.py --skip-typed-ir-native` step then passed, which
includes `check_x64_scalar.py` natively ("31689 C-reference cases, 12 exact
slow-path traps, foreign Bools, 7/8-argument non-tail calls, 7/8/9/64-argument
rotations, callee saves/alignment/volatile clobbers"), and so did the
experimental frame and register modes step and the RV64 Linux (qemu-user)
step. This closes the plan's last M2 box. It is a correctness leg only: no
performance was measured on Linux, and A64 ELF execution on Linux is still not
covered by CI.
