# Sol HTTP: bounded requests and streamed publication

Kind: API, implementation decision and local validation. Applies to the
uncommitted roadmap tree based on `27a4cdc`. Completes the HTTP portion of
[Phase 4](2026-10-29-SOL-LIBRARIES-PHASE4.md); installation and the cross-host
release gate remain Phase 5 work.

## Public interface

`sol/lib/http.sol` supplies request/option construction helpers. The operations
and types below are preprovided:

```sol
HttpRedirects = Type (NoRedirect | RedirectHttps Int | RedirectHttp Int).
HttpRoute = Type (HttpRoute String Int String).
HttpOptions = Type (HttpOptions Int Int Int HttpRedirects String (List HttpRoute)).
HttpRequest = Type (HttpRequest String String (List (String, String)) Bytes).
HttpResponse = Type (HttpResponse Int (List (String, String)) Bytes).
HttpInfo = Type (HttpInfo Int (List (String, String)) Int).
HttpError = Type (HttpError HttpReason Int String).

Http.backend : Unit -> Result String HttpError.
Http.request : HttpOptions -> HttpRequest -> Result HttpResponse HttpError.
Http.download : HttpOptions -> HttpRequest -> String -> Bool -> Result HttpInfo HttpError.
```

Options are **deadline milliseconds, body-byte budget, aggregate response-header
byte budget, redirect policy, CA file, DNS routes**. Request fields are **method,
URL, headers, raw body**. Response fields are status, headers and immutable body;
Info replaces the body with the received byte count. `H.defaultOptions` selects
30 seconds, 1 MiB body, 64 KiB headers, NoRedirect, system CA roots and ordinary
DNS. `H.get`/`H.head` construct requests. `withDeadline`, `withBodyLimit`,
`withHeaderLimit`, `withRedirects`, `withCA` and `withRoute` change options.
`H.header name headers` returns every matching value, without combining duplicates.

Methods are GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS. GET/HEAD require an
empty request body; upload bodies are immutable Bytes, at most 16 MiB. URLs must
explicitly use http:// or https://; userinfo and control characters are refused.
The adapter does no shell parsing or implicit URL escaping. URL/CA paths admit
at most 8192 characters. Request headers admit 128 entries, 256-character token
names, 8192-character values and 64 KiB total encoded bytes. CR/LF/NUL controls
are refused; framing, host, connection, compression and Expect headers are
adapter-owned. Custom header values encode as UTF-8.

## Limits, transport and TLS

Http.request materializes at most 16 MiB of response Bytes. Http.download streams
the network body into private disk staging with constant-sized I/O buffers and
admits up to 1 TiB; it does not materialize the body in the parent. Zero body
budget accepts only an empty received body (HEAD remains bodyless regardless of
the advertised content length). Excess Content-Length is refused before transfer
where available; callbacks enforce the limit on unknown-length/chunked data too.
The returned body is dechunked, with content encodings such as gzip left raw.
There is no automatic decompression that could grow beyond the byte budget.

The response-header budget is 0..1 MiB **across all status lines, framing,
interim responses, redirects and trailers**, not just the final header list.
Libcurl's own per-header-line cap also applies. Returned names are lower-case
ASCII; values preserve each byte as the corresponding Latin-1 code point,
with surrounding HTTP whitespace removed. Duplicate headers retain order.
Interim/redirect headers are discarded from the final list; final trailers are
included. Malformed headers, truncated bodies and transport failures are errors,
without silent truncated success.

TLS verifies both the certificate chain and URL hostname. Empty CA path uses
the library/system trust store; an explicit CA file supplies roots. There is no
insecure flag. `HttpRoute host port address` changes DNS routing for that exact
host/port while preserving the URL hostname for TLS/SNI and HTTP Host. Routes
are explicit, at most 32; they are useful for local fixtures and controlled host
routing. withRoute replaces the previous entry for the same case-insensitive
host/port. The adapter ignores netrc and ambient proxies and does not load curl
configuration files. It has no cookie jar, automatic authentication or external
credential-store integration.

NoRedirect returns a 3xx response for caller inspection. RedirectHttps n follows
only HTTPS targets; RedirectHttp n explicitly permits HTTP and HTTPS targets,
including a downgrade. The limit is 0..20; zero follows none and fails on the
first attempted redirect. Automatic following is restricted to GET/HEAD so a
mutating method is not silently replayed. Other schemes are forbidden on both
initial requests and redirect targets.

## Ownership, errors and publication

The linked host dependency is **libcurl >= 8.4 with HTTP, HTTPS and TLS support**,
checked at build and runtime; no curl executable is required. Each request runs
in the same fpr binary's isolated native worker. The parent sends a bounded
request description through a private 0700 scratch directory. Raw binary data
never passes through a String or shell. The request worker uses libcurl and
bounded disk sinks; the existing owned-process runner supplies group cancellation
and direct-child reaping. This also bounds a blocked resolver without depending
on cancellation inside a foreign library call.

Deadlines are 1..86,400,000 ms and cover worker startup, transfer, result reading
and download publication. Timeout, Ctrl-C, actor cancellation or runtime failure
unwind the worker owner, kill its process group and wait before scratch cleanup.
Ctrl-C retains runner status 130. Hard process crashes cannot perform this
cleanup; the transfer also has a native timeout, and scratch may need removal.
There is no general remote-effect rollback or exactly-once guarantee.

Both request and download are immediate external operations. They refuse pending
buffered effects and participate in guarded retry. A later conflict fails without
repeating the request; Script.replayable explicitly accepts replay. A method
spelled GET is not proof that the server has no side effects. Backend/version
inspection alone performs no request.

Http.request returns **Ok for completed non-2xx responses**, so status, headers
and error bodies can be inspected. Http.download publishes only a fully received
and closed **2xx** body. It uses bounded copy to a same-directory private stage,
then no-clobber link publication or explicit replacement. Existing regular-file
mode bits are preserved on replacement; symlink/nonregular replacement is refused.
It is immediate publication, outside the buffered file transaction, without an
fsync durability promise. Transfers that fail before publication leave the old
destination intact. Cancellation at the publication boundary can leave a complete
new destination; no partial destination bytes are exposed, and a completed
publication is not rolled back. The timeout diagnostic states that uncertainty.

HttpReason is one of HttpInvalid, HttpUnavailable, HttpTls, HttpTimeout, HttpLimit,
HttpRedirect, HttpTransport, HttpIo or HttpStatus. Match this constructor rather
than parsing messages. The integer is a libcurl detail code where available,
the response status for HttpStatus, or zero for local validation/timeout/I/O.
Messages provide the relevant limit or failure. Oversized body/header results
are distinct limit errors; non-2xx download refusal is HttpStatus.

## Runnable workflows and evidence

- `sol/scripts/http-fetch.sol URL OUTPUT [--replace]` streams and publishes a
  2xx response, reporting its byte count after success.
- `sol/scripts/http-json-field.sol FIELD URL OUTPUT` captures bounded JSON,
  requires a string field, and updates the output transactionally. Network,
  malformed JSON, schema and status errors preserve the existing output.
- `tools/sol-http-check.py`: 61 loopback-only checks cover binary capture/upload,
  status/header/trailer access, exact limits, unknown-length/chunked bodies,
  redirects/downgrade policy, validated TLS and hostname refusal, timeouts,
  actor cancel/Ctrl-C, guarded replay, publication/modes, JSON transforms and
  repeated descriptor use. It runs with PATH=/nonexistent and the existing
  public TLS test fixtures; no public service, account or live credential.
- `tools/sol-http-check.py --benchmark OUTPUT`: independent streamed hashlib
  verification plus system RSS and sampled memory for the parent/worker family
  at 100 MiB and 1 GiB. The saved
  [report](evidence/2026-10-29-sol-phase4/http-memory.json) records source/binary
  hashes, settings, commands and samples. Family-memory growth was about 8 MiB,
  within the 32 MiB gate. The ps samples are observations, not a hard combined-RSS
  maximum; system time's RSS is retained separately. The host was also preparing
  the Linux VM, so wall times are not controlled cross-version comparisons.

Local fixtures need permission to bind loopback sockets. The restricted run was
refused by the OS; the permitted run passed. The macOS delivery evidence is local,
not a hosted-CI or Linux claim. Linux x86-64 is being built for Phase 5 separately.

Implementation references: libcurl documents
[write/header callbacks](https://curl.se/libcurl/c/CURLOPT_HEADERFUNCTION.html),
[protocol restrictions](https://curl.se/libcurl/c/CURLOPT_PROTOCOLS_STR.html) and
[in-progress byte limits](https://curl.se/libcurl/c/CURLOPT_MAXFILESIZE_LARGE.html).
The adapter enforces its own callback budgets as well as the native byte limit.
