# Typed IR, milestone M2: the direct AArch64 backend

Date: 2026-10-21. Kind: implementation record for
[the typed native IR plan](2026-10-20-TYPED-NATIVE-IR-PLAN.md), milestone M2,
first half (AArch64), on the branch `codex/a64-overflow-checks-20261020`
at codegen revision 67 (unchanged: the legacy emission is byte-identical
with the backend off). The runtime contracts it relies on are the
[M0 register](2026-10-21-NATIVE-IR-CONTRACTS.md)'s; the IR is
[M1](2026-10-20-TYPED-IR-M1.md)'s with the
[review repairs](2026-10-21-TYPED-IR-M1-REPAIRS.md).
Audience: compiler implementers and reviewers.

This change adds an opt-in backend that emits AArch64 directly from the
typed IR for the M1 scalar subset under the hosted Base profile, with every
virtual value in a frame slot and no register allocation. It makes no
performance claim and measures none; a function through this backend is
slower than the legacy one (every temporary is stored and reloaded), which
is the stated M2 shape. x86-64 selection, the second half of M2, is open
(see "What was not done").

## Switches

| Variable | Values | Effect |
|---|---|---|
| `FPR_TYPED_IR_BACKEND` | `1` (whole units), `mixed` (per function) | route emission through the typed-IR backend; unset: the legacy generator, byte for byte |
| `FPR_TYPED_IR_STRICT` | `all`, or `f,g,h` (unqualified names) | a fallback of a named function (or of any function) fails the compile, naming the function and the reason |
| `FPR_TYPED_IR` | as in M1 | the diagnostic report; still changes no emitted code and is still no cache key |

The name: the `FPR_TYPED_IR` family groups the three variables; `_BACKEND`
says this one selects emission where the bare variable only reports;
the value `1` is the form every other opt-in switch takes
(`FPR_SELF_LOOPS=1`), `mixed` names the other granularity. `_STRICT` is
the plan's "strict coverage mode" by its own name.

Both switches and the selection revision are in the unit-cache identity
(`Compile.hs` `tag`: `-tirbe<rev>`, `-tirbe<rev>mixed`, `-strictall` or a
hash of the strict names) and in the run-cache key (`Build.hs` `runKey`).
`Codegen.Target.A64.a64SelectionRev` is the revision; it is 1.

Whole-unit granularity is the default, as the plan asks until the ABI
interoperability tests pass. They pass in this change (below), and the
`mixed` granularity is offered behind its own value with the same tests
rather than promoted: a mixed unit's legacy functions, native functions
and C callers all meet at the same generated-code ABI, which is what the
tests establish.

Under the backend, a unit whose functions all lower and select is
emitted natively; the notes say `typed-ir-backend: native N/N functions
(whole unit)` and one line per function with its frame size and bound.
Otherwise every function of the unit stays legacy and each declined
function is reported with its reason (`typed-ir-backend: f fallback:
...`). The root of a program, holding `main` with its strings and
`Sys.args`, always falls back as a unit today; a module unit of scalar
functions goes native, which is how the fixture is built. A verifier
failure, an invalid selected instruction, a placement failure or a frame
beyond the ceiling are compiler errors, never silent fallbacks (the frame
ceiling is reported as a refusal by name; see "Selection").

A target without a direct backend (x64, rv64, rv32, the QOS and builtin
profiles) reports the reason and stays legacy; strict mode then fails.

## Policy

`Codegen.Policy` is the explicit target and profile policy the lowering
takes (`Codegen.Lower.lowerProgram` and `lowerFn` now take it first):
the profile (`HostedBase`, `Builtin`, `BuiltinArc`, `QosApp`, `Rv32`),
whether fuel is on, and the stack-check rule. `Compile.hs` derives it
from the options; M2 implements `HostedBase` with fuel and a stack check
at every entry (`m2Policy`). Every other profile is refused by name
("the builtin profile has no typed-IR native lowering in M2"), as is
the legacy shallow rule (`StackCheckLegacyShallow` is declared so that
the choice is written down; the backend checks every entry, which the M0
register allows provided calls and bounds account for it, and they do:
the stack check is a counted C call in every function's bound).

| Module | Responsibility |
|---|---|
| `Codegen/Policy.hs` | the policy record and its validation |
| `Codegen/Selected.hs` | the selected-instruction structure: virtual registers with a class, fixed or tied constraint; implicit uses and definitions; clobbers; flag use and definition; control effect; the calls inside an instruction; `checkFn`, the validity rules |
| `Codegen/Frame.hs` | symbolic frame objects (size, alignment, kind, managed status, escape) and `layout`: the legacy frame shape |
| `Codegen/Place.hs` | conservative placement: every virtual register in its own slot, loaded and stored around each instruction under its constraints |
| `Codegen/Bounds.hs` | structured segment analysis over the final stream: `native-insns-v1` |
| `Codegen/Target/A64.hs` | selection from the IR, the A64 register file and scratch pool, the frame ceiling, rendering (Mach-O and ELF), the bound line |
| `Codegen.hs` | `nativeSelect` and `emitProgramWith`: which functions of a unit take the backend, the notes, the native text appended after the legacy lowering |
| `Compile.hs`, `Build.hs` | the switches, the policy, strict mode, the cache identities, the two bound summaries under `FPRC_WCET` |

### The selected-instruction vocabulary and x86-64

`Selected.hs` is written with x86-64's needs in it from this commit, as
the plan requires, although no x86-64 selection exists yet:

- `Tied i`: a definition that must be the register of use operand `i`
  (two-address arithmetic and shifts);
- `Fix p`: a fixed register (the division registers `%rax`/`%rdx`, the
  shift count in `%rcx`, argument and result registers, where the first
  argument's `%rdi` and the result's `%rax` differ);
- implicit uses and definitions (`%rdx` as the dividend's sign
  extension, `%rsp` of a call-alignment pseudo), clobbers (the SysV
  caller-saved set at a call), flag use and definition (`cmp`/`setcc`,
  `cset`, `csel`, `b.cond`), symbols as operands (the `fpr_x64_a6`/`a7`
  TLS cells of a wide call).

`tests/SelectedIR.hs` writes those shapes down against an x86-64 register
file, checks that `checkFn` accepts them and refuses thirteen
malformations by name (a tied operand that does not exist, is not a
virtual register or has another class; a tied use; a fixed reserved or
non-existent register; a result both defined and clobbered; a call
without clobbers; two uses fixed to one register; a branch to an
undefined label; a value never defined; a value with two classes; a label
defined twice), and that conservative placement honours them (the tied
definition reuses its use's register, fixed operands take theirs, the
shift count lands in `%rcx`, scratch never collides with a fixed or
implicit register, exhaustion is a named failure).

### Frame objects and layout

A frame object has a size, an alignment, a kind (a spill slot of a
virtual register, a saved register, a temporary), whether it may hold a
managed reference and whether its address escapes. `layout` places the
link area (the return address at fp-8, the caller's frame pointer at
fp-16) and the objects below it in creation order, 16-aligned: the legacy
frame shape (`Codegen.compileFnBody`, register-allocation design 1.1).
Nothing is shared or reused; slot reuse with compatible lifetime,
representation and root status is M3's.

### Placement

`placeInSlots` gives every virtual register (the IR's values and every
temporary selection introduced) a slot. Before each instruction its uses
are loaded into registers that satisfy their constraints (a fixed
operand into its register, the rest into the target's scratch pool,
never a register the instruction names implicitly or clobbers); after
it, its definitions are stored (a tied definition in its use's register).
No value is in a register between two instructions, so no value is live
across a call, a safepoint or a stack-segment change, and no clobber can
reach one. The loads and stores a target supplies are flag-neutral; an
instruction that reads flags therefore sees the flags its predecessor
wrote. A return or tail transfer defines nothing (checked).

## Selection: what each IR operation becomes

The A64 register file: `x0..x30` and `sp` integer, `d0..d31` float;
reserved as operands: `sp`, `x16`, `x17` (the expansions' scratch), `x18`
(the platform register), `x28` (the hart register), `x29`, `x30`. The
placement's scratch pool is `x9..x15`. A C call clobbers `x0..x17` and
`x30`. No callee-saved register is used, so none is saved: `x19..x27`
are untouched, which is what `ctx_a64.S` (which saves exactly those and
`x29`) requires.

| IR | Selected (before placement; `t` are temporaries) |
|---|---|
| `const n` | `li` (`mov`, or a `movz`/`movk` chain) |
| `nullary t v` | `la` of `fpr_unit`, `fpr_false`, `fpr_true` for (0,0), (1,0), (1,1); else the unit's `.Lnul_t_v`, which the legacy rodata emits (the native functions' references are added to `cgNulls`) |
| `tag v` | `lsl t, v, #1`; `orr d, t, #1` |
| `untag v` | `asr d, v, #1` |
| `boolof p` | `la f, fpr_false`; `la t, fpr_true`; `cmp p, #0`; `csel d, t, f, ne` |
| `truth v` | `ldursw d, [v, #4]` (the Bool object's variant) |
| `not p` | `eor d, p, #1` |
| `isint v` | `and d, v, #1` |
| `tagtest t c v` | `and`, `cbnz miss`, `ldursw [v,#0]`, `li`, `cmp`, `b.ne miss`, `ldursw [v,#4]`, `li`, `cmp`, `cset eq`, `b done`; `miss: li d, 0`; `done:` (an Int never reads a header) |
| `cmp o a b` | `cmp a, b`; `cset d, <lt gt le ge eq ne>` (signed) |
| `eqval`/`neval a b` | `and`, `and #1`, `cbz slow`; `cmp a, b`; `cset eq/ne`; `b done`; `slow:` `bl fpr_prim_fn__x3d_x3d` (or `_x21_x3d`) with a, b in x0, x1; `ldursw d, [x0, #4]` (the legacy `$arc.eq` guard: two tagged Ints compare inline, anything else is the C primitive's deep equality) |
| `arith + - a b` | `add`/`sub t, a, b`; `sbfx n, t, #0, #63`; `cmp n, t`; `b.ne slow`; `mov d, t`; `b done`; `slow:` retag a and b (`lsl`, `orr #1`), `bl fpr_prim_fn__x2b`/`_x2d`, `asr d, x0, #1` |
| `arith * a b` | `mul t, a, b`; both operands within 31 bits (`sbfx #0,#31`, `cmp`, `b.ne wide`) go to the fit check; `wide:` a zero divisor fits, else `sdiv q, t, b`; `cmp q, a`; `b.ne slow`; `fit:` the 63-bit fit check; the same slow path with `fpr_prim_fn__x2a` (the legacy `ScalarChecked "*"`) |
| `arith / a b` | `cbz b, slow`; `sdiv t, a, b`; the fit check (the most negative Int / -1); the slow path with `fpr_prim_fn__x2f` |
| `call f(args)` | arguments in `x0..x7` (fixed), `bl fpr_fn_<mangled>`; result in `x0`; `Foreign` callees are `bl fpr_prim_fn_<mangled>` (core primitives) or `bl fpr_g_<mangled>_call<n>` (declared HAL/foreign primitives, six arguments at most), exactly the legacy `known` and HAL paths |
| `safepoint` (inlined `$fuel`) | the tick: hart read, `ldur`, `sub #1`, `stur`, `cmp #0`, `b.gt ok`, `bl fpr_fuel_exhausted`, `ok:` |
| entry `stackcheck` + `safepoint` | one pseudo: hart read; `mov x10, sp`; `ldr x11, [x9, #456]` (stk_lo); `sub`; `ldr x11, [x9, #464]` (stk_span); `cmp`; `b.lo stk`; `bl fpr_stack_grow`; `cbz x0, same`; `mov sp, x0`; `same:` hart read again; `stk:` the tick (the legacy sequence, `Codegen.compileFnBody` `stackCheck`/`fuelCheck`) |
| `ret v` | `x0 <- v`; `ldur x30, [x29, #-8]`; `mov x9, x29`; `ldur x29, [x29, #-16]`; `mov sp, x9`; `ret` |
| `br entry(args)` (self tail call) | arguments in `x0..`, the epilogue, `b fpr_fn_<self>`: the legacy transfer, so the entry runs its parameter stores, stack check and tick again |
| `br b(args)` | a parallel copy into the block parameters (cycles broken with a fresh temporary), `b` |
| `condbr p -> t(as) \| e(bs)` | `cbnz p`, `b`; with edge arguments, an edge block per side holding its copies |
| `tailcall f(args)` | arguments in `x0..`, the epilogue, `b <symbol>` (generated or foreign) |

The hart read is `mov x9, x28` under `fpr build` (hosted AArch64 reads its
hart from x28; `Compile.hs` applies `deTlsQosAppA64` to the legacy text
for the same reason), the Darwin TLV descriptor call for `a64mac` without
`--base` (saving x0 and x30 around it, as `A64.hs` does) and the
local-exec TLS sequence for `a64` ELF. Every read happens where it is
needed, after any call that may have moved the actor to another hart.

The prologue is the legacy one: `sub sp, sp, #frame`; the return address
and the caller's frame pointer at the top of the frame; `add x29, sp,
#frame`; the parameters stored to their slots from `x0..x7`; then the
entry pseudo. Frames beyond 4095 bytes build the immediate in `x16`;
slot offsets beyond the unscaled range go through `x16` too (the legacy
`farBase`). The frame ceiling is 32768 bytes, half the hosted runtime's
`FPR_STACK_HEADROOM` (64 KiB, `runtime/actors.c`): the check runs after
the frame decrement, so a frame must stay well inside the headroom the
runtime keeps for C below `stk_lo`. A larger frame is refused by name
(`a frame of N bytes exceeds the 32768-byte ceiling`); the legacy
generator has no such ceiling and no such check.

Labels are `.Ltir_<mangled function>_<n>` (`L...` on Mach-O), unique
across the unit. The native text is appended after the legacy lowering
of the unit (`.text` again), so the unit's rodata, string and nullary
objects, module table and function objects stay the legacy emitter's.

### Lowering changes

`Codegen.Lower` takes the policy and a map of the primitives with a
direct C entry (`Codegen.foreignEntries`: core primitives at any arity
as `fpr_prim_fn_<name>`, declared HAL/foreign primitives up to six
arguments as `fpr_g_<name>_call<n>`, core primitives winning as in
`genT`'s `known`). A saturated call to one lowers to a `Foreign` callee
carrying its symbol, in value and tail position; the names the legacy
generator expands inline (`$arc.*`, `$scalar.*`, `F64.*`, the operators,
`charAt`, `strlen`, `band`, `bor`, `bxor`, `BITSHIFTL`, `BITSHIFTR`)
stay refused. The evaluator reports a foreign call as stuck (it models
no C). This widens the scalar subset by one call shape; it is what lets
a native function call back into the C harness, and it is also why the
prelude's `Actor.*` and `Int.*` entries lower in mixed mode.

## Bounds

`Codegen.Bounds.analyse` runs over the rendered stream, each selected
item with its instruction count, control effect, whether its last
instruction is a safepoint boundary (the entry pseudo, an inlined tick,
a call or tail transfer to a generated function) and how many C calls it
holds. The result is `# native-insns-v1: <name> segmax=N exittail=N
ccalls=N` after the function: the longest run of A64 instructions
between boundaries, the longest run from a boundary to an exit, the C
calls. A cycle without a boundary is `UNBOUNDED`, which is a fallback
reason (in strict mode a failure); none occurred in the fixtures. The
legacy `# wcet:` label is never attached to native code; `FPRC_WCET=1`
prints the legacy table with a note that the native functions are not in
its bound, then a separate `[native-insns-v1]` table. Neither is elapsed
time, and this metric is not interchangeable with the legacy count: it
counts target instructions after placement, whose spill loads and stores
the legacy metric never sees.

M1 check:

  on hand-written token streams (an unticked cycle is `UNBOUNDED`, a
  ticked one is bounded by its length, the exit tail), and the A64 pipeline
  end to end on a hand-written IR function in the three hart-access
  configurations, and the frame ceiling as a named refusal.
- `tests/typed_ir/scalarlib.fpr` (a module unit: the M1 scalar functions,
  `mulovf`, callbacks into C in value and tail position, a deep non-tail
  recursion that marks every level in the harness, a loop whose block
  parameters swap) under the legacy root `tests/typed_ir/scalar_mod.fpr`
  with the C harness `tests/typed_ir/tir_probe.c` (`--with`). Built with
  `FPR_TYPED_IR_BACKEND=1` and the fifteen library functions under
  `FPR_TYPED_IR_STRICT`, the unit is 20/20 native (its scalar workers
  included) and the root falls back as a unit. Thirty-two calls answer
  what the legacy binary answers and what independent arithmetic says
  (the expected values are written in the script, not read from a
  compiler), traps word for word: the overflow of `+`, `*` (both the
  31-bit fast path's exit and the division check: 3037000500², 2³¹·2³¹)
  and `/` (the most negative Int by -1), the zero divisor; `*` and `/`
  results on both sides of the fast paths; truncating division.
- C interoperability: the harness calls native `fib`, `sum`, `addovf` and
  `cbSum` through the function values the root hands it (`call1`,
  `call2` read the code pointer of the static PAP), so a C caller enters
  native code with tagged words in `x0..` and reads `x0`; `cbSum` and
  `cbTail` call `TirProbe.cb` from native code in value and tail
  position; the overflow trap raised inside a C-called native function is
  the primitive's text.
- Deep recursion: `deep 100000` (non-tail, every level a C call) answers
  100001 on both backends; the harness saw the native frames in 8 stack
  segments (the legacy frames, smaller, in 7): `fpr_stack_grow` moved
  `sp` to new segments and every frame returned into its own.
- One and four harts (`--harts 1`, `--harts 4`): the same answers,
  including `sum 3000000 0`, whose fuel runs out many times.
- Cache transitions off/on/off/mixed/off: each build's unit files carry
  the identity of its mode (`g67rt3pc5...`, `g67-tirbe1rt3pc5...`,
  `g67-tirbe1mixedrt3pc5...`), the answers are the same throughout.
- Strict mode names the function: `FPR_TYPED_IR_STRICT=fib,main` on the
  M1 fixture fails with `main: the primitive or HAL value \`Unit\``.
- Mixed mode on the M1 fixture `tests/typed_ir/scalar.fpr`: 14/22
  functions native in the root beside the legacy `main`; the same nine
  calls as the legacy binary (and the prelude unit at 113/267 native,
  through which `print` and `parseInt` ran).
- Emission: with the backend off the assembly holds no `typed-ir a64`
  header and no `native-insns-v1` line; on, every native function has a
  finite bound and no `# wcet:` label, every legacy function keeps its
  `# wcet:` line; `FPRC_WCET=1` prints the two tables apart.
- The Mach-O TLV variant (`--target=a64mac` without `--base`) and the ELF
  variant (`--target=a64`) assemble with clang (`-target
  aarch64-unknown-linux-gnu` for ELF).
- The legacy emission with the backend off is byte-identical to the
  pre-change compiler's: the kept root assembly of the M1 fixture and the

## What was not done, and what is next

- **x86-64 selection is open.** The second half of M2 (`Codegen/Target/X64.hs`
  through the constraint model, native Linux execution) was not started;
  the vocabulary and its tests are the preparation the plan asked for.
  `FPR_TYPED_IR_BACKEND` on an x64 target reports "no typed-IR native
  backend for x64" and stays legacy.
- No register allocation: every virtual value is in a slot (M3). The
  generated code is larger and slower than the legacy generator's; no
  timing was taken and none is claimed.
- No simplification: materialised Bools, repeated `untag`s and
  conversion pairs are emitted as lowered.
- The frame ceiling (32768 bytes) is this backend's; the legacy generator
  has none. Arities above eight (the hart spill cells) are still refused
  by the lowering.
- Not verified: anything on a board, under QOS, on Linux (the ELF text
  was assembled, not run), the TLV variant beyond assembling, the
  `all` strict mode on a corpus (the prelude never passes it today),
  the bench corpus coverage under the backend.
- The mixed granularity is behind its own value and tested; promoting it
  to the default, or promoting the backend at all, is a decision the
  plan reserves for M5.

Next, per the plan: x86-64 selection through this vocabulary with native
Linux execution (closing M2), then M3's liveness and allocation.
