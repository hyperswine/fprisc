# fprisc architecture review (hyperswine/fprisc, main @ ff96204, read-only)

Recent work (since about 2026-10-15): the typed IR became the default (a29bb2a). The AArch64 and x86-64 translators were retired (f1ba409, d72cf63). Legacy generation was retired for every profile (2223fec), and native instruction auditing landed (afebff1). Backend now: Core -> Codegen.Lower -> Codegen.IR (SSA, block parameters instead of phis, representation types TVal/TInt/TRaw/TPred/TAddr/TF64) -> Verify/Simplify/Split -> per-ISA selection (Codegen/Target/{A64,X64,RV}.hs) into Codegen.Selected (virtual-register machine instructions with constraints) -> Codegen.Allocate (linear scan) -> Frame -> text assembly. Codegen.Eval is a reference interpreter for the IR. This is a design in the Cranelift/QBE style and it is sound.

## Ranked opportunities
1. **Split the Core-level optimisations out of Codegen.hs (1716 lines).** Vector fusion (fuseVecFix, nestPipelines), specialisation plans (SpecPlan/PipePlan/MvPlan/RvvPlan, typePlan), `declines` and target dispatch all live in one module. Better: a `Core.Opt.*` pass list, each pass Prog -> Prog with its own verify step, run by a GHC-style pipeline driver. Codegen.hs would shrink to a backend driver. Effort: medium, mechanical.
2. **Make Core a typed, uniquely-named IR.** `FPRISC.Core` is untyped and uses `Name = String` (freshRoot-style renaming). Lowering has to rebuild representations, Workers/Reuse/Kernel redo shape inference, and capture/shadowing bugs are possible. Better: Core binders carry a Unique plus the Infer type (like GHC Core or OCaml Lambda/Flambda). That deletes re-derivation code in Lower/Workers/Kernel and makes a Core lint possible. Effort: large.
3. **Structured diagnostics.** Infer and Safety return `[String]`, and positions travel as a "@OFF~ " prefix in the text that the error sinks later turn back into file:line:col. SExpr carries positions through an `SMark` wrapper that every matcher has to `unmark`. Better: `data Diag = Diag Span Severity Code Doc`, with spans on the AST nodes (or an annotated AST via a type parameter). This prevents lost or misplaced positions and string-parsing bugs. Effort: medium.
4. **Env-var feature flags into one typed Options record.** Build.hs:321 reads 22 `FPR_*` variables, and Compile.hs reads more (FPR_TYPED_IR_BACKEND, still accepting "legacy" only so it can refuse it, plus STRICT). Better: CLI flags parsed once into an Options record (like `-fno-*`), with the M2/M3 rollout toggles that are now always on deleted (SELF_LOOPS, FORWARD_PARAMS, SPLIT_ENTRY, SHRINK_WRAP and so on). This deletes dead paths and stops builds from depending on whatever happens to be in the environment. Effort: small.
5. **Typed machine instructions instead of string mnemonics.** `SInstr` uses `plain "tailjump" [...]`, and `OS String` for symbols. Selection and emission can disagree on spelling or arity, and the "complete native instruction auditing" exists partly to catch exactly that. Better: one ADT per ISA (`data X64Op = Mov | ...`), the LLVM MachineInstr / Cranelift `MInst` approach, with one printer per ISA (or Cranelift-style ISLE-like pattern tables). Typos become compile errors. Effort: medium per target; do x64 first.
6. **Register allocator quality and ABI generality.** Codegen/Allocate.hs is a basic linear scan: it spills the interval with the fewest accesses and keeps a spilled value in its slot for the whole range. The header calls it "an initial allocator". The x64 ABI puts args 7 and 8 in private TLS cells, not on the SysV stack, so foreign calls with more than 6 args can't follow the convention. Better: interval splitting at block boundaries plus a move-resolution pass (as in Cranelift regalloc2 or Wimmer linear scan). Also add an explicit per-target `CallConv` value used by both Lower and selection, with proper SysV/AAPCS stack arguments for foreign callees. Effort: medium to large; check the C-interop need before starting.
7. **A real test suite.** There is no cabal `test-suite`: tests/*.hs (TypedIR, AllocIR, SelectedIR...) sit next to 300+ .fpr/.c/.S files driven by the Makefile and scripts (plus a new TESTING.txt). Better: a tasty/hspec suite plus golden tests, and QuickCheck differential testing of `Codegen.Eval` against native execution. The evaluator is already there, so that comparison is cheap and very effective. Effort: small to medium.
8. **The 3120-line FPRISC.hs.** One module holds the lexer, parser, surface AST, desugarer and the linearity/autoDrop analysis. Better: Syntax/Lexer/Parser/Desugar/Linearity modules, with eval desugaring and arity spilling moved out of the parser module. Effort: small. Rebuilds get faster and the passes get clearer owners.

## Leftovers made obsolete by the typed IR
- Comments still point at the deleted `Codegen.inlineTable`, the "legacy generator", the "legacy frame" and the "legacy `la a0, ...`" as the semantic reference: Codegen/IR.hs (header, constructor comments, line ~144), Lower.hs, A64.hs, X64.hs, Frame.hs, Eval.hs and Bounds.hs (the legacy `# wcet:` metric). The reference is now Codegen.Eval plus runtime.c, so re-anchor those comments.
- The `FPR_TYPED_IR_BACKEND=legacy` refusal branch (Compile.hs:429), and the env names that still say "TYPED_IR" even though there's no other backend.
- `emFallbacks` (Codegen.hs:108,360): there's nothing left to fall back to, so it's now only an error path. Rename it to refusals or make it a typed error.
- `typedIrNotes`/`tgtTypedIr`: the M1 "report only" mode ("changes no emitted code").
- Docs: docs/2026-10-19-REGISTER-ALLOCATION.md and others describe the Codegen.hs frame-slot generator as current, so mark them historical.

Not reviewed in depth: Sol/* (the VM/JIT, a separate subsystem), runtime GC internals, module reload. has_vec (runtime.c:1316) is a recursive object walk. If it runs on a hot path, caching a "contains vec" header bit set at allocation would be the standard fix, but I didn't verify the call frequency.
