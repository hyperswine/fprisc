# A WebAssembly VM in FP-RISC

Date: 2026-10-05. Kind: implementation record. Applies from revision
`927e9e0` plus `examples/wasm/`. A port of the Haskell interpreter in
`HaskPlayground/src/WASM` (WasmVM, WatParser, Actors, Main, TestMain) to
FP-RISC source only: no C and no new primitive.

## What is there

| File | From | What it is |
|---|---|---|
| `examples/wasm/wasmvm.fpr` | WasmVM.hs | the small-step interpreter: values, instructions, numerics, memory, frames, `step`, `runToEnd`, `invoke` |
| `examples/wasm/wat.fpr` | WatParser.hs | text format to a module: S-expressions, names, folded and flat instructions, the opcode table |
| `examples/wasm/actors.fpr` | Actors.hs | descriptor tables, the grant cache, fuel slices, the round-robin scheduler, one prompt per round |
| `examples/wasm/calc.fpr` | Main.hs | the calculator demo; with arguments, your own expressions |
| `examples/wasm/wasmtest.fpr` | TestMain.hs | the 57-case semantics suite over `tests.wat` |
| `calc.wat`, `ticker.wat`, `tests.wat` | examples/ | copied unchanged |

    ./fpr run examples/wasm/calc.fpr
    ./fpr run examples/wasm/calc.fpr "6 * 7" "81 / 9"
    ./fpr run examples/wasm/wasmtest.fpr

## What was checked

- `calc.fpr` with no arguments prints the same transcript as the Haskell
  `WASM.Main`, byte for byte (calculator and ticker interleaved, the
  capability prompt, then four more expressions).
- `wasmtest.fpr` passes 57 of 57. The Haskell passes 55 of the same 57: its
  parser loses the sign of `-0` (copysign) and misreads `f32.const nan`
  (truncsat_nan). The port reads both.
- Not checked: differential testing against wasmtime (`difftest.py`), and
  anything beyond these three modules.

## How the port differs

**Integers.** An FP-RISC Int is 63 bits. An i32 is held as its unsigned
value; an i64 is two unsigned 32-bit halves, with add, subtract, multiply
(16-bit limbs), shifts, rotates, comparison and bitwise long division
written out. No product in the VM exceeds 2^48, so nothing depends on how
Int overflow behaves.

**Floats.** F32 and F64 carry the arithmetic. There is no primitive from a
float to its bits, so `reinterpret` and float stores find the exponent by
scaling. `F64.pow` is not exact even for 10^1 (it made `2.5` parse as a
neighbour of 2.5), so powers of two and ten are repeated multiplication.

**The instance is a value.** Haskell keeps memory and globals in IORefs.
Here the VM record carries the instance, `Finished` hands it back, and the
caller threads it to the next call. Linear memory is a sparse persistent
map from address to byte.

**Step is the same record trick.** Running out of fuel or meeting an import
returns the record. The scheduler is the Haskell one, clause for clause.

## Language notes from writing it

- An operator on floats needs a signature in scope: without one `a + b`
  is Int arithmetic on the bit patterns, with no diagnostic.
- `cases` cannot be used as a name in an expression (it reads as `case`
  then `s`), and the error is reported at an earlier binding.
- `fn` is reserved, so it cannot name a parameter. A lambda cannot take a
  tuple pattern; `fn p -> case p of (a, b) -> ...` does.
- A record type with free type variables works as a constructor field.

## Not done

- **Memory use.** Nothing is reclaimed while a VM runs: the suite peaks at
  about 100 MB, almost all of it `fib 20`. A long-running guest needs code
  as a flat array with program counters, so the state is small enough to
  step under `Sys.loopWith`, and memory as a `Vector`.
- **Speed.** Locals and memory are AVL maps; a byte write is a map insert.
- The binary format, WASI preview1, validation before execution, typed
  blocks by `(type $t)`, hexadecimal float literals.
- `f32.convert_i64` and decimal literals with more than 15 digits may
  round twice.
- The fixed numbers are the Haskell's: call depth 2000, 1024 pages, fuel
  slice 60, host call cost 10.
