# Sol F64, step 2: one typing, no fallback (27 November 2026)

Step 1 ([2026-11-27-SOL-F64.md](2026-11-27-SOL-F64.md)) typed Sol's floats as native types them,
`F64`, but let a script that mixed `Int` and `F64` run the old way, with its errors as warnings.
Step 2 removes that fallback. Mixing is now a type error in scripts and in the REPL.

## What changed

- `sol-vm/Sol/Infer.hs`: the strict table is now the only builtin table (`solBuiltins`). The old
  table, which erased floats to `Int`, is gone, along with `inferResultStrict`. The REPL's session
  checker uses the same profile, so it is strict too.
- `sol-vm/Sol/Main.hs`: one type check, so there is no fallback and no `=== F64: WARNINGS ===`.
  `SOL_F64` and `SOL_F64_WARNINGS` are no longer read.
- `sol-vm/Sol/Cache.hs`: the compile-cache key drops `SOL_F64`.
- `sol-vm/Sol/Preamble.hs`:
  - `Vec.mmul`, `zipAdd`, `zipSub`, `zipMul`, `dot` and `scale` take `Vector a`, not `Vector Int`.
  - `k * v` gets a struct per scalar type: `VecScale` for `Int`, a new `VecScaleF64` for `F64`.
    The resolver picks a two-typed operator by the head types of both operands, so each scalar has
    to be pinned. An unpinned `k` stays a type variable and matches nothing. Under strict typing
    `2 * Vec.fromList [1, 2]` was refused too, until the `Int` scalar was pinned.

## Migration

A full rescan of the repository's 235 Sol scripts (`sol --asm`, every directory depth) found three
mixing scripts that the step-1 scan had missed: `dtree`, `linreg` and `svm`. That scan had resolved
`fpr` relative to each script's directory, so scripts at other depths never ran. All mixing scripts
are now migrated:

| Script | What it needed |
|---|---|
| `sol/lib/plot.sol` | float pixel constants, typed `fmin`/`fmax`, `isNil` for float lists, `F64.ofInt` for legend offsets |
| `sol/lib/matrix.sol` | `Matrix a` over `Vector a`; `mNil` for `== []` |
| `sol/lib/rand.sol` | `unit` and `gauss4` answer `F64` |
| `sol/examples/csvplot.sol` | fit in `F64`, a local `fabs` |
| `sol/examples/physics.sol` | constants and the integrator in `F64` |
| `sol/examples/nn.sol` | `List F64` throughout, typed `relu`/`sq`/`lScale`/`reluGate` |
| `sol/examples/mlpipe.sol` | statistics, records and training in `F64` |
| `sol/examples/plotdemo.sol` | spring, descent, orbit and wave series in `F64` |
| `sol/examples/algebra.sol` | `%` on floats removed (it is `Int` only); `F64 ^` checked within a tolerance; a float dot product and a float `k * v` |
| `sol/examples/linreg.sol`, `svm.sol`, `dtree.sol` | data, weights and thresholds in `F64` in place of `Numeric.div` (labels stay `Int` in `dtree`; `svm`'s are `F64`, so all three folds are typed) |

Every migrated example prints the same with `SOL_JIT=0 SOL_GPU=0` as with the JIT on. `dtree`
recovers the planted rule exactly (x1 < 0.25, then x2 < -0.5). `linreg` learns 1.7497 / -0.4973 /
0.2500 against 1.75 / -0.5 / 0.25.

qos and coscad scripts migrate when their Sol pin moves past this.

## Found, not changed

- **Native's `pow` loses the last digit.** `F64.pow 2.5 2.0` is `6.24999999999999`, because native
  computes `exp(y * log x)` (`runtime.c` `fpow_`). Sol's `Sol.FMath.fpow` is bit-identical to it, as
  the parity check requires. An exact path for integral exponents would be a native change first.
- **Four scripts fail to type-check, for reasons unrelated to floats:**
  - `tools/toolchain-files.sol` defines `readBytes`, which became a builtin in 0.16.0 (`143df4e1`).
    It fails only when compiled as a script. The eight tools that `use` it, `package-toolchain`
    among them, type-check.
  - `tests/sketch-paths.sol` has a `.set` projection that no longer types, probably from the same
    commit.
  - `sol/lib/cli.sol` and `sol/lib/live.sol` are libraries. They report non-exhaustive cases only
    when compiled as scripts, and they also failed that way on 0.15.0. Their users type-check (the
    `sol-live` check passes).
  - None of the four is in the check suite.

## Checks

- Sol check suite (CI-style, `sol` linked to the branch `fpr`): 38 run, none unexpected.
- Rescan: of the 235 scripts, the only ones that do not type-check are the four above.
- REPL: a mixed `1.5 + 2` is refused as a type error and the session continues.
