# Indexing: the 0-based / 1-based split, and a migration to 0-based

Date: 2026-10-01. Kind: register of the current split, and a proposal for a
migration that has not started. It applies to revision `cf97fee`. QOS
(`../qos`) inherits every contract here.

## Why this page exists

FP-RISC has no single index base. Most of the string and list surface is
1-based, and parts of the vector and memory surface are 0-based. The two
meet in ordinary code. On 2026-10-01, writing the double-buffered TUI
(`qos/docs/2026-10-01-DISPLAY-BUFFERS.md`), a scratch test of `Vec.set`
starting at 0 panicked with `index out of range`. The cause was not a bug:
`Vec.set` is 1-based. The new TUI code now mixes both bases in one module.
`frameV` uses `Vec.at`/`Vec.put` (0-based), and the run emitter it reuses
reads `nrow ! (c + 1)` (1-based).

A wrong base is an off-by-one, and it fails in two ways:

- **Silently wrong**, when the index is still in range: the neighbouring
  element.
- **A panic**, at index 0 or one past the end.

The type checker cannot see either. That is the same class of failure as the
silent wrong answers removed in the failure-honesty round.

## The split as it stands

**1-based**

| Surface | Contract | Defined in |
|---|---|---|
| `charAt s i` | byte `i`, 1..len, otherwise panic | `runtime.c` `g_charAt` |
| `substr s off len` | bytes from `off`, clamped | `runtime.c` `g_substr` |
| `strIndexOf p s`, `strIndexFrom p s i` | position of the match, **0 = not found** | `runtime.c`, Sol `VM.hs` |
| `xs ! i` | list element `i` | `runtime.c` `fpr_prim_fn__x21` |
| `Vec.get i v`, `Vec.set i x v` | row `i` | `vec.c` `h_get`/`h_set` |
| `std/string`: `slice from to`, `dropLeft`/`dropRight`, `indexOf`/`indexFrom` (→ `Option`) | positions | `std/string.fpr` (header: "positions are 1-BASED") |
| `std/binary` | reads by position; past the end is `None` | `std/binary.fpr` |
| SString `at`/`put` | byte `i` | `runtime/sstr.c` |
| Sol strings | 1-based Unicode code points, 0 = not found | `Sol/Preamble.hs`, `Sol/VM.hs` |
| Sol vector index | `getVec r (i - 1)`, "like list !" | `Sol/VM.hs` |

**0-based**

| Surface | Contract | Defined in |
|---|---|---|
| `Vec.at i v`, `Vec.put i x v` | row `i` (the same ops as get/set, index + 1) | `vec.c` `h_at`/`h_put` |
| `Vec.iota n` | the values 0..n-1 | `vec.c` `h_iota` |
| `List.indexed`, `List.indexedMap` | indices from 0 | `std/list.fpr` |
| `Mem.read*`/`write*`, `reg8`/`reg32` offsets, `Word.bitSet`/`bitTest` | byte offsets and bit numbers | the machine layer |
| Sol's internal code point access | 0-based (the 1-based contract is the surface) | `Sol/Val.hs` |

**Counts and lengths, not positions**

`Vec.split n` (the first `n` rows), `Vec.range lo hi` (values, inclusive) and
`String.len`.

`vec.c` already records the intended direction above `h_at`:

> "get/set are 1-based (the standing trap); at/put are the same ops with the
> index the rest of the system uses. New code should use at/put."

The string surface has no 0-based counterpart yet.

**Call sites today** (`.fpr` and `.sol`, comments excluded):

| API | fprisc (std, tests, examples, core) | qos (programs, tests, core) |
|---|---:|---:|
| `charAt` | 119 in 21 files | 135 in 34 files |
| `substr` | 55 in 15 | 56 in 25 |
| `strIndexOf`/`strIndexFrom` | 17 in 7 | 2 in 2 |
| `Vec.get`/`Vec.set` | 36 in 13 | 23 in 3 |
| `Vec.at`/`Vec.put` | 3 in 2 | 3 in 1 |
| `!` as an index | 0 | 1 (the TUI run emitter) |

## Migration: completely 0-based

Status: **proposed, not started.**

The goal is one base everywhere: positions and indices from 0, slices as
half-open `[start, end)`, and "not found" as `None`, never a sentinel.

**Constraints**

- **Never flip the meaning of an existing name.** `charAt s 1` changing from
  "the first byte" to "the second" type-checks, and in most programs it stays
  in range. That is a silent wrong answer in every caller at once. Every
  0-based operation gets a new name, and the old name is retired, not
  redefined.
- **Committed module versions are immutable** and pinned by hash. They keep
  calling the old names. Removing a builtin from the prelude breaks them; the
  2026-09-19 HAL page records that this already happened once, with `Mmio`.
  The old names must stay resolvable until every pin has moved to a version
  that does not use them. Otherwise the migration re-commits every frozen
  module, as tightening the signature checks did.
- **Both profiles share one vocabulary.** The base runtime and Sol
  (`Preamble.hs`, `VM.hs`) must change together. `Sol/Infer.hs` and
  `compiler/Infer.hs` say so today ("byte strings, 1-based, 0 = not found").

**Steps**

1. **Add the 0-based surface beside the old one.** It does not exist yet for
   strings and lists. The names are still to be decided. One shape: a byte
   at a position; a half-open slice `[start, end)` in place of
   `substr off len`; find returning `Option Int`; and list `at` in place of
   `!`. The vector side already has `Vec.at`/`Vec.put`. Add differential tests
   that each new operation equals the old one with the index shifted, for
   every in-range and out-of-range index, in both profiles.
2. **Move `std` first.** It is the largest block of call sites, and every
   program sees its contract. Re-commit each module as a new version, and
   change its header comments ("positions are 1-BASED").
3. **A rewrite aid, not a blind rewrite.** Add a tool that lists every old
   call site with its file and line, and proposes the rewrite where the
   shape is mechanical (`charAt s (i + 1)` becomes `at s i`; `substr s off
   len` becomes a slice from `off - 1` to `off - 1 + len`). The rest it
   leaves to review. A loop that counts from 1 to `len` must change its
   bounds as well as its calls, and only a reader sees that.
4. **Move the programs:** fprisc's examples and tests, then QOS (`programs/`,
   `tests/`, `core/`). Move each module pin as its module is re-committed.
   The QOS smoke and `check-all.sh` gates hold at every step.
5. **Deprecate:**
   1. The compiler warns on an old name in code being compiled now (not in
      a pinned version).
   2. After that, it errors in new code.
   3. The names stay in the prelude for pinned versions only.
6. **Remove** the old names once no pin in either tree uses them. The
   prelude, `runtime.c`, `vec.c`, `sstr.c` and the Sol VM lose them together.
   `docs/2026-09-20-STD.md` (a living register) records the new contract.

**Not decided:** the names, and whether `Vec.range lo hi` should become
half-open to match the slices. Those decisions go in a dated page when the
migration starts.
