# States: the register of intermediate states

Kind: living register, kept current in place (like `2026-09-19-BOUNDS.md`).
Started 2026-10-07. It follows the framework in
`../qos/docs/2026-10-06-FP-RISC-QOS-Reliability-Draft.md`: every state in
which scheduling, failure, cancellation or ownership can affect correctness
gets explicit semantics -- its owner, what it holds, which events it
accepts, how it is left, and the test that exercises the exit.

Each guarantee carries a status: **Proposed** (wanted, not built),
**Implemented** (code exists, cited), **Tested** (a test drives it, cited),
**Known gap** (a stated defect or missing answer). A promotion cites code
and test.

Section 1 is the actor lifecycle, implemented in `runtime/actors.c`;
section 2 the mailbox; section 3 the memory actor, pools, stacks and
admission; section 4 the interrupt router, the timer and the log actor. QOS's own register, for the paths that live
there, is `../qos/docs/2026-10-08-STATES.md` (first entry: one Files
request down to the block device and back).
Line numbers are as of commit `26c59d4`.

## 1. The actor lifecycle

### 1.1 The state is a product, not an enum

The code names three states (`ST_READY`, `ST_BLOCKED`, `ST_DEAD`, in the
atomic word `var`). The real state is that word together with these fields
of the actor control block (`acb_t`, actors.c:138-232):

| Field | Meaning | Written by |
| --- | --- | --- |
| `var` | READY / BLOCKED / DEAD | spawn; the actor (READY->BLOCKED, `block_unless`); a waker (BLOCKED->READY, CAS in `wake`); kill and body return (->DEAD) |
| `running` | 0, or 1 + the hart whose loop switched into it and has not got it back | the hart loop only (CAS in, store out, :1434-1453) |
| `hart` | owner hart: the only hart that dequeues, runs or reaps it | spawn; a thief (`steal`, READY and not current only) |
| `in_rq`, `in_bl` | listed on the owner's run queue / backlog (one entry is the invariant) | owner hart only |
| `wait_kind`, `wait_arg` | while BLOCKED: 1 any, 2 from (`arg` = sender), 3 res | the actor, in `block_unless` |
| `slp_on`, `slp_hart`, `wake_at` | linked on a hart's sleeper list, with a deadline | `a_sleep_us`; `slp_drain` |
| `mem_reply` | an outstanding request to the memory actor (pending / block / cancelled) | the actor; the memory actor (CAS) |
| `irq_target` | waiting on a device: the deadlock detector counts it | the actor itself (`Sys.irqTarget`) |
| `watch`, `watchers` | parked on a `receiveFromRes` peer / how many are parked on THIS one | the watcher |
| `external_cleanup` | one cleanup hook a device primitive registered | the actor (`fpr_actor_cleanup_set`) |
| `stack` | non-zero until reaped (`reap` is idempotent on it) | spawn; `reap` |
| `ch` | the channel block (mailbox), until reaped | spawn; `reap` |

The acb itself is never freed once published (`reap`, :725-729): it IS the
actor value other actors hold, and a send to a dead actor reads its `var`.
Identities (`id`, from an atomic counter) are never reused.

### 1.2 Named states

Each row is a named intermediate state, the field combination that is it,
and its record (owner, held, leaves by, test, status).

**Reserved** -- `spawnHeap` admission only. An acb from `acb_unpublished`,
a stack, buckets, channel block, entry copy and grant are taken one by one
(`a_spawn_heap`, :2148-2182) and not yet visible to any other actor.

- Owner: the spawner. Holds: everything in `admission_t` (:1998-2006).
- Leaves by: publication (all taken), or rollback in reverse
  (`admission_rollback`, :2129-2139); an unpublished acb goes back to
  `acb_unpublished`, the only path by which an acb is ever reused.
- Status: **Tested** (`tests/base/admission.fpr`, fault phases 1-8 in
  `FPR_ADMISSION_TEST` builds). Plain `spawn` has no Reserved state: it
  takes each piece and halts the machine on any failure -- **Known gap**
  (S1/Q1 in `2026-10-05-SUPERVISION-AND-ADMISSION.md`).

**Published / Runnable** -- `var` READY, `running` 0, listed (`in_rq` or
`in_bl`) or in flight to its owner (`xpush` ring, XCAP 64 per hart pair).

- The publication point: `ledger_push` then `ship` (:2082-2090);
  everything written before `ship` happens-before the owner sees the acb.
- Leaves by: the owner's `deq` (to Running), a thief's `steal` (READY and
  not current only; it changes `hart`), or kill (to Dead-pending-reap,
  reaped where it is listed).
- Status: **Implemented**.

**Running** -- `var` READY, `running` = 1 + h, `h->current` = it.

- Leaves by: blocking (Deciding), fuel preemption or `yield` (Preempted),
  body return (Ended), kill (Kill-requested), `fpr_actor_fail` (log, then
  kill of itself).
- Status: **Implemented**. A second hart switching into it is caught by
  the `running` CAS (`double_run`, a panic) -- **Implemented**.

**Preempted** -- `var` READY, already re-listed on its own backlog by
`fpr_fuel_exhausted` / `yield` (:1529-1537), but `running` still set: the
context is not yet saved.

- Hazard: a thief must not take it. `steal_from` skips the victim's
  current (:847-860). **Implemented** (comment documents the race).
- Leaves by: the switch out completing (to Runnable).

**Deciding** -- inside `block_unless` (:1669-1694): `var` CAS READY ->
BLOCKED, a full fence, then the wait predicate is checked once more.

- A message that arrived in between flips it back READY and the actor
  continues (TR 11). A kill in between makes the CAS fail or the re-check
  return with `var` DEAD -- see Kill-requested.
- Status: **Implemented** (the Dekker pairing with `a_send`).

**Waiting(any | from X | res)** -- `var` BLOCKED, `running` 0, `wait_kind`
1/2/3, counted in `g_blocked` (and `g_irq_waiting` if `irq_target`).

- Leaves by: a message satisfying the predicate (a sender's `wake`:
  CAS BLOCKED -> READY, then `ship` to the owner); for `res`, the peer's
  death (`wake_watchers`); kill.
- Dependency: named by `wait_kind`/`wait_arg`, printed by the deadlock dump
  ("waits any" / "waits from N").
- Deadline: none. `receiveFrom` on a peer that dies waits forever;
  `receiveFromRes` answers `Err "dead actor"`. **Known gap** for plain
  `receiveFrom` (by design today; FAILURE-HONESTY).
- Status: **Tested** (`tests/base/deadpeer.fpr` for res; most suites).

**Sleeping** -- `var` BLOCKED, `slp_on` 1, linked on hart `slp_hart`'s
list with `wake_at` (`a_sleep_us`, :1714-1760). Counted in `g_sleepers`,
which keeps the deadlock detector from firing.

- Leaves by: `slp_drain` at the deadline (wake), a message (it wakes early
  and re-parks until the deadline), kill (`slp_drain` unlinks a DEAD sleeper
  and reaps it if not running, :1821-1824).
- Status: **Implemented**; the double-link cycle it once had is fixed and
  commented. Kill-while-sleeping has no test -- **Proposed** test.

**WaitingForMemory** -- an actor whose allocation went to the memory actor
(`fpr_mem_take`): `mem_reply` pending until the memory actor CASes in a
block or a refusal.

- Death: `reap` calls `mem_cancel` (:2888-2894), which swaps in a
  cancellation sentinel; a grant already delivered is freed there, and the
  memory actor's later CAS against "pending" (:2977) fails, so a late grant
  goes home instead of becoming an orphan.
- Status: **Implemented**; tested only through admission's phases 7-8.

**Kill-requested (running)** -- `var` DEAD while `running` is set on some
hart: kill is advisory for a running actor and lands at its next switch
(the hart loop reaps it then, :1458). Includes the Deciding race above,
where `block_unless` returns and the actor runs user code while DEAD until
its next switch.

- Status: **Implemented**, by design ("advisory", actors.c:56-57). No
  bound on how long it runs on: a loop with no allocation, send or receive
  reaches a switch only at fuel preemption (2,000 function entries).

**Kill-requested (blocked)** -- kill found it BLOCKED: `var` CAS to DEAD,
watchers woken, and the actor shipped to its owner hart, whose `deq` or
backlog scan reaps it (a_kill, since `26c59d4`).

- Before `26c59d4` this state had no exit: the actor was on no queue and
  was never reaped. Status: **Tested** (`tests/base/killblocked.fpr`: 1,500
  kills stay under 32 MiB on one and four harts; they lost about 100 MB).

**Ended** -- the body returned (`trampoline`, :1540-1559): `var` DEAD,
watchers woken, then the switch out; the hart loop reaps it (:1458).
Actor 0 is different: its return ends the machine (`fpr_exit`) or, in a
loaded process, hands the result to the loader.

- Status: **Implemented**.

**Reaping** -- `reap` (:699-730), on the owner's hart-loop stack, never
the dying actor's: cancel a memory request; fix the blocked counters; run
the one cleanup hook; drain borrow holds; release the packing slab; reclaim
the pool; return every stack segment; put the channel block in limbo; unpin
the entry; tell the process loader (`fpr_pid_quiet`).

- Status: **Implemented**. The cleanup hook of a killed BLOCKED actor runs
  only since `26c59d4`.

**Reaped** -- `stack` 0, `ch` 0. The acb remains (~250 bytes) forever. The
channel block is reused only after every live hart's epoch has advanced
twice (`chb_matured`), so a send that read a stale READY finishes on
well-formed channel memory.

- Status: **Implemented** (type-stable, epoch-deferred, :567-690).

### 1.3 Transitions

| From | Event | Guard / decision point | To | Effects |
| --- | --- | --- | --- | --- |
| - | `spawnHeap` | each reservation succeeds | Reserved | pieces taken |
| Reserved | all taken | - | Runnable | publish (`ledger_push`, `ship`) |
| Reserved | a piece refused | - | (gone) | rollback; `Err "fixed heap: ..."` |
| - | `spawn` | - | Runnable | any failure halts the machine |
| Runnable | owner dequeues | `running` CAS 0 -> h+1 | Running | |
| Runnable | idle hart steals | READY, not pinned, not victim's current | Runnable (new `hart`) | |
| Running | fuel / `yield` | - | Preempted | re-listed before the switch |
| Preempted | switch out completes | - | Runnable | |
| Running | wait | CAS READY -> BLOCKED | Deciding | |
| Deciding | predicate now true | CAS BLOCKED -> READY (or a waker did) | Running | |
| Deciding | predicate false | - | Waiting / Sleeping | counted, switch out |
| Waiting | message / peer death | waker's CAS BLOCKED -> READY | Runnable | ship to owner |
| Sleeping | deadline | `slp_drain` on `slp_hart` | Runnable | |
| Running | body returns | - | Ended | DEAD, wake watchers |
| Running | kill / `fpr_actor_fail` | CAS -> DEAD | Kill-requested (running) | wake watchers |
| Waiting / Sleeping | kill | CAS BLOCKED -> DEAD | Kill-requested (blocked) | wake watchers, ship |
| Runnable | kill | CAS READY -> DEAD | (reaped where listed) | wake watchers |
| Dead (any) | kill | `var` already DEAD | unchanged | none |
| Ended / Kill-requested | owner hart, not running | `stack` != 0 | Reaping -> Reaped | see Reaping |

### 1.4 The draft's universal obligations, for actors

| ID | For actors | Status |
| --- | --- | --- |
| U1 ownership | the owner hart alone dequeues, runs and reaps; `running` CAS fences a double run | Implemented |
| U2 one outcome | `var` changes only by CAS from a known state; a second kill is a no-op | Implemented (since `26c59d4` for kill) |
| U3 admission observable | `spawnHeap` refuses by name; plain `spawn` halts the machine | Implemented / Known gap |
| U4 no stale reference to a reused object | acbs and ids are never reused; channel blocks only after the epoch | Implemented |
| U5 caller resolution apart from cleanup | a watcher's `Err "dead actor"` precedes reaping; a late memory grant is returned | Implemented |
| U6 every wait names its dependency | `wait_kind`/`wait_arg`, printed by the deadlock dump; no deadline on any wait; plain `receiveFrom` on a dead peer never resolves | Known gap |
| U7 budgets | stack ceiling (`fpr_stack_max`), mailbox (Static/Dynamic, `RING_MAX`), fuel 2,000 entries; no budget on actors per process, cleanup hooks (1), watchers | Partial |
| U8 partial init/shutdown accounted | admission rollback; reap returns everything it can name | Implemented, with the gap below |

### 1.5 Known gaps

- ~~**Messages queued in a dead actor's mailbox are never released.**~~
  Closed 2026-10-08: `reap` drains the rings (`chb_drain`), a matured
  limbo block is drained again before reuse, and the body's result is
  released in `trampoline` (a received root returned as the result pinned
  its whole message slab). Measured before: 300 deaths with 49-50 one-KiB
  messages unread lost about 16.5 MB per round, linearly, on one and four
  harts. **Tested** (`tests/base/deadmail.fpr`): 900 more deaths cost under
  4 MiB on one hart and 9-12 MiB on four (section 2.5). Found while
  writing section 2.
- A dead actor's watchers learn nothing but `"dead actor"`: the reason is
  only logged (S2).
- One cleanup hook per actor; a second registration panics.
- `kill` is unchecked: any actor may kill any other, actor 0 included (S7).
- A running actor's kill has no bound in time beyond fuel preemption.
- No wait has a deadline; the deadlock detector is the only escape, and it
  halts the machine.
- The trace ring (`tr`, 16 entries) records numeric site codes, not these
  state names.

### 1.6 Tests to add, one per exit

Kill while Sleeping; kill while WaitingForMemory; kill in Deciding (both
orders); kill of a Preempted actor with an idle thief present; a watcher
waiting on an actor that is killed while blocked; spawnHeap rollback at
every phase on four harts. (An actor dying with mail queued:
`tests/base/deadmail.fpr`, 2026-10-08.)

## 2. The mailbox and a message

Added 2026-10-08, after `2026-10-08-PLANE-TABLES.md`: the mailbox is what
`send` means, on the language side of the plane; the control block below
it is the scheduler's. Line numbers are as of the commit that added this
section. `2026-09-07-MAILBOX.md` is the user-facing contract.

### 2.1 The state is the channel block plus the ARC table

An actor's mailbox is one channel block (`chblk_t`, actors.c): `MAXSND`
= 8 channels, 7 dedicated (one sender each) and the eighth the shared
ring (`SHIDX`, sender key `SHARED_KEY`, per-entry sender tags). A message
is a root in the ARC table plus the slab it lives in.

| Field | Meaning | Written by |
| --- | --- | --- |
| `ch[i].sender` | 0 free; an acb address (dedicated); `SHARED_KEY` | first-time senders, by CAS (`chan_for`); `chan_init` on reuse |
| `ch[i].rv` | the ring in force: `cap`, `slots`, `from` (tags, shared only), `old` (the chain of outgrown rings) | growth, under `a->shlock` (`ring_install`) |
| `ch[i].rh`, `rt` | consumer head, producer tail, monotonic `uint32_t` | the receiver (`take_at`); a producer (`ring_push`, release) |
| `ch[i].rh_seen`, `rt_seen` | each side's cached view of the other's index | re-read only when the ring looks full / empty |
| `ch[i].dyn` | 1: double when full, to `RING_MAX` 2^20; 0: refuse | spawn (`spawnCap`), `chan_init` |
| `a->shlock` | orders many producers on the shared ring; excludes growth from the selective receive's shifting | producers; the receiver when shifting |
| `a->scan` | the round-robin start of the next `receive` | the receiver |
| `a->msg_slab` | the SENDER's packing slab: copies pack into it until it is full | the sender (`msg_copy_in`) |
| `arct[]` | the promoted root and its count; a slab's `escaped` counts its promoted roots, `holds` its open borrow windows | `fpr_arc_incref` / `fpr_arc_decref` (under `arc_lock`) |
| `a->dp[]` | the receiver's parked drops: holds released at its next receive (`DP_N` windows) | `fpr_drop_park`, `drop_drain` |

### 2.2 Named states of a message

**Local** -- the sender's value, pool-owned or already shared.

**Checked** -- `send` read the target's `var` and it was not `DEAD`
(`fpr_send_as`). The read is not a lock: the target may die before the
push lands (see Stranded).

**Copied** -- `fpr_msg_copy_to(m, pid)`: a deep copy into the sender's
packing slab (`msg_slab`, ownerless from birth), sized for the receiver's
process. `sendArc` to the same pid skips this and shares
(`fpr_arc_promote_share`); across pids a share is a copy. `sendLinear` of a
movable root to the same pid skips it and transfers the root; otherwise it
copies and consumes the sender's binding.

- Owner: nobody yet; the slab is pinned by the sender's hold.
- Status: **Implemented**.

**Promoted** -- `fpr_arc_incref`: the root enters the table, the slab's
`escaped` rises. From here the value is shared memory and only drops end
it.

**Pushed** -- `ring_push`: slot written, then `rt` released. On the
shared ring under `shlock`; on a dedicated ring lock-free (one producer).
A full Dynamic ring doubles first: the new block is taken OUTSIDE the lock
(it may park the sender on the memory actor), installed under it after a
re-check, the old ring kept on the `old` chain until the block is reused.

- Owner: the receiver's channel. Dependency: none; a push never waits.
- Leaves by: Taken, Drained.
- Status: **Tested** (`tests/mailbox.fpr`: Dynamic grows in order, 3,000
  shared values in flight).

**Refused** -- the ring is full and Static, or Dynamic at `RING_MAX`, or
no memory for the doubling: the copy is dropped (`fpr_arc_decref`) and
`send` answers `Err "mailbox full"`. Nothing is queued, nothing retained.

- Status: **Tested** (`tests/mailbox.fpr`: Static 8 queues 8 of 20 and
  refuses 12 by name; as a loaded process through the plane's
  `spawn_cap`, `Q/tools/mailbox-process-check.sh`).

**Dead target** -- `var` was `DEAD` at the check: `Err "dead actor"`, no
copy made. `sendLinear` still consumes the sender's binding (the contract
is "this value left me"). **Tested** (`tests/mailbox.fpr`).

**Woken** -- after the push, a full fence then `wake(a)`: CAS `BLOCKED ->
READY` and ship to the owner hart. The Dekker pairing with `block_unless`
(section 1, Deciding) is what makes a message never lost between the
receiver's last scan and its park. **Implemented**.

**Taken** -- the receiver's `receive` scans channels from `a->scan`
(round-robin), `receiveFrom` reads the sender's dedicated channel or scans
the shared ring by tag, `receiveRes` scans every ring for a `T_RESULT`.
The head is taken lock-free (`take_at`, `rh` release); a non-head take
shifts the head side down under `shlock`. The root is now the receiver's.

- Status: **Tested** (every suite; `tests/base/deadpeer.fpr` for
  `receiveFromRes`).

**Dropped (parked)** -- the receiver's `drop` is `fpr_arc_decref`: the
count falls, `escaped` falls, `dc_release` frees the root's vectors, and
the dropper takes a HOLD on the slab until its next receive
(`fpr_drop_park`), because the compiler's `drop m` lands right after the
destructure while the arm still reads the children. In hart-loop context
(no actor) the slab goes home at once if nothing else keeps it.

**Released** -- the slab goes home (`slab_home`: the memory actor, a
grant recycler in a process, or the buddy) when `escaped == 0` and
`holds == 0`. A slab is shared by many messages: ONE undropped root keeps
every neighbour's bytes.

- Status: **Implemented**; the "one root pins the slab" case is what
  `tests/base/deadmail.fpr` measured (2.5).

**Drained (at reap)** -- the receiver died with messages Pushed:
`chb_drain` drops each slot as the receiver's own drop would and moves
`rh` to `rt`, before the actor's parked holds are released. Since
2026-10-08. **Tested** (`tests/base/deadmail.fpr`).

**Stranded (in limbo)** -- a sender that passed Checked before the kill
pushes after the reap's drain. The channel block is in limbo
(type-stable, epoch-deferred: section 1, Reaped), so the slot is
well-formed; the message waits there until the block matures (every live
hart's epoch advanced twice) and is taken for a new actor, where
`chb_take` drains it again before `chan_init`. Bounded by one ring per
dead actor, released at the next spawn that reuses the block. Since
2026-10-08. **Implemented**; no test drives the race -- **Proposed**.

**Result of the body** -- the actor's return value: released in
`trampoline` since 2026-10-08 (`fpr_arc_decref`; a pool-local or by-value
result is a no-op). Before, a received root returned as the result was
never dropped and pinned its slab. **Tested** (`tests/base/deadmail.fpr`).

### 2.3 Named states of a channel

**Free** (`sender` 0) -> **Claimed** (CAS to the sender's key; counters
and policy were initialised before the actor was published, never on
claim) -> **Reclaimable** (the sender is `DEAD` and the channel drained,
`rh == rt`: a new sender may CAS it, keeping the monotonic counters) ->
**Shared fallback**: when all seven are claimed a new sender lands on the
shared ring, where `receiveFrom` is a tagged scan and a non-head take
shifts. The block itself: **In use** -> **Limbo** (stamped) -> **Matured**
-> **Reused** (`chan_init` frees the outgrown rings, resets counters and
cached views; a reused block's stale `rt_seen` once claimed messages that
were never sent).

### 2.4 The draft's universal obligations, for the mailbox

| ID | For the mailbox | Status |
| --- | --- | --- |
| U1 ownership | a message has one owner at every state: sender (Local), nobody but a pinned slab (Copied), the channel (Pushed), the receiver (Taken), the table (Dropped) | Implemented |
| U2 one outcome | a send answers exactly one of Ok, "mailbox full", "dead actor"; a slot is taken by exactly one `take_at` (`rh` release) | Implemented |
| U3 admission observable | a refusal queues nothing and says why; Static is a declared bound | Tested |
| U4 no stale reference | channel blocks reused only after the epoch; dedicated slots only when the sender is dead and drained; `old` rings kept until reuse | Implemented |
| U5 resolution apart from cleanup | `Err "mailbox full"` precedes the copy's release; a dead receiver's mail is released after its watchers were answered | Implemented |
| U6 every wait names its dependency | receive's wait is `wait_kind` 1/2/3 (section 1); a send never waits except for memory during growth (the memory actor, named by `mem_reply`) | Implemented |
| U7 budgets | ring cap (Static n, Dynamic to 2^20), 7 dedicated senders then the shared ring, `DP_N` parked windows, `MSG_SLAB_SZ` packing; no bound on bytes queued (a Dynamic ring of 2^20 one-MiB messages is admitted) | Partial |
| U8 partial init/shutdown accounted | a failed growth leaves the ring as it was; reap and limbo reuse both drain | Implemented |

### 2.5 Known gaps

- **Bytes queued are unbounded.** The cap counts messages, not bytes; a
  Dynamic ring admits 2^20 messages of any size.
- **The shared-ring fallback is silent.** An eighth sender loses
  per-sender isolation and its `receiveFrom` becomes a scan with
  shifting; nothing tells either side (`2026-10-05-SUPERVISION-AND-ADMISSION.md`
  Q5 is the same family: `n` rounds and clamps silently).
- **A residue on four harts.** After the 2026-10-08 fixes,
  `tests/base/deadmail.fpr` still loses 9-10 MiB over 900 deaths on four
  harts and 12 MiB over 2,700: mostly per-hart caches, but the slope,
  about 1 KiB per death, is not explained. One hart: under 4 MiB, flat.
- **Stranded has no test** (the send-versus-kill race).
- `receiveFrom` on a dead peer never resolves (section 1, U6).
- A process's `sendArc` to another pid is a copy; the downgrade is
  silent.

## 3. The memory actor and admission

Added 2026-10-09. The memory plane as `runtime/buddy.c`, the memory actor
in `runtime/actors.c` (`mem_body`, `fpr_mem_take`, `fpr_mem_give`), pool
growth in `runtime/runtime.c` (`fpr_alloc`'s slab path, `fpr_grow_counted`),
stacks (`stack_block`, `stack_grow_at`) and `spawnHeap` admission
(`a_spawn_heap`, section 1 Reserved). `2026-10-03-MEMORY-ADMISSION.md` and
`2026-10-02-ACTOR-MEMORY-LIFECYCLE.md` are the design pages; this is the
state map. Function names rather than line numbers.

### 3.1 The state is three allocators and one reply word

| Field | Meaning | Written by |
| --- | --- | --- |
| the buddy (`buddy.c`): free lists per order over one arena, under `buddy_lock` | every big block on the machine: slabs, stacks, acbs, rings, channel blocks, process images | `buddy_alloc` / `buddy_free`, and their `_try` forms that give up if the lock is held |
| `mem_act` | the memory actor: pinned to hart 0, pid 0, `prio` 1 (admitted ahead of the backlog), Dynamic rings from `MEM_CAP` 1024 | `fpr_mem_spawn`, once |
| `a->mem_reply` | this actor's outstanding request: 0 none, `MEM_PENDING`, `MEM_CANCELLED`, or the granted pointer | the requester (store PENDING, exchange to 0 on receipt); the memory actor (CAS PENDING -> ptr); `reap` (`mem_cancel`, exchange to CANCELLED) |
| `mem_hart_key[h]` | a pinned READY acb per hart: the sender key for frees from contexts with no actor (reaper, IRQ delivery, boot) | boot |
| `pool->cur`, `pool->buckets`, `pool->bigfree` | an actor's pool: the current slab (bump pointer `hp`..`end`), size buckets, big free blocks | the owning actor only (pool-local hot path, no routing) |
| `pool->fixed_heap` | non-zero: a `spawnHeap` grant; growth is refused, not requested | spawn |
| `sl->owner`, `sl->escaped`, `sl->holds` | a slab's owner pool (0 = ownerless: a message slab or an orphan), its promoted roots, its open borrow windows | the owner; the ARC table under `arc_lock` |
| `a->stack`, `a->segs`, `a->spare`, `a->stk_total` | the first stack block and the chain of grown segments (each twice the last), one warm spare, the total | the actor itself (`stack_grow_at`), `reap` |
| `fpr_stack_max` | the ceiling on one actor's stack (1 GiB; `FPR_STACK_MAX_MB`) | start |
| counters `fpr_mem_reqs/waits/direct/frees/denied/inline`, `fpr_grow_count/bytes`, `growlog[]` | what happened, for `Sys.memInfo` and the grow log | the paths below |

### 3.2 Named states of a request for memory

**Inline** -- `fpr_mem_take`: `buddy_alloc_try` with the lock free. The
common case; nothing queued, no actor involved (`fpr_mem_inline`).

**Posted** -- the lock was busy or the buddy had no block: `mem_reply :=
PENDING`, a plain Int `(bytes << 1) | 1` pushed on the requester's own
channel to the memory actor (`mem_post`: the request path allocates
nothing), then a fence and `wake`. A push that fails (the actor's ring
could not grow) falls back to **Direct** (`fpr_mem_take_direct`, the
buddy under its lock, counted in `fpr_mem_direct`). The memory actor
itself, and any context with no current actor, always take Direct.

**WaitingForMemory** -- `block_unless(a, p_mem)`: parked until
`mem_reply != PENDING`. Section 1 names this state; its dependency is the
memory actor, its deadline none. Counted in `g_blocked`, so the deadlock
detector sees it.

**Granted** -- the memory actor's `buddy_alloc` succeeded and its CAS
`PENDING -> ptr` won; a fence, then `wake(r)`. The requester exchanges the
slot back to 0 and owns the block. **Denied** -- `buddy_alloc` returned 0
(`fpr_mem_denied`): the CAS stores 0, the requester wakes to a null and
its caller decides (a slab path panics "heap exhausted"; `spawnHeap`
answers `Err`; `stack_block` returns 0).

**Cancelled** -- `reap` ran `mem_cancel` on a requester that died while
Posted: the slot is exchanged to CANCELLED, and a grant that had already
landed is freed by the reaper. A grant that lands later finds the CAS
against PENDING failing and `buddy_free`s itself ("a late grant goes home
instead of becoming an orphan").

- Status: **Tested** (`tests/base/admission.fpr`, fault phases 7 and 8:
  cancellation after allocation before the reply, and after the reply
  before the wake).

**Freed** -- `fpr_mem_give`: `buddy_free_try` on the spot, else a one-way
Int `ptr >> 1` to the memory actor under the actor's key or the hart's
pinned key; a push that fails frees under the lock. Frees never wait and
are never answered.

- Status: **Implemented**; `tests/memory.fpr` (100 workers' blocks come
  home on qosp and bare metal) in the QOS sweep.

### 3.3 Named states of an actor's pool

**Bump** -- `fpr_alloc` from `pool->cur` (`hp` to `end`): no lock, no
routing. **Bucket** -- an exact-size recycled block. **BigFree** -- a
pool-local list of big blocks, taken by exact total.

**Growing** -- the slab is full: `want` is the request plus the slab
header, floored at a size that starts at `FPR_SLAB_MIN` and doubles per
slab to `SLAB_SZ` (256 KiB), so a small actor costs one small block and a
growing one pays a few extra on the way up. The block comes from the
memory actor (`fpr_mem_own`), the plane's memory table
(`fpr_plane_memory->slab_new`) or a loader grant (`fpr_grow_memory`,
with the self-topping spare against the spawn-versus-reap race). The
growth is logged (`growlog`, site and size).

- A **fixed heap** never grows: `fpr_actor_fail("fixed heap: local grant
  exhausted")` ends the actor alone. A `Sys.arena` inside a fixed heap is
  refused ("scratch arenas require separate admission"). **Tested**
  (`tests/base/fixedheap.fpr`).
- An ordinary pool whose growth is Denied panics the machine: "heap
  exhausted". **Known gap** (SUPERVISION S1).

**Reset** -- `Sys.poolReset` / `AC.boundary`: every slab but the current
is returned, buckets and big frees dropped. A fixed heap resets only if
nothing has escaped ("reset blocked by escaped data"). **Tested**.

**Torn down** -- `fpr_arc_teardown_pool` at reap: slabs with `escaped ==
0 && holds == 0` go home; the rest are **Orphaned** (`owner := 0`) and go
home at the last drop (section 2, Released).

### 3.4 Named states of a stack

**Initial** -- `stack_block`: one block of `STACK_SZ` (128 KiB; 256 KiB
in QOS apps) from the memory actor, the whole buddy block used (the
guard at its true low end, `stack_guarded`). Without a memory actor
(legacy process mode) a free list with self-topping.

**Growing** -- the compiler's entry check finds less than
`FPR_STACK_HEADROOM` left: `stack_grow_at` pops segments `sp` has left
(keeping the largest warm as `spare`), then links a new segment of twice
the last. Nothing moves; the function returns into the old segment by
itself.

- **Ceiling**: `stack_sz + stk_total + 2 * size > fpr_stack_max` panics
  the machine ("stack overflow -- the actor's stack reached its
  ceiling"). **Known gap** (S1: a resource failure that halts everything).
- Denied growth (no block) is also a panic. **Known gap**.
- Status: **Implemented**; `tests/dtree.fpr` crosses the first boundary.

**Released** -- `stk_release_all` and `stack_recycle` at reap: every
segment home to the memory actor (unguarded first).

### 3.5 Admission (`spawnHeap`)

Section 1, Reserved, lists the eight pieces and the rollback. What this
section adds: admission is the ONLY path that asks before taking. Plain
`spawn` takes an acb, a stack, buckets, a channel block and an entry copy
one by one and halts the machine on any miss (A1); a process image is one
buddy block at load and then "may grow without count" (A8); the mailbox
and stacks are not charged to anything (A6, A7); and the only check
anywhere is "does the buddy have a block" (A4). `2026-10-03-RESOURCE-
ACCOUNTS.md` in QOS drafts the budgets; nothing implements them.

### 3.6 The draft's universal obligations, for memory

| ID | For memory | Status |
| --- | --- | --- |
| U1 ownership | a block has one owner: the buddy's free list, an actor's pool, a message slab's promoted roots, an image's record; a reply word changes hands by CAS | Implemented |
| U2 one outcome | a request is Granted, Denied or Cancelled exactly once (the CAS against PENDING decides); a late grant frees itself | Tested (admission phases 7-8) |
| U3 admission observable | `spawnHeap` refuses by name and reserves nothing on refusal; a fixed heap's overrun ends the child alone; plain spawn and ordinary growth halt the machine | Partial, **Known gap** |
| U4 no stale reference | an acb is never freed; a channel block is reused after the epoch; an orphaned slab outlives its pool until its last root | Implemented |
| U5 resolution apart from cleanup | a requester's death cancels its slot before its stack is returned; the grant's return is the memory actor's or the reaper's, never both | Tested |
| U6 every wait names its dependency | WaitingForMemory names the memory actor; no deadline; the detector is the only escape | Known gap (shared with section 1) |
| U7 budgets | `fpr_stack_max`; the slab floor and ceiling; `MEM_CAP`; a fixed heap's grant; nothing per actor, per process or in total | Partial |
| U8 partial init/shutdown accounted | admission rollback; teardown homes or orphans every slab; the loader frees an image when its pid is quiet | Implemented |

### 3.7 Known gaps

- **Three resource failures halt the machine** from any actor: ordinary
  heap exhaustion, stack ceiling, plain spawn's misses (S1).
- **No total or per-process budget.** A process may grow without count
  (A8); the memory actor applies no policy beyond availability (A4).
- **The memory actor is a single hart-0 actor** with a Dynamic ring: under
  contention every miss on `buddy_alloc_try` queues behind it, and its
  own ring growth takes the direct path. No measurement of its latency
  under load exists in the tree.
- **`Sys.memInfo` free bytes do not come back promptly** after a process
  with fixed heaps ends: QOS `tools/admission-check.sh` reports
  `returned=False` (free not within 512 KiB of the start) on main as of
  2026-10-08, before and after the mail-leak fixes. Unexplained.
- The four-hart residue of section 2.5 (about 1 KiB per death) may live
  here (per-hart stack or bucket caches) rather than in the mailbox.
- The reply path is a word plus a wake, so a full mailbox can never lose
  a grant; but a requester whose `block_unless` loses the Dekker race and
  is killed in Deciding (section 1) relies on `mem_cancel` running after
  the CAS -- **Proposed** test (kill while WaitingForMemory, section 1.6).

## 4. The interrupt router, the timer and the log actor

Added 2026-10-09. Three small actors with the same shape: a C mechanism
that claims or stages, one installed FP-RISC actor that owns the policy
(installed by CAS, never replaced), and a reply protocol on its own
channel key so a request's answer is never confused with a delivery.
Code: `runtime/actors.c` (`irq_drain`, `tmr_drain`, the `Sys.irq*` and
`Sys.timer*` primitives), `core/prelude.fpr` (`irqRoute`, `logServe`),
`runtime/runtime.c` (`fpr_logput`, `g_logStaged`).

### 4.1 The interrupt router

| Field | Meaning | Written by |
| --- | --- | --- |
| `irq_router` | the ONE router acb, or 0 | `Sys.irqInstall`, CAS from 0, once |
| `irq_bound` | gate: the irq hart's loop reads no MMIO until a router exists | install |
| `irq_src_key` | the deliveries' channel key (a static's address: never an acb) | boot |
| `fpr_irq_hart` | the last live hart: every claim and delivery starts there | `fpr_actors_init` |
| the router's `tab : List (Int, Int)` | source -> bound actor, any number of sources | the router, on bind/unbind |
| `a->irq_target` | the bound actor's own mark: "waiting on a device", which the deadlock detector counts as a way to be woken | the actor itself (`Sys.irqTarget`) |
| the device's mask | a claimed source stays masked until its actor acks | `hal_irq_claim` (masks), `Sys.irqAck` (`hal_irq_ack`) |

**Unrouted** -- no router: `irq_drain` returns at once; a source nobody
opened cannot raise.

**Installing** -- the first `Sys.irqBind` (`irqRouterStart`): spawn a
candidate (`spawnCap 1 64`: Dynamic, because the irq hart's post cannot
wait or retry), `Sys.irqInstall`; one wins, a losing candidate is told 0
and ends. **Implemented**.

**Binding** (`sysIrqBind src me`): an actor binds ITSELF (binding another
is refused by name), marks `irqTarget 1`, asks the router `(me, 1, src)`
and waits `receiveFrom me r`. The router records `(src, me)`, opens the
source (`Sys.irqOpen` -> `hal_irq_open`: the device may raise now) and
replies 1. The source is opened BEFORE the bind is answered.

**Claimed** -- on the irq hart's loop: `hal_irq_claim` claims AND masks
one source, `irq_drain` sends the plain Int to the router under
`irq_src_key` (copy-free, allocation-free from scheduler context). A
full router ring that cannot grow drops the claim silently -- **Known
gap** (the source stays masked: a lost interrupt with no recovery path).

**Routed** -- the router (`irqRouteSrc`): the source's owner gets
`Sys.irqDeliver who src` on the deliveries' channel; a full mailbox makes
the router yield and retry; a dead owner drops the delivery (the source
stays masked). A source nobody bound is dropped and stays masked.

**Delivered / Handled / Acked** -- the bound actor receives the Int
(`receive`, with `irq_target` counted around its park), services the
device, and `Sys.irqAck src` unmasks it. Until then the same source
cannot raise: no same-source storm by construction. An actor that forgets
to ack has silenced its device forever -- **Known gap**, by design.

**Unbinding** (`sysIrqUnbind src`): only the bound actor; the router
removes the entry and answers how many sources the caller still holds.
"The router answers in order, so whatever it handed over before the
unbind is already queued": True means nothing more arrives. The mark is
cleared only when the caller holds no source. It does not mask the
hardware, cancel queued deliveries, or detach a killed actor.

**Owner dead** -- a bound actor that dies leaves its `(src, who)` entry;
the next claim's delivery is dropped and the source stays masked
(`irqHandTo`: "dead actor" -> Unit). **Known gap**: no automatic detach,
no notice.

- Tests: `tests/base/irqroute.fpr` (bind another refused, unbind
  another's refused); QOS UART with PLIC tx/rx on two harts; Portable
  uartsvc/uartroute/kbdread; `tests/builtin_interrupt.fpr` (the
  machine profile's raw path). **Tested** for the happy and refusal
  paths; the dropped-claim and dead-owner paths have none.

### 4.2 The timer

One deadline at a time: `Sys.timerBind` sets `tmr_act` (answering
whether the machine HAS a hardware timer; hosts answer 0 and Timer.qa
falls back to sleeper children), `Sys.timerArm delta` sets the absolute
`tmr_deadline` and kicks the irq hart (IPI) to re-arm `mtimecmp`.
`tmr_drain` on the irq hart: once `mtime >= deadline`, clear it, park the
hart's `mtimecmp` (hart 0 keeps the detector's own), and deliver the
deadline as a bare Int under `tmr_src_key`. The service pops everything
due, notifies, re-arms the nearest.

- A 64-bit deadline on rv32 is read under a lock (no 64-bit atomics).
- A full timer mailbox drops the tick (`fpr_send_as` result ignored) --
  **Known gap**: Timer.qa re-arms only on a received tick, so one dropped
  tick is a stalled timer service until the next `timerArm`.
- Status: **Implemented**; QOS `tests/timerroute.fpr`.

### 4.3 The log actor

| Field | Meaning | Written by |
| --- | --- | --- |
| `log_actor` | the ONE log actor, or 0 | `Sys.logInstall`, CAS, once |
| `stage[32 KiB]`, `stage_used`, `stage_dropped` | C's lines between two drains: a panic, `fpr_actor_fail`, a host thread; fixed, because those cannot allocate; a line that does not fit is counted, never cut | `fpr_logput` under `log_lock` |
| `echo_*` | the console echo's rate limit by sequence: 16 per 64 lines, one summary line when suppression ends | `fpr_logput` |
| `LogSt` | per severity (0 normal, 1 warn, 2 error, 3 host): the kept lines newest first, as many as `Sys.logKeep` says (64 to start); the sequence counters | the log actor |

**Staged** -- a C line: appended to `stage` (or `stage_dropped++`) and
echoed at once under the rate limit; the console never waits on an actor.

**Put** -- an FP-RISC `log`/`logWarn`/`logErr`: `(me, 1, sev, line)` to
the log actor, then `receiveFrom me r` for the answer. "A put is
answered after the echo, so a line logged before an exit or a panic still
prints, in order." A full log ring: yield and retry. A dead log actor:
the line goes C's way (`Sys.logStage`). Cost about 1.3 to 2.5 µs a line.

**Drained** -- before EVERY answer the actor takes what C staged
(`Sys.logStaged`: the copy is sized and allocated before the lock is
taken, because an allocation may park on the memory actor while a writer
on this hart spins on the lock), keeps each line, and adds one line
naming the dropped count if any.

**Kept / Echoed / Snapped** -- `Sys.logSnap sev` answers fresh copies
in the caller's pool; `Sys.logSeq` the total ever written; `Sys.logKeep n`
resizes every severity (at least 1).

- Tests: `tests/base/logplane.fpr` (100 lines, a wide line, a staged C
  line, seq/snap/keep), QOS hostlog and logstorm. **Tested**.
- **Known gaps**: a `logAsk` to a dead log actor is `error` (panic) --
  the asks have no fallback where puts do; a put from the log actor's
  own hart while it holds `log_lock` cannot happen (the drain allocates
  first), but a put FROM the log actor itself would deadlock on its own
  mailbox -- nothing in the prelude does this, nothing forbids it; the
  stage is 32 KiB fixed (a panic storm from many harts drops lines and
  says so).

### 4.4 The draft's universal obligations, for the three

| ID | Router / timer / log | Status |
| --- | --- | --- |
| U1 ownership | one installed actor each; a source has one bound actor; the stage has one lock | Implemented |
| U2 one outcome | install is a CAS; a bind or unbind is answered once in order; a claim is delivered once or dropped | Implemented |
| U3 admission observable | bind another / unbind another's refused by name; a put's refusal retries, a dead logger falls back; a dropped claim or tick is NOT observable | Partial, **Known gap** |
| U4 no stale reference | deliveries and replies on distinct channel keys; a dead owner's delivery is dropped, not misdelivered | Implemented |
| U5 resolution apart from cleanup | an unbind's True is "nothing more arrives", separate from masking or detaching | Implemented |
| U6 every wait names its dependency | a bound actor's park is marked `irq_target`, which the deadlock detector counts; binders and loggers wait on the router or log actor with no deadline | Partial |
| U7 budgets | the stage (32 KiB, counted overflow), the echo rate, `Sys.logKeep`; the router and timer rings are Dynamic with the irq hart's posts unchecked | Partial |
| U8 partial init/shutdown accounted | a losing candidate ends; an unbind clears the mark only at zero sources; no detach on death, no router shutdown | Partial |
