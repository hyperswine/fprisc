------------

1. Closing the Remaining Post-Erasure Seam
Physical worker and reuse migration (compiler/Workers.hs, compiler/Reuse.hs): Move $worker.fields.*, $worker.scalar.*, and Perceus $reuse.fresh / $worker.consume.* generation onto Core/Typed/Program.hs so they consume checked BinderIds and field schemes directly rather than re-inferring shapes after Core/Typed/Erase.hs.
ARC and raw ownership lowering (compiler/Arc.hs, compiler/Representation.hs, compiler/Interrupt.hs): Transition $arc.retain/$arc.release insertion and --raw representation verification across the erasure boundary (extending Compiler/Native/Representation.hs), eliminating the parallel untyped representation pass.
Duplicate untyped pass retirement (compiler/Inline.hs, compiler/Mono.hs, compiler/Struct.hs, compiler/ReceiveTurns.hs): Audit what still calls the legacy untyped Core versions of inlining, callback specialization, struct specialization, and receive-turn conversion now that Core.Typed.* and Compiler.Native.Regions own those transformations for native builds, and collapse any dead untyped code paths.
2. Remaining File-Splitting & Diagnostic Cleanup
Inference table and unifier extraction (compiler/Infer.hs): Split the ~1,450-line Infer.hs by moving the ~400-line primitive scheme tables (builtinEnv, builtinLinShapes, aotProf) into Infer.Builtin and the row/type unification and skolemization routines (unify, unifyRow, zonk, checkDeclared) into Infer.Unify.
Root directory namespace consolidation (compiler/): Group the remaining ~20 flat root modules into domain directories—such as Verify/ or Frontend/ for Safety.hs, Precond.hs, Exhaust.hs, Cost.hs, Manifest.hs, StdBridge.hs, and StdCheck.hs, and Module/ or Compiler/ for Modules.hs, Commit.hs, Publish.hs, and Home.hs.
Full source spans and remaining diagnostic producers (compiler/Diagnostic/Syntax.hs): Migrate Precond.hs, Struct.hs, Frontend/Paths.hs, and Cost.hs off string errors onto structured Diagnostic values, and upgrade SMark Int point offsets to half-open SourceRange spans so Frontend.Diagnostics's legacy @OFF~ adapter can be deleted.
3. Native Runtime & Codegen Performance (docs/2026-10-26-PERFORMANCE-PLAN.md)
Direct receive-turn loops and same-hart handoff (pingpong 2.1x regression): Replace the C g_receive_loop $\rightarrow$ g_loop_in trampoline (which spends 37% of pingpong allocating closures and copying state) with a register-resident self tail-call loop that cycles the arena slab lazily when full, paired with same-hart scheduler handoff when a sender blocks waiting on its receiver.
Inline $vec.at/get/len and IR loop optimizations (byteloop 23x, sha 29x vs. C): Lower flat-element vector reads directly to OIndex/OLoad behind inline bounds checks in Codegen/Lower.hs, and add loop-nest/dominator analysis in Codegen.IR for LICM, difference-bound interval elimination of redundant overflow/index traps, and $fuel tick amortization across bounded loops.
Live-range splitting and inline bump allocation (fib 2.6x vs. C): Split virtual-register live intervals at block boundaries with move resolution in Codegen/Allocate.hs (so cold call paths don't force whole-function spills) and emit inline slab-pointer bump allocations before calling into C.
4. Compile-Time Memory & Test-Suite Consolidation
Dead-symbol pruning before Typed Core transformations (docs/2026-10-26-COMPILE-TIME-BUDGET.md): Prune unreferenced imported/prelude definitions right after module splicing and reachability analysis so large multi-unit builds (pos1.fpr still allocates ~97.7 GB across stages) do not carry unused definitions through Infer, Core.Typed.*, and Regions.
Grouped Cabal test runner (fp-risc.cabal): Consolidate the 15 separate test-suite executables (TypedCore, TypedCalls, TypedCallbacks, TypedStaging, TypedStructs, TypedTraps, TypedUnits, etc.) into 2–3 multi-module test runners (matching the pattern used in test-suite TypedProgram) to reduce Cabal link overhead during make base.
