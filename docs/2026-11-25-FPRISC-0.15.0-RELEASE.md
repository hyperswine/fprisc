# FP-RISC 0.15.0 release

Published 25 November 2026: [v0.15.0](https://github.com/hyperswine/fprisc/releases/tag/v0.15.0), a macOS ARM64
archive of 236 commits since 0.14.0. The `fprmeta` index does not offer it yet (see [the index](#the-index)).

The archive was built from clean revision `df95470a` and has SHA256
`d966379d2ef66265fbcdbcb44053e98b6c5052ba25a34a3fe696761fee6b375d` (22,957,441 bytes). Its compiler is the one
built at the version commit (`d1654aab`, merged as `0c893a24`; `df95470a` changes only `tools/`), with SHA256
`bd0911783c86fc4df7a5c8248a61d81f5a352f385f995e237ea80b503a3afd3c`. It needs macOS 27.2 or later, and Apple's
Command Line Tools for native builds. The release page lists the changes.

## What it contains

- The first v1.0 language slices: exact `Int` with bignum promotion, floored `/` and `%`, exact bitwise ops,
  010 small immediates, and the removal of `Word`, SString, VList, `std/set` and Atom. `intMax` and `intMin`
  are deprecated, and `fpr commit` refuses them.
- Deadline receives (`Sys.receiveUntil`, `Sys.receiveFromUntil`, `Sys.waitInbox`).
- Zero-cost passes G1 to G11, RawInts, and the hot-spot fixes (#117, #119).
- Compiling only the reachable definitions of imported std modules (#120). On CI, compile allocation against the
  old baseline is pos1 −15.6%, std-live −80.1% and hello +5.2%.
- The stdlib consolidated from 107 to 67 modules.

## A fix the packaging found

`runtime/runtime.c` includes `bigint.inc` (exact Int, `1695e4de`), but `tools/toolchain-sources.sol` staged only
`.fpr/.sol/.c/.h/.S`. The first candidate, from `0c893a24`, therefore could not compile its own runtime. `fpr test`
in a new project failed with `'bigint.inc' file not found`. #122 adds `.inc` to the staged extensions, and the
release was packaged from its merge commit `df95470a`.

## Qualification

- CI (`sol-checks`, `sol-native`, Linux x86-64) passes at `df95470a`.
- The archive was extracted to a path containing a space and run with `HOME` empty and only the archive's `bin`,
  `/usr/bin` and `/bin` on the path (macOS 27.2.1, Apple M4):
  - `fpr --version` and `sol --version` report 0.15.0.
  - `fpr new`, then `fpr check`, `fpr test` and `fpr run -- Ada` all pass.
  - `--target=macos-x86_64` builds a binary that runs under Rosetta.
  - nbody at 5,000,000 steps matches `tests/bench/clbg/expected`.
  - A Sol script using `std/order` runs.
  - None of the 11 Mach-O files names a Homebrew or `/usr/local` library.
- The download from the release page matches `SHA256SUMS`.

## The index

The signed `fprmeta` index (`docs/release-indexes/fprisc.json` and its `.sig`, published in the Homebrew tap's
`toolchains/`) is unchanged, because signing needs the `fpr-release` key, which stays with the owner. Ready entries
are [`release-indexes/fprisc-0.14.0-entry.json`](release-indexes/fprisc-0.14.0-entry.json) and
[`release-indexes/fprisc-0.15.0-entry.json`](release-indexes/fprisc-0.15.0-entry.json); QOS Portable SDK 0.5.0 and
0.6.0 wait in the same directory. To offer them, from this checkout, with the tap checkout and the `fpr-release`
key on this machine:

```sh
fpr sol tools/publish-release-index.sol --tap /path/to/homebrew-tap --key /path/to/fpr-release   fprisc:0.14.0 fprisc:0.15.0 qos:0.5.0 qos:0.6.0
```

The script fetches `release.json` and `SHA256SUMS` from each GitHub release, checks them against the published
archive, appends the entries in version order, signs the exact index bytes (OpenSSH, namespace `fprmeta-index`,
identity `fpr-release`), verifies the signatures, and prints the git commands to publish the tap. The private
key is only passed to `/usr/bin/ssh-keygen` locally; the script does not read or copy it. See
[`release-indexes/README.md`](release-indexes/README.md).
