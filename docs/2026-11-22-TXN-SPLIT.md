# Txn split: the state layer separates from the commit protocol

Date: 2026-11-22.
Kind: delivery record for finding 3 of the
[architecture review](2026-11-18-COMPILER-ARCHITECTURE-REVIEW.md)
(`Sol/Txn.hs` was the everything-module: 2106 lines, ~143 top-level
functions spanning transaction state, filesystem operations, the typed
error model, locks, the redo journal, saga/Git undo, realtime escapes,
process plumbing, temp-dir ownership and the commit itself).
Host: macOS arm64 (darwin 27.2.0), GHC 9.8.2.

## The split

The module had a clean one-way dependency boundary that the review's
section comments already implied: everything up to the "external
commands" marker observes and buffers; everything after it publishes.
That boundary is now a module:

- **`Sol.TxnState`** (1020 lines) — the state and filesystem layer:
  `TxState` and its in-transaction views, the exact-byte content
  snapshots, the metadata-promise store (`MetaSnap`, `diskMeta`,
  `metaStale`), the filesystem operations (`txLs`/`txWalkE`/`txStat`/
  `txExists`/...), the typed error model (`FsErr`, `classifyIO`,
  `fsPanic`), temp-dir ownership, the effect log and its briefing, and
  the commit-protocol artifact-name test (`lockArtifact`, shared with
  the layer above).
- **`Sol.Txn`** (1146 lines) — the protocol that publishes a `TxnState`:
  locks and reclaim, the redo journal and its recovery, the recovery
  state directory, the Git saga, realtime escapes and their accounting,
  process plumbing and the stdin snapshot, and `commit` itself
  (validate under lock, journal, replay, unlock), plus the retry policy
  the drivers set.

The import is one-way (`Sol.Txn` imports `Sol.TxnState`; no cycles),
and `Sol.Txn` re-exports the state layer wholesale
(`module Sol.Txn (module Sol.Txn, module Sol.TxnState, module
Sol.Effects)`), so the three importers (`Sol.VM`, `Sol.Main`,
`Sol.Mod`) are unchanged. Two pure naming helpers (`displayProcess`,
`undoPath`) moved down with the briefing code they serve; the FFI
imports (`c_fsyncPath`, `c_pidAlive`, `c_getpid`, `c_hardExit`) are all
protocol-side and stayed.

## Verification

Behavior-preserving by construction (the split moved declarations; no
signature changed) and verified: `make fpr` clean; `test:RawInts`,
`test:Interval`, `test:EncodingA64`, `test:EncodingContract` all pass;
`tests/run.sol` gives the pre-split verdicts (87 PASS, the 4 recorded
numeric-slice failures: `result-sizes`, `layout-raw`, `layout-raw-i64`,
`reactor`); a REPL session exercises a transactional commit, panic
isolation and recovery. The compiler's unit-test suites link both
modules through the re-export.

## Remaining

The review's decomposition proposal went further (Locks/Journal/Fs/
Escapes as separate modules). This first cut drew the line that removes
the everything-module character (state-vs-protocol, each under 1150
lines and single-purpose); finer cuts are cheap follow-ups now that the
one-way import exists — the next candidates are the realtime-escape
block and the process plumbing, both of which only the layer above
consumes. Finding 10 (`Compile.hs`, 1748 lines) is untouched.

## Finer cut (same day): the escapes layer

The review's remaining candidates — the realtime-escape block and the
process plumbing — are now their own module too: **`Sol.Escapes`**
(348 lines) holds everything a transaction run does OUTSIDE the
transaction: the realtime escapes and their accounting (`RtCounts`),
the process plumbing shell and deferred commands share
(`runProcessSpec`/`runProcessMode`), and the stdin snapshot. It imports
`Sol.TxnState` (for the effect log and `txForget`); `Sol.Txn` imports
`Sol.Escapes` and re-exports it, so the importers remain unchanged.
`Sol.Txn` is down to 883 lines — the commit protocol proper plus locks,
journal, recovery and the saga.

Same gates re-run on the new binary: the four unit suites, `run.sol`
(87 PASS, the same 4 recorded failures), and a REPL session with a
commit, panic and recovery.
