# Typed x64 SSE2 map pairs

This increment follows [captured NEON maps](2026-10-23-CAPTURED-SIMD.md)
at `662c3a1`. Typed x64 and qx64 kernels now evaluate the same two-lane
Int/F64 expressions using SSE2. SIMD selection is enabled on these targets
by default; `FPR_NO_VEC_SIMD=1` keeps scalar typed kernels. The generator
revision is 74 and x64 selection revision 21.

## Target contract

The lane register is `xmm8`; expression temporaries occupy `xmm9..xmm15`.
The shared expression counts its temporaries explicitly. The planner
retains scalar code above seven temporaries on x64, while A64 retains its
fifteen-temporary budget. The x64 selector also refuses an oversized pair
if it is supplied directly. A seven-node expression exercises the final
reserved register in the selected-IR tests; eight nodes are refused.

Loads and stores use unaligned `movdqu`. Broadcasts use `movq` followed by
`punpcklqdq`. Int add/subtract use `paddq`/`psubq`, followed by scalar
63-bit fit checks of both stored lanes. F64 uses `addpd`, `subpd` and
`mulpd`. Each binary node copies its left operand before the two-address
operation. None of these operations requires SSE3, SSE4 or AVX. There is
no FMA contraction or reassociation.

Every broadcast has one virtual word operand, so captures that spill do
not exceed the allocator's reload budget. A pair is charged its logical
fuel before vector scratch becomes live; no vector register crosses a
call or safepoint. This pass needs no x64 context-layout or runtime ABI
change and does not add an x64 FP allocation pool.

## Correctness

The shared `check_captured_simd.py` now executes native A64, x64 and qx64,
each with SIMD enabled and disabled. On this ARM Mac, x64 execution is
under Rosetta. The qx64 harness preserves the borrowed-hart/argument-cell
addressing and substitutes only the OS FS-base access, as the existing
qx64 emission oracles do.

Each target/mode passes 6,729 independent cases: checked Int operations,
large Int captures, F64 edges/randoms and exact rounding/signed-zero
rules, empty and odd vectors, canaries, seven-argument pressure, descriptor
fallbacks and hostile fuel calls. Six additional executions test overflow
in either lane for add/subtract/reverse subtract. A separate check verifies
identical logical fuel for 66 vector lengths. On x64, the seven-capture
F64 expression is correctly scalar; the smaller affine expression is SIMD.
The C harness explicitly initializes x64 argument cells 7/8 before calling
the eight-argument probe.

The complete Base sweep passed **113/113 jobs**, exit 0, in 368 seconds
with four workers ([full log](evidence/2026-10-23-sse2/base-final.log)).
This includes all new oracles and the direct-selector scratch-budget tests.
Native Linux x64 execution remains a separate platform/CI gate.

[Oracle log](evidence/2026-10-23-sse2/oracles.log).
The first exploratory harness run omitted those argument cells; its failure
is retained separately and is not successful validation evidence.

## Paired Rosetta measurement

31 paired rounds compare the preserved compiler at `662c3a1` with SSE2,
using the same linkage oracle and C harness. Each sample runs a
128-element captured map 100,000 times. Descriptor setup and answer checks
are outside the timer; large fuel prevents yield calls. Every result is
checked. Emission assertions require the baseline map to be scalar and
the new map to contain SSE2.

| Kernel | Baseline median ms | SSE2 median ms | Median paired ratio | 95% bootstrap interval | Faster rounds |
|---|---:|---:|---:|---:|---:|
| Int add captured zero | 26.970 | 12.442 | 0.4615 | 0.4605..0.4626 | 31/31 |
| F64 affine captured one/zero | 24.944 | 10.662 | 0.4278 | 0.4260..0.4285 | 31/31 |

These are **Rosetta** results for small hot maps, about 54%/57% less kernel
time. They do not establish native Linux x64 performance, cold-memory
throughput, whole-application gains, physical QOS acceptance or energy.
The captures are ABI inputs; the compiler cannot specialize their values
from the C caller. Background load and frequency are uncontrolled.
