# Sol gets F64 as native has it: step 1 of 2 (27 November)

Kind: delivery record. Branch `sol-f64`. The owner chose option A, a float type in Sol as native
has it, in two steps (27 November):
1. Add `F64` with its conversions, and report mixed `Int`/`F64` arithmetic as a warning while
   scripts migrate.
2. Make it an error once they are clean.

This is step 1.

## What changed

Sol now type-checks with native's float types:
- A float literal is `F64` (`f32` suffix: `F32`).
- `Num.sin` … `Num.pow` take and answer `F64`; `Num.floor`/`Num.round` are `F64 -> Int`;
  `Num.bits` is `F64 -> Int`.
- The `F64.*`/`F32.*` surface exists:
  - the maths functions;
  - `ofInt`, `toInt` (truncates, refused outside the Int range), `ofF32`/`ofF64`;
  - `str`, which is `runtime.c`'s `dtoa` ported to `Sol.FMath`: 15 significant digits for `F64`,
    7 for `F32`, so Sol prints floats exactly as native does;
  - `Try.parseF64`.
- `Int` and `F64` do not mix, `%` is not defined for `F64`, and `==` or printing reaches a float inside
  a structure only through `F64.str` or `F64.==`. All three are native's rules.

**Step 1's fallback** (`sol-vm/Sol/Main.hs`):
- A script type-checks with the strict table first.
- If that fails but the script type-checks the old way, `Int` as the one numeric type, it runs the
  old way. The strict errors print as warnings under `=== F64: WARNINGS ===`, with the conversions
  to use.
- `SOL_F64=strict` turns the fallback off (step 2's rule), for migrating; the compile cache keys
  on it.
- `SOL_F64_WARNINGS=0` silences the warnings.
- The REPL keeps the old typing until step 2.

**The prelude is clean under strict typing.** `Int.mod` and `Int.pow` (what `%` and `^` resolve
to) used `Num.floor` over division. They now use two primitives typed `Int` in both tables,
`Num.floorDiv` and `Num.trunc`, which still behave as before on any number for old-mode scripts. In
the old table the `F64.*` names exist too, with their floats erased to `Int`, so a migrated script
also runs in fallback mode.

## Migration

`sol --asm` compiles without running. Comparing each script with and without `SOL_F64=strict` found
11 of the repository's 235 Sol scripts that pass only the old way. Five are migrated here:

| Script | What it needed |
|---|---|
| `machine/tangnano20k/board-host.sol` | the classifier in `F64`: `F64.ofInt` for counts, `Split Int F64`, `Try.parseF64`. Same tree, digests and SHA-256 as the C reference; the threshold now prints with 15 significant digits |
| `tests/fmath/parity.sol` | `F64.ofInt i * 0.0137`; still bit-identical to native |
| `sol/examples/jsoncsv.sol` | amounts and fractional JSON numbers through `Try.parseF64`, totals as `JReal`, float comparisons by `F64.str` |
| `sol/examples/strings.sol` | float parsing tested with `Try.parseF64` |
| `sol/examples/dispatch.sol` | float constants, `F64.ofInt`, a typed `plus` (an unannotated `a + b` defaults to `Int`) |

Left for step 2: `plotdemo`, `csvplot`, `mlpipe`, `nn`, `physics` and `algebra`, with
`sol/lib/plot.sol` and `sol/lib/matrix.sol`. They treat every number as one type (`Numeric.div`,
`Numeric.sqrt`, mixed literals) and need their data typed `F64` throughout. qos and coscad scripts
migrate when their Sol pin moves past this; until step 2 they run with warnings.

## Checks

- Sol check suite: 38 run, none unexpected.
- `tests/fmath/parity.sol` and `strings.sol` match native byte for byte.
- A clean float script prints the same as its native twin, including negative, small, large and
