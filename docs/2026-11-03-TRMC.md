# Tail Recursion Modulo Cons (B2)

Date: 3 November 2026. Kind: implementation record. Applies to `codegenRev = 149`
(`a64SelectionRev = 29`, `x64SelectionRev = 28`, `rvSelectionRev = 29`).
Implements item **B2** of
[the unboxing and zero-overhead proposal](2026-11-01-UNBOXING-ZERO-OVERHEAD-PROPOSAL.md).

## Problem

List-producing functions in `std/list.fpr` (`mapGo`, `imapGo`, `filterGo`,
`mapFilterGo`, `filterMappedGo`, `fmapGo`, `takeGo`, `twGo`, `zipGo`, `merge`,
`mergePairs`, `groupGo`) are written in tail-recursive accumulator-reverse form:
each step prepends onto `acc` (`elem :: acc`) and every exit calls `reverse acc`
or `revOnto acc tail`. Likewise, `List.append xs ys` is written as
`revOnto (reverse xs) ys`.

Whenever a list pipeline is not fused away into a scalar consumer (for example,
when the list itself is returned, stored in state, passed to `head`/`take`/
`sortWith`, or declined by `FusionPolicy` because a callback may trap on
division), the accumulator-reverse loop allocates **two** `Cons` cells per
output element and walks the entire output list a second time in `revOnto`.

## Design

### 1. Core pass (`Core.Opt.Trmc`)

`Core.Opt.Trmc` runs in `Core.Opt.Pipeline` after `ReuseConstructors` and before
`BatchTicks` and `PairReturns`, gated by `FPR_NO_TRMC=1` (`-notrmc` in cache
identity):

1. **Accumulator-reverse loop transformation (`$worker.trmc.<f>`)**:
   - Recognizes any self-recursive function `f` (arity $2 \dots 63$, body size
     $\le 1024$) with a parameter `acc = ps !! i` that is never shadowed or
     read outside tail positions, where:
     - Every non-trapping exit leaf is `reverse acc`, `revOnto acc tailExpr`,
       `reverse (hd :: acc)`, or `revOnto (hd :: acc) tailExpr` (where `reverse`
       and `revOnto` are verified structurally against `prog`/`imports` so
       same-named user lookalikes are never misidentified).
     - Every recursive call to `f` is a saturated tail call passing either
       `CVar acc` unchanged (e.g. `filterGo` on a rejected element) or a
       let-chain wrapping `CMk 2 1 [hd, CVar acc]` (with `acc` not occurring
       free in `hd` or any other argument).
   - `f` keeps its public signature `(ps)`. At its exit leaves, if `acc` is
     `Nil` (`CTagEq 2 0 (CVar acc)`), `f` returns `tailExpr` directly without
     calling `revOnto`. At its consing recursive calls, after evaluating
     arguments in strict left-to-right order, if `acc` is `Nil`, `f` allocates
     the first cell `cell0 = CMk 2 1 [hd, Nil]` and tail-calls
     `$worker.trmc.<f>` with `root = cell0` and `last = cell0` in place of
     `acc` (if a caller ever passes a non-`Nil` initial `acc`, `f` stays in its
     original loop and calls `revOnto` at the end).
   - Inside `$worker.trmc.<f>`, `root` and `last` are guaranteed by construction
     to be freshly allocated, uniquely owned `Cons` cells:
     - Each consing recursive step allocates `cell = CMk 2 1 [hd, Nil]`, links
       `last`'s tail to `cell` via `$trmc.setTail last cell` with **no branch**
       on `last`, and tail-calls `$worker.trmc.<f>` with `(root, cell)`.
     - Each non-consing recursive step forwards `(root, last)` unchanged.
     - Each `Nil`-tail exit leaf (`reverse acc` / `revOnto acc Nil`) simply
       returns `CVar root` (0 allocations, 0 branches, 0 calls).
     - Each non-`Nil`-tail exit leaf (`revOnto acc tailExpr`, such as `merge`'s
       `revOnto acc ys` or `mergePairs`'s `reverse (one :: acc)`) links
       `$trmc.setTail last tailExpr` and returns `CVar root`.

2. **Two-pass `append` rewrite (`$worker.trmc.append`)**:
   - Rewrites `revOnto (revOnto xs Nil) ys` and `revOnto (reverse xs) ys` (both
     nested and let-bound) to a single forward pass that returns `ys` when `xs`
     is `Nil`, and otherwise allocates the first `Cons` cell `cell0` and loops
     in `$worker.trmc.append(tl, ys, cell0, cell0)`, linking `last.tail = ys`
     when `xs` reaches `Nil`.

### 2. Typed IR and Backend Selection (`OSetField`)

`Codegen.Lower` lowers `$trmc.setTail last cell` to `OSetField 1 lastV cellV`
(`opEffect = Writes`, `clobbersRegisters = False`), verified by
`Codegen.Verify`, evaluated in `Codegen.Eval`, and selected as a single word
store at byte offset `8 + W * index` across all 64-bit targets:

- **AArch64 (`Codegen.Target.A64`)**: `StoreField` (`str <cell>, [<last>, #16]`)
- **x86-64 (`Codegen.Target.X64`)**: `StoreField` (`movq <cell>, 16(<last>)`)
- **RISC-V (`Codegen.Target.RV`)**: `Store64` (`sd <cell>, 16(<last>)`)

## Verification and Rollback

- **Rollback switch**: `FPR_NO_TRMC=1` (`-notrmc` in `Compiler.Options`).
- **Allocation reductions** (with list fusion disabled so materialized list
  allocations are measured, 1,000-element inputs):
  - `List.append` (1,000 + 500): **3,500 $\to$ 2,500** allocations, on the
    default profile. Two-pass `append` is not inlined, so the rewrite always
    reaches codegen.
  - `List.map` / `List.filter`: **3,000 $\to$ 2,000** and **2,000 $\to$ 1,500**
    with `FPR_NO_SPEC=1`, which is where the transform's own saving is
    visible; on the default profile these rows are unchanged, see
    *Placement* below.
  - Hand-written accumulator-reverse loops that call a top-level helper
    (`go r (inc x :: acc)`) or no callback at all save the same one cell per
    element on the default profile (**300 $\to$ 200** over 100 elements).
- **Placement (open).** The typed specializer inlines a called loop into its
  caller before the Core pass runs (`$typed.mono.<owner>.N`), and an inlined
  loop is no longer self-recursive, so `Core.Opt.Trmc` cannot recognise it.
  `List.map`/`filter` with a callback parameter therefore keep their inlined
  accumulator-reverse pass on the default profile; the pass reaches only
  functions the specializer leaves as calls (`append`, or any loop whose body
  it does not inline). Closing this needs the transform on the typed IR, or
  the specializer running after it — see the record's *Next* note.
- **Test coverage**: `tests/CorePipeline.hs` (worker creation, `$trmc.setTail`
  linking, entry-to-worker transition, rollback), `tests/TypedIR.hs`,
  `tests/CompilerOptions.hs`, and `tests/check_trmc.py` (differential
  behaviour, trap order, allocations with and without specialization,
  multi-target emission).
