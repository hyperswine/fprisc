# FP-RISC 0.16.0 release

Published 27 November 2026: [v0.16.0](https://github.com/hyperswine/fprisc/releases/tag/v0.16.0). It is the first
release with Linux toolchains beside macOS ARM64, and covers 64 commits since 0.15.0. The owner asked to cut it
the same day. The release page lists the changes.

- **Source:** all three were packaged from clean revision `59094d75`. The compiler is the one at the version
  commit `6d2d75c3`; `59094d75` changes only `tools/linux-archive.sol`.
- **Assets:** each archive has its manifest. The macOS one is `release.json`, as before; the Linux ones are
  `release-linux-x86_64.json` and `release-linux-arm64.json`. One `SHA256SUMS` covers all three.
- **Requirements:**
  - macOS: 27.2 or later, and the Command Line Tools for native builds.
  - Linux: glibc 2.36 or later (Debian 12, Ubuntu 22.10+, Fedora 37+), and a C compiler for native builds.

## How it was built

- **macOS:** `tools/compiler-licenses.sol`, `tools/stage-toolchain.sol` and `tools/package-toolchain.sol` on this
  Mac.
- **Linux:** `tools/linux-archive.sol --version 0.16.0` built in `packaging/linux/Dockerfile` (bookworm, GHC
  9.8.2) on colima: arm64 natively, x86-64 under Rosetta.
  - `--version` is new this release. After the build and `archive-smoke`, it runs the same three packaging tools
    inside the container and writes the release to `OUT/release`. The clean-container smoke test then runs on
    that archive.
  - Its `git fetch` from the shared repository now takes every branch. It took only the branch the main checkout
    had out, which did not contain the release commits.

## Qualification

- **CI** passes at `6d2d75c3` and `59094d75` (`sol-checks`, `sol-native`, Linux x86-64).
- **macOS:** the archive was extracted to a path containing a space and run with `HOME` empty and only its
  `bin`, `/usr/bin` and `/bin` on the path.
  - `fpr --version` and `sol --version` report 0.16.0.
  - `fpr new`, then `check`, `test` and `run -- Ada` all pass.
  - `--target=macos-x86_64` builds a binary that runs under Rosetta.
  - nbody at 5,000,000 steps matches `tests/bench/clbg/expected/nbody.md5`.
  - A Sol script using `std/order` runs.
  - None of the 11 Mach-O files names Homebrew or `/usr/local`.
- **Linux, both platforms:**
  - `archive-smoke` in the build container: staged with bundled libraries, run from a path with a space and
    `HOME` empty, the linkage check, `fpr new`/`check`/`test`/`run`/`build`, and a Sol script.
  - The release archive alone in a fresh `debian:bookworm-slim` with only `gcc` and `libc6-dev`: the same
    commands.
- **Downloads:** all three files from the release page match `SHA256SUMS`, and the tag points at `59094d75`.

Not run: real Linux hardware, RISC-V boards, QOS against this compiler, and the applications table 0.15.0 had.

A Sol run with `HOME` empty needs `SOL_STATE_DIR` or `XDG_STATE_HOME`. 0.15.0 behaves the same; the smoke tests
set it.

## The index

The signed `fprmeta` index is unchanged: signing needs the `fpr-release` key, which stays with the owner.
- **macOS:** [`release-indexes/fprisc-0.16.0-entry.json`](release-indexes/fprisc-0.16.0-entry.json) is ready,
  made by `tools/publish-release-index.sol --entry-only` from the published assets. To offer it alongside the
  waiting 0.14.0 and 0.15.0 entries:

  ```sh
  fpr sol tools/publish-release-index.sol --tap /path/to/homebrew-tap --key /path/to/fpr-release \
    fprisc:0.14.0 fprisc:0.15.0 fprisc:0.16.0 qos:0.5.0 qos:0.6.0
  ```
- **Linux:** there are no entries. `fprmeta` checks the host with `sw_vers`, and both it and the index tool require
  `minimumMacOS`, so installing a Linux toolchain through `fprmeta` needs Linux support in both (`minimumGlibc`
  in place of `minimumMacOS`, and Linux host detection). Until then the Linux archives are direct downloads.
