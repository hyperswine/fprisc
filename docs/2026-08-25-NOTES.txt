The primary difference between argv and stdin is timing and delivery method: argv delivers fixed parameters to a program before it begins running, while stdin provides an open data stream to the program during its execution.

Two things follow:

The profiles are the wrong way round for the project's priorities. PLATFORM says partial implementations must be labelled. By that rule only the hosted Sol profile is near a plausible Base. The three AOT profiles, which carry the WCET and OS story, would all be labelled "restricted". The gap is also bigger than STD-PLAN says: I counted 9 missing string builtins there, but the Sol Str Struct exposes 23 operations the AOT one doesn't.
Nothing can check laws yet. PLATFORM wants laws such as map id = id and append associativity. Property testing exists only for buddy.c (Hypothesis) and the SPSC channel model. FP-RISC tests grep for exact output strings, and StdCheck proves cost bounds, not laws. Base conformance needs a property-test harness that runs on every profile. The existing check that dtree's output matches the GHC reference bit-for-bit shows the cross-profile comparison can work.
