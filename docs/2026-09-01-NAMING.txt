Consistent Naming Mappings and Explanations

Each entry is a key-value pair in this form:

term = Brief description. Example: a concrete spelling, command, or observed use.

The key is the canonical project spelling. Alias entries point to that spelling.


LANGUAGE AND EXECUTION

FP-RISC = The shared functional language and compiler frontend; an ISA is a separate choice, despite "RISC" in the name. Example: the same parsed program can target rv64, a64, or x64.

QOS = The operating environment that hosts packaged FP-RISC applications, either as a native kernel or through a Unix host. Example: `./qos.py run tests/hello.fpr --on qosp` runs a QOSPortable app.

Sol = The HostedBytecode profile of FP-RISC: shared syntax and inference, followed by the Sol bytecode VM, JIT, and transactional runtime. Example: `fpr sol sol/scripts/lowercase.sol in.txt out.txt`.

profile = A choice of how guarantees are discharged, which backend executes, and which library tier is available; it is not an ISA. Example: QOSPortable on a64 and QOSPortable on x64 are one profile on two ISAs.

BareMetal = The AOT profile linked with `machine/virt`, with no operating system underneath it. Example: `make bare-metal-run PROG=tests/fmath.fpr` boots the result under QEMU.

QOSNative = The AOT RISC-V profile in which a `.qa` process runs on the QOS kernel. Example: `make native-run` boots `system.fpr` and loads apps from the QOS disk.

QOSPortable = The AOT host-ISA profile in which `qosp` hosts one `.qa` process on Unix through `qos_hal_t`; it is not the old co-compiled POSIX target. Example: `./qosp --yes ../fp-risc/app.qa`.

HostedBytecode = The Sol profile, where runtime transactions provide the rollback net that AOT profiles replace with static exclusion. Example: `fpr sol script.sol` runs bytecode plus JIT code in one host process.

one frontend = The rule that all profiles share parsing, inference, modules, structures, contracts, and preconditions. Example: both `fpr compile x.fpr out.s` and `fpr sol x.sol` enter through `FPRISC.hs`.

one grammar = The rule that `.fpr` and `.sol` do not have competing parsers; profile-specific acceptance happens after shared parsing. Example: `> print "hi".` parses everywhere but is accepted only in the Sol view.

profile-gated view = Shared syntax whose use is accepted or refused according to the selected profile. Example: a top-level `>` evaluation is grammatical but rejected outside HostedBytecode.

discharge = To satisfy a language guarantee by proof, static exclusion, or a named runtime mechanism. Example: stdcheck can discharge a positive-divisor precondition statically; Sol discharges file atomicity with transactions.

std = The safe library tier whose operations require bounded worst-case behavior and proof-pass acceptance; it is not an abbreviation for a generic standard library. Example: `fpr stdcheck std/checkdemo.fpr` reports discharged obligations.

measure = A contract annotation proving recursive progress by requiring the marked value to decrease. Example: `(n : Int | measure n)` admits a countdown that recurses with `n - 1`.

_ (type) = A fresh anonymous type placeholder inferred independently at that position; unlike a named lowercase type variable, repeated underscores do not state that their types are equal. Example: `List _` means a list whose element type is inferred from use.

_ (pattern) = A wildcard that matches without binding the value; discarding a linear shape through it is rejected as a leak. Example: `case result of Ok x -> x | _ -> fallback` ignores the unmatched payload.

named typed hole = A `?name` expression that makes compilation fail while reporting the inferred type needed at that location. Example: `?res` can report `typed hole, ?res : Int`.

runtime typed hole = The `??` expression, which compiles so the surrounding pipeline can run and then traps if evaluation reaches it. Example: a prefix can print diagnostics before `??` raises `SOL PANIC: typed hole`.

omega cost = A symbolic WCET term for an unsafe or otherwise unbounded operation. Example: a call to an opaque `core_*` primitive contributes `omega(name)` to the proof report.

refusal = A deliberate, named rejection that preserves the relevant prior state; preferred over silently weakening a guarantee. Example: a live-reload arity mismatch is refused and the previous module remains bound.

honest = A result or diagnostic that names a lost guarantee instead of implying success. Example: a failed deferred process prints `NOT atomic` rather than an ordinary atomic commit receipt.


SOL TRANSACTIONS AND PROCESSES

whole-script transaction = The unit of Sol atomicity: every top-level evaluation in one invocation shares one snapshot and commits once or not at all. Example: a panic in the second `>` statement unwrites the first statement's pending file write.

phase = One top-level `>` evaluation within a whole-script transaction; it sequences work but is not its own commit boundary or scope. Example: a first phase can queue a file write and a later phase can panic, causing the write to be abandoned.

snapshot = The stable file view observed by one transaction attempt. Example: two `readPath` calls for the same path see the same snapshotted content unless the transaction itself writes that path.

read set = The snapshotted paths and directory listings validated at commit to detect interference. Example: another writer changing a read path causes a whole-script retry.

write journal = The transaction's buffered filesystem intentions before validation and commit. Example: `writePath "out.txt" body` enters a replacement in the journal instead of writing immediately.

goal state = The requested final filesystem state rather than an instruction that must be replayed literally. Example: a pending write means "this path contains these bytes" at commit.

rollback net = HostedBytecode's runtime mechanism for recovering from panic or conflict where another profile would statically exclude the unsafe behavior. Example: an abandoned transaction attempt exposes none of its buffered file writes.

retry = Re-execution of the entire Sol script against a fresh snapshot after validation finds a conflict. Example: `SOL_FORCE_RETRY=1 fpr sol tests/txnretry.sol` evaluates twice but commits once.

transactional refusal = An `Err` or panic that abandons buffered state without leaking partial effects. Example: an invalid path update leaves both the model and disk unchanged.

receipt = A runtime acknowledgment that names the effect classes that reached commit; it is evidence, not the transaction itself. Example: `[sol] committed 1 file(s) + 1 deferred command(s) atomically (whole-script transaction)`.

receipts = Context-dependent plural of `receipt`; qualify it when runtime commit receipts could be confused with point-of-sale records. Example: "Sol receipts name committed effects; POS receipts encode completed sales."

commit line = The printed Sol receipt for a completed run. Example: a read-only script has no commit line because it landed no effects.

structured process = An external command represented by raw argv, cwd, environment overrides, stdin, and timeout, without shell parsing. Example: `P.spec ["tar", "-czf", target, "--", source]` preserves each argument exactly.

query = A structured, read-only process run during evaluation and repeated on transaction retry. Example: `Proc.query (P.spec ["uname", "-a"])` collects host information without a shell.

deferred command = A structured mutation queued with `Proc.afterCommit` so it cannot run during an attempt later abandoned by conflict. Example: archive creation runs only after transaction validation.

redo journal = The durable record used to recover deferred commands after commit. Example: recovery reruns an entry that lacks its durable done marker.

at-least-once = The deferred-command crash contract: an effect can run again if the process crashes after the effect but before recording completion. Example: use `tar -czf` replacement or an idempotency key rather than a non-idempotent increment.

realtime escape = An immediate, unjournaled effect that explicitly leaves Sol's rollback model and may repeat on retry. Example: `Proc.runNow` and `writeNow` cause the runtime to report `NOT atomic overall`.

pending-effect refusal = The rule that prevents an immediate process from overtaking already queued effects. Example: `Proc.runNow` returns `Err` when a file write or deferred command is pending.

fence = To stop later dependent deferred commands after one command fails. Example: in `tests/procfail.sol`, exit 1 prevents the following queued process from running.

effect class = A category named separately in transaction accounting. Example: committed files, deferred commands, and realtime escapes are distinct effect classes.

railway = The `Result`-based composition style in which `Ok` continues and the first `Err` stays on the failure rail. Example: `Try.parseInt s |>? validate |> mapOk render`.


MEMORY AND OWNERSHIP

linear = Having exactly one owner, with use after consumption rejected; this is the default for bulk data. Example: `Vec.push x v` consumes `v` and returns the vector handle to use next.

threaded handle = A linear value explicitly returned by every operation so ownership remains visible in ordinary data flow. Example: `(n, v2) = Vec.len v;` continues with `v2`, not `v`.

consume point = The single point where ownership ends or moves. Example: `Vec.free v`, scope-exit autodrop, or `sendLinear peer v` consumes `v`.

drop law = The rule that each received message root is dropped once after its contents are used. Example: the compiler inserts a drop after a provably dead receive binding.

autodrop = The compiler pass that discharges the drop law for recognizable receive/destructure shapes. Example: `tests/autodrop.fpr` completes 200 round trips with no manual `drop` calls.

copy on retain = The rule that a nested value kept beyond destruction of its received root must first be copied into the retaining actor's pool. Example: retaining a field pointer and then dropping its message root is invalid without a copy.

Rc = Plain, intra-actor reference counting for genuinely shared tree or list data; its increments and decrements are not atomic. Example: Rc reaching zero calls `dealloc` inside the owning actor.

ARC = Explicit cross-actor sharing of frozen data; it is not the default lifetime regime. Example: `sendArc` promotes a shareable object and each holder later calls `drop`.

promotion = The explicit transition from local ownership to cross-actor ARC sharing. Example: the first `sendArc` freezes the object and creates the sender's standing share.

send = The actor-send mode that deep-copies the complete message into an ownerless destination slab. Example: sending a tuple containing a vector copies its header, columns, and spans.

sendLinear = The actor-send mode that moves a linear message and consumes the sender's binding, enabling zero-copy relay. Example: the frame ping-pong passes one vector pointer between actors.

sendArc = The sole actor-send mode that shares by explicit ARC promotion; linear vectors are refused. Example: three recipients can hold one frozen tuple with balanced holder counts.

arena = A bounded memory region used for grouped allocation, often bump-allocated and released wholesale; it also names the fixed process-loading address range. Example: `Sys.arena scratch` releases all scratch allocations when `scratch` returns.

grant = A block supplied by the lower buddy allocator to a process or actor pool. Example: a loaded process turns its initial heap grant into its first slab.

slab = A contiguous bump-allocation block owned by a pool or used as one copied actor message. Example: actor death returns its escape-free slab chain wholesale.

per-actor pool = The actor-local allocator made of bump slabs, exact-fit buckets, and `bigfree`. Example: a long-lived worker calls `Sys.poolReset` at loop boundaries.

pool reset = A declared lifetime boundary where a long-lived actor reclaims temporary pool storage. Example: an MVU worker resets frame-temporary allocations after each iteration.

bucket ceiling = The largest size served by fixed size-class recycler buckets, currently 8 KiB. Example: a freed 4 KiB block returns to a bucket; a larger vector column goes to `bigfree`.

bigfree = The per-pool, exact-fit LIFO recycler for blocks above the bucket ceiling; it means "big-block free list," not a bulk deallocation operation. Example: `tests/bigfree.fpr` repeatedly builds and frees 100k-element vectors while arena usage stays flat.

big free = Alias for `bigfree`; use the joined lowercase spelling when naming the allocator tier or test. Example: say "the block returns to bigfree," not "a Big Free occurs."

warm free list = A recycler after it has acquired the reusable blocks needed for a steady workload. Example: `bigfree.fpr` performs three warm-up cycles before comparing memory across forty more.

immortal actor = A deliberately long-lived actor whose pool cannot rely on actor death for reclamation. Example: a renderer loop must recycle large vector columns instead of accumulating them until shutdown.

frame = In memory-model discussions, one iteration's owned bulk state, passed or double-buffered as structure rather than left for collection. Example: `tests/frames.fpr` relays one linear frame for 199 zero-copy bounces.

bigframe = A compiler/codegen stress case with more live local slots than a short immediate offset can address directly; it is unrelated to graphical frame size. Example: `tests/bigframe.fpr` keeps 300-plus let slots live.

Memory.qa = The planned/packaged service that owns global buddy grants and serializes access through one actor mailbox. Example: process growth requests conceptually go to Memory.qa rather than mutating a shared allocator directly.

ARC.qa = The service that owns cross-actor reference-count policy and auditing. Example: an ARC manager drains INC and DEC messages through one mailbox.


VECTORS AND OPTIMIZATION

Vec = The compute-bound growable-array abstraction, linear by default and represented as contiguous columns for records. Example: use `Vec.map (fn p -> p.x + 1) points`, not a hand-named column primitive.

SoA = Structure of Arrays: a vector of records stores one contiguous column per field rather than boxed rows. Example: `Vec {x, y}` stores an x column and a y column.

dualize = Compile an ordinary record element function into unboxed functions over the columns it reads and writes. Example: `fn s -> s.age + 1` becomes a dense loop over the age column.

generic apply tier = The correct row-by-row fallback when a Vec site cannot use a specialized column loop. Example: a pattern-matching element function runs through generic function application.

specialization tier = The backend path that emits dense, unboxed column loops for accepted Vec operations. Example: a64 and rv64 specialize eligible record maps; x64 currently reports that this tier is off.

decline = A compiler-reported decision not to apply an optimization, while preserving program behavior through a fallback. Example: `vec note: Vec.map over f runs in the GENERIC apply tier`.

fusion = Combining adjacent Vec passes into one traversal when linear ownership makes the intermediate unobservable. Example: `Vec.map f (Vec.map g v)` becomes one composite pass.

fusion fixpoint = Repeating fusion until a chain of three or more eligible passes has collapsed completely. Example: the `_vfuse_1_*` name in `tests/vecfuse2.fpr` witnesses a second fusion round.

write-back fold = A fused map-and-fold pass that stores each mapped value back into the vector before folding it, preserving the map's visible mutation. Example: `Vec.fold f z (Vec.map g v)` can execute as one pass.

mask = A planned branch-light column marking which rows survive a conditional vector operation. Example: a future `Vec.filter pred v` writes predicate results to a mask before compaction.

compaction = Restoring dense vector storage by sliding or gathering live rows. Example: today's `Vec.filter` eagerly compacts in place with read and write cursors.

auto-tabling = Runtime memoization of eligible pure recursive Sol functions after compile-time and dynamic gates accept them. Example: repeated integer calls can hit the bounded LRU table instead of recursing again.

fuel = The VM's bounded execution budget used to insert cooperative preemption points. Example: exhausting a quantum yields and increments the fuel-preemption count rather than monopolizing the runtime.


PACKAGES, MODULES, AND LOADING

.qa = The application distribution and loading unit shared by QOSPortable and QOSNative. Example: `tools/mkqa.py` packages a manifest, load contract, and flat image into `app.qa`.

QAR2 = Revision 2 of the `.qa` container format, containing text section metadata plus MANIFEST, LOAD, and IMAGE payloads rather than a runtime ELF. Example: a loader first expects the header `QAR2`.

flat image = The loadable bytes laid out at their final offsets, with gaps already zero-filled, so loading needs no ELF program-header walk. Example: the loader copies IMAGE to `base`, then zeroes `imagesz..memsz`.

slot = The fixed virtual-address range reserved for one loaded process or plugin image. Example: a second overlapping plugin load is refused in QAR2 loader tests.

qosp = The Unix host executable for QOSPortable applications; it supplies the QOS HAL table and loader but is not itself a profile. Example: `qosp --yes app.qa` maps the arena and enters the app.

qos_hal_t = The versioned function table through which a QOSPortable app reaches host services. Example: the loader refuses an app/host ABI version mismatch.

scratch area = A mutable module source file used for editing, not the identity-bearing committed artifact. Example: `mymod.fpr` may change after `mymod#824900fc92b96248` has been committed.

mint = Create an immutable, addressable module version after compatibility and closure checks. Example: `fpr commit mymod.fpr` mints a new binding in `.fpr/versions.db`.

pin hash = The frontend's hash of the pin-normalized AST and dependency tree, used as module identity. Example: `M = use "mymod#824900fc92b96248".` pins the reviewed meaning.

pinned use = A module import naming both the module and its pin hash. Example: committed closure rejects `use "mymod"` and suggests `use "mymod#hash"`.

commit closure = The property that every transitive dependency of a committed module is pinned and copied into the content store. Example: deleting scratch sources does not break a fully committed dependency tree.

immutable rebind = The rule that an existing name/version pair cannot later point to different content. Example: publishing changed content requires a new version instead of replacing v1.1.

pkgstore = The policy-free content-blob and append-only-binding service to which the local `.fpr` store maps. Example: `fpr push` uploads the blob, then its `(name, version, hash)` binding.

seam = A deliberately small, documented integration boundary whose concepts and formats already agree but whose final wiring may be separate. Example: push/pull was originally the two-HTTP-call seam between `.fpr` and pkgstore.

LiveReload = Re-resolving an attached module to a signature-compatible newer version while in-flight calls finish on the old mapped code. Example: attaching Math.v2 makes new resolutions win without unloading Math.v1.

impostor = A package with the expected role or name but an incompatible export shape, used to prove loader refusal. Example: `mathbad.fpr` changes arity and must leave the live v2 module bound.

load-time seatbelt = The runtime name/arity compatibility check that backs up deeper commit-time signature checks. Example: `Mod.compatAt old new` refuses a missing export before rebinding.

PAP = A partially applied function value carrying supplied arguments and remaining arity. Example: capturing a linear vector makes the PAP itself linear and consumable once.


DISK AND APPEND-ONLY STORAGE

QLOG = The realized page-aligned QOS disk log format, with metadata, bounded append-only DATA, and circular SWAP regions. Example: page 0 begins `QLOG <head> v<ver> ...`.

HEAD = The metadata pointer to the beginning of the latest complete DATA log state. Example: a torn append leaves HEAD unchanged so recovery truncates back to it.

DATA = The bounded, append-only page region of QLOG; existing records are not overwritten in place. Example: an append past `dataEnd` returns `Err`.

SWAP = The circular QLOG page region reserved for overwriteable actor paging data. Example: its cursor wraps onto the oldest swap page after reaching the end.

chunk = A hashed QLOG record fragment associated with a URL; higher-level files are reconstructed by folding their live chunks in log order. Example: `QREC` stores page count, payload length, URL, and hash.

BULK entry = A QLOG record that packs multiple small URL chunks into shared pages to avoid page waste. Example: `QBLK` is used instead of one page-aligned `QREC` per tiny value.

file (QLOG) = A higher-level URL-to-content view, not a primitive on-disk inode; content is the fold of live chunks for that URL. Example: System.qa can expose `/notes` by folding its QLOG records.

compact = The idempotent QLOG GC sweep that copies live records forward, truncates by HEAD, and recomputes the Merkle root. Example: rerunning compaction over unchanged live data yields the same HEAD and root.

Merkle root = The metadata hash summarizing the ordered live chunk hashes after compaction. Example: QLOG stores it in the `m<merkleRoot>` metadata field.

append-only binding = A durable name-to-value history where changes add records rather than mutating prior meanings. Example: `.fpr/versions.db` appends `name version hash` rows.

receipt (POS) = In the point-of-sale example, an immutable encoded sale record; this is separate from a Sol runtime receipt. Example: `pos2.sol` appends `number|cashier|total|items` to its receipts log.
