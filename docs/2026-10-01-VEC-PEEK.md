# Vector reads that build no pair

Date: 2026-10-01. Kind: implementation record. Item 4 of the list of
remaining improvements, after the display work found that each vector read
allocated ([LOOPWITH](2026-10-01-LOOPWITH.md), "Not done").

## The cost

`Vec.get`, `Vec.at` and `Vec.len` return `(value, handle)`, because a
Vector is linear and the read has to hand the handle back. In the runtime
(`vec.c`) the handle returned is always the very one passed in, so the
pair carries nothing new. It still cost a 48-byte allocation per read:

- in every vector loop;
- for good in a long-lived actor's pool, because pools are reclaimed only at
  death or at an arena boundary.

`tests/bench/vecread.fpr` (50 passes of 1M reads) ran in 0.43 s with
**2.4 GB** resident.

## The rewrite (`compiler/Inline.hs` `vecPeek`)

`(x, v2) = Vec.at i v` desugars to:

    let t = Vec.at i v in if tag(t) == Tup2 then let x = t.0; v2 = t.1 in ...

The pass rewrites the site to `let t = $vec.at i v`. `$vec.at` is a runtime
read that returns the value alone; the pass drops the shape check, reads
`t.0` as `t`, and reads `t.1` as `v`. `Vec.get` → `$vec.get` and `Vec.len`
→ `$vec.len` likewise. The new primitives are in `vec.c`; they make the
same checks and give the same panic messages, and the code generator calls
them directly (`halAr`).

A site is left alone unless all of these hold:

- the handle is a variable;
- the pair is used only through its two projections;
- neither the pair's name nor the handle's name is rebound before those
  uses.

It runs on the base pipeline only, before inlining. The linearity check has
already passed on the source by then, so aliasing the handle breaks no
ownership rule. It does not run under `--arc`, whose ownership lowering
would count the alias.

`FPR_NO_VEC_PEEK=1` turns it off. That setting is part of the unit-cache
and `fpr run` keys; `codegenRev` is 25.

## Verified

- **`tests/base/vecpeek.fpr`** (`check_base`) checks each form, a pair kept
  whole, the element's name shadowing the handle's, and the out-of-range
  panic. The rewrite on and off give the same values. 2,000 reads cost
  **96 B** (the two loops' final pairs) against **96,096 B** without it.
- **`vecread`** joins the performance ratchet at 158 ms; the other
  benchmarks are unchanged.

| `vecread` (50 × 1M reads) | Time | Peak RSS |
|---|---:|---:|
| without | 0.43 s | 2.42 GB |
| with | 0.15 s | 19 MB |

## Not done

- A read whose handle is an expression rather than a variable keeps its
  pair. So does a pair that is passed on whole.
- The Sol VM is unchanged: its vector reads are its own.
