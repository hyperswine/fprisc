# Typed IR, milestone M1: the IR, its verifier, a scalar lowering and a reference evaluator

Date: 2026-10-20. Kind: implementation record for
[the typed native IR plan](2026-10-20-TYPED-NATIVE-IR-PLAN.md), milestone M1,
on the branch `codex/a64-overflow-checks-20261020` at codegen revision 66.
Audience: compiler implementers and reviewers.

This change emits no code, bumps no code-generation revision and changes no
default.  It adds the typed IR as five modules, a report beside the legacy
emission that says which functions the new lowering accepts and why it
refuses the others, and a check that the reference evaluator agrees with
the legacy binary on values and traps. Tick counts are structural evaluator
expectations, not native measurements. It makes no speed
claim and no claim about any target's instruction selection.

Follow-up (2026-10-21): the [review repairs](2026-10-21-TYPED-IR-M1-REPAIRS.md)
replace body-based convention recovery with producer metadata and fix a native
Bool singleton mismatch. The implementation description below records the
initial revision; see that follow-up for current behaviour.

## What was built

| Module | Lines | Responsibility |
|---|---:|---|
| `compiler/Codegen/IR.hs` | 202 | the types: virtual values, block parameters, typed operations, terminators, the function, effects |
| `compiler/Codegen/Verify.hs` | 133 | the mandatory checks: single definitions, signatures, edges, reachability, dominance, callee conventions |
| `compiler/Codegen/Dump.hs` | 60 | the deterministic text form |
| `compiler/Codegen/Eval.hs` | 146 | the reference evaluator: result, trap text, the order of effects as events |
| `compiler/Codegen/Lower.hs` | 400 | Core to IR for the scalar subset, with the scalar workers' raw conventions recovered from their bodies |

One representation, as the plan was narrowed: the IR describes operations
and representations over virtual values; nothing in it names a physical
register, a frame slot or a target instruction.  Blocks take parameters
(no phi nodes).  The entry block's parameters are the function's; a jump to
the entry block is the self tail call, and passes through the entry's
stack check and safepoint like any other activation.  The reference
evaluator counts a safepoint per activation and per loop turn, which is
the legacy generator's fuel contract (G1, `Codegen.wcetAnnotate`).

### Representations

`TVal` (a tagged runtime word), `TInt` (an unboxed Int within the 63-bit
range), `TPred` (0 or 1).  `TRaw`, `TAddr` and `TF64` are declared so the
vocabulary is fixed; no M1 operation produces them.  Every change of
representation is an instruction: `tag`, `untag`, `boolof`, `truth`.  The
lowering emits them wherever the Core's typing crosses a representation,
and emits no fewer: the dump of `sum` below shows `untag v0` twice because
the source reads `n` twice.  Folding pairs and sharing conversions is the
simplification pass of M2 and M3, after selection can say what a fold
costs on each target; the IR as lowered is the honest statement of what
the program does, not an optimised one.

### Checked arithmetic

`arith + - * /` on `TInt` traps in program order with the C primitive's
message (`runtime/runtime.c`): `Int overflow: a + b does not fit an Int
(-4611686018427387904..4611686018427387903); I64 is the type that wraps`,
and `division by zero`.  The plan allowed either explicit failure edges or
operations with ordered trap semantics; M1 takes the second, which keeps
blocks straight-line and matches what the legacy inline fast paths do (the
slow path re-enters the primitive with the original operands and the
primitive panics).  A later milestone that wants the failure edge for a
target has to add it as a transformation with its own proof.

### Equality

`==` and `!=` on values that are not both already `TInt` lower to `eqval`
and `neval`, deep structural equality, because inference leaves a bare
`==` polymorphic where `+` is Int (the legacy `$arc.eq` guards for two
tagged Ints and otherwise calls C).  Orderings are Int by typing and lower
through `untag` to `cmp`.

### The scalar workers

The private scalar workers (`$worker.scalar.*`, `Workers.scalarWorkers`)
take raw Ints and Bool objects and answer a raw Int or a Bool.  Their
conventions are not written anywhere; `Lower.workerSignatures` recovers
them from the bodies to a fixpoint: an operand of a `$scalar.` operation is
an Int, a tag-tested or branched-on parameter is a Bool, an argument to
another worker has that parameter's kind.  A worker with a parameter or
result left undetermined is refused by name.  A call's `Callee` carries
the parameter and result representations, so the verifier checks every
call against its callee's entry.

### Fallback

An unsupported Core form is a refusal naming the form (`a string literal`,
`the primitive \`print\``, `a field projection`, `a constructor with
fields`, `a lambda`, `a partial or over-saturated application`, `arity
above 8`).  A verifier failure on a lowered function is a compiler error.
Nothing falls back silently.

## The report: `FPR_TYPED_IR`

Set `FPR_TYPED_IR` and the compiler prints, beside its ordinary notes, for
each unit it emits in that invocation:

```
typed-ir: coverage 9/16 functions
typed-ir: $worker.scalar.fib lowered (3 blocks, 11 instructions)
typed-ir: fib lowered (8 blocks, 26 instructions)
typed-ir: main fallback: the primitive `Sys.args`
```

`FPR_TYPED_IR="dump"` adds the dumps; `eval:<fn>:<int>...` adds the
reference evaluator's answer for that call, with its safepoint and call
counts.  The variable is not part of any cache identity because it changes
no emitted code; a unit served from the cache prints no report, so a
corpus-wide count needs a fresh cache.  On `rv32` the report says the
lowering is not available: M1's Int range is the 64-bit targets'.

## Evidence

`tests/check_typed_ir.py`, added to `tests/check_base.py`:

- `tests/TypedIR.hs` (run through `runghc` like `tests/SelfLoops.hs`): a
  well-formed function verifies and nineteen malformations are refused by
  name (a missing entry, a duplicate block, a double definition, a use
  before its definition, a use without dominance, an undefined value, a
  wrong operand type, an illegal conversion, a declared type disagreeing
  with the operation, a discarded result, a branch on a value, a return of
  an Int, a jump to a missing block, wrong edge argument count and type, an
  unreachable block, a malformed call, a call convention disagreeing with
  the callee's entry, a constant outside the Int range).  The generator's
  Core shapes for `fib` and `sum`, written by hand from `FPR_DUMP_CORE`,
  lower, verify, dump identically twice, and evaluate to `fib 20 = 6765`
  with 21,891 safepoints and `sum 100 0 = 5050` with 101; the checked `+`
  on `intMax + 1` traps with the primitive's text as the last event.
- `tests/typed_ir/scalar.fpr`, the real pipeline: `fib`, `sum`, `addovf`,
  `divz`, `even`/`odd` (mutual tail calls), `clamp` (a branch in value
  position, a join block with a parameter) and the two scalar workers lower
  on a64, x64 and rv64; `main` is the reported fallback.  Nine calls,
  including two traps, evaluate to what the legacy binary prints or panics
  with.  `fib 20` counts 21,892 safepoints (the wrapper's activation and
  21,891 of the worker's), `sum 1000 0` counts 1,002 (the wrapper and 1,001
  loop turns).  The dump is byte-identical across the three targets and
  between runs.  The emitted assembly is byte-identical with the report on
  and off.

Two dumps from that fixture, as the report prints them.  The worker is the
loop with its safepoint on the entry; the public function is the worker's
guard and the tagged original:

```
fn $worker.scalar.sum (n acc) -> int entry b0
b0(v0: int, v1: int):
  stackcheck
  safepoint
  v2: int = const 0
  v3: pred = cmp == v0, v2
  condbr v3 -> b1() | b2()
b1():
  ret v1
b2():
  v4: int = const 1
  v5: int = arith - v0, v4
  v6: int = arith + v1, v0
  br b0(v5, v6)
```

```
fn fib (n) -> val entry b0
b0(v0: val):
  stackcheck
  safepoint
  v1: pred = isint v0
  condbr v1 -> b1() | b2()
b1():
  v2: val = nullary 1 1
  br b3(v2)
b2():
  v3: val = nullary 1 0
  br b3(v3)
b3(v4: val):
  v5: pred = truth v4
  condbr v5 -> b4() | b5()
b4():
  v6: int = untag v0
  v7: int = call $worker.scalar.fib :: int -> int(v6)
  v8: val = tag v7
  ret v8
b5():
  ...the tagged original: untag, cmp <, two calls to fib, arith +, tag, ret
```

The wrapper's guard materialises a Bool and tests its truth (`nullary`,
`br`, `truth`) where the legacy `jumpIf` branches straight on the tag bit;
that fold is the simplification pass's, not the lowering's.

### Coverage on the bench corpus

The report on `tests/bench` at this revision, root units and the std units
compiled in the same invocation (`tools/bench.py`'s programs; a64):

| Program | Lowered | Fallback reasons |
|---|---:|---|
| fib | 2 of 3 | `print` |
| helpers | 4 of 7 | `print`, an application of a local (a function parameter) |
| specialization | 3 of 5 | `print`, a local application |
| sha, all units | 28 of 373 | 153 primitives, 91 field projections, 47 HAL values, 34 constructors with fields, 10 string literals, 7 local applications |
| byteloop, nbody, strbuild, pingpong, mixed_locals | 0 | primitives, strings, a projection, a constructor with fields |

The scalar subset is a sliver of real programs.  That is the plan's
expectation (M4 is the long tail) and the reason the report exists: the
number to watch from here is how each milestone moves these counts, and
the rule in the plan's "Keeping up with the legacy generator" is what
stops them from moving backwards.

## What was not done, and what is next

- No native code: M2 is the AArch64 selection with conservative spills and
  the x86-64 constraints in the operand model from its first commit.
- No simplification: conversion pairs, materialised Bools in conditions and
  repeated `untag`s of one parameter stay as lowered.
- No bounds: the "IR instructions between safepoints" metric is still the
  legacy annotator's; the IR carries its safepoints explicitly and the
  bound over the new path is M2's, named separately as the plan requires.
- M0's register page is not written; this page records the two inventory
  facts the slice needed (the scalar workers' convention, the bound's
  consumers: `Compile.wcetSummary` under `FPRC_WCET` and the
  `tests/check_*.py` scripts, nothing in QOS).
- Not verified: anything on a board or under QOS; the evaluator against
  programs beyond the fixture; `check_base.py` as a whole was not run for
  this change, the register, self-loop and worker suites were (recorded
  in the commit message).

## 2026-10-21 evidence clarification

The native fixture supplied result and trap comparisons. Its fuel counters
were not observed: the evaluator tick totals were compared with structural
expectations. Identical dumps for three requested targets establish portable
lowering, not three native execution legs. The runtime/bounds inventory now
lives in [NATIVE-IR-CONTRACTS](2026-10-21-NATIVE-IR-CONTRACTS.md); QOS contains
documentation references to the bound even though no executable parser was
found in the inspected source.
