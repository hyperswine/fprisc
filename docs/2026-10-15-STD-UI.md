# std/ui: layout and appearance as the application's own words

Date: 2026-10-15. Kind: implementation record. Step 2 of
[2026-10-15-DESIGN-GOALS-REVIEW.md](2026-10-15-DESIGN-GOALS-REVIEW.md);
the shape it proposed, built.

## What it is

```
UI = use "std/ui".
page model = UI.page True { UI.stack | gap = 4, pad = 4, fill = UI.Screen } [
    UI.hstack { UI.stack | justify = UI.Between, align = UI.Center } [
        UI.label { UI.txt | size = UI.Title } "Inventory",
        UI.space Unit,
        UI.button { UI.btn | kind = UI.Primary } [G.send codec Save] "Save" ],
    UI.scroll { UI.stack | gap = 3, fill = UI.Grow } (List.map card model.notes) ].
```

- **Nodes**: `vstack`, `hstack`, `scroll`, `listRow`/`listItem` (a ruled
  row of a list), `space`, `page`; `label` (fixed text, a static), `text` (a
  model value, a dynamic slot) and `local` (a value the page holds);
  `button`, `input` (a text area when `rows > 1`), `labelled`; `badge`
  (static) and `status` (dynamic), `toast`; `card`, `rule`; `keyed`. Each
  takes an attribute record and children, or attributes then text.
- **Attribute records with defaults**: `stack`, `txt`, `btn`, `field`,
  `panel` are ordinary values; a call overrides fields by record update.
  There is no optional argument and nothing is a string.
- **The vocabulary**: `Align` (Start Center End Stretch Baseline),
  `Justify` (Lead Middle Trail Between Around Evenly), `Fill` (Natural Grow
  Wide Screen Slim Reading Broad), `Scale` (Hero Title Heading Body Strong
  Caption Tag Mono Overline), `Tone`
  (Ink Muted Faint Accent Danger Success Warning OnAccent), `Kind` (Plain
  Primary Quiet Destructive). `gap` and `pad` are steps on the spacing
  scale (0 to 6: 0, 4, 8, 12, 16, 24, 32 px), never pixels.
- **Variants** are typed: `vary = [UI.OnNarrow [UI.GapOf 1, UI.Hidden]]`,
  with `OnWide` and `OnHover`, and the `Tweak`s are the same words as the
  records.
- **Events** are std/view's typed ones, passed to `button` and `input` as
  attributes: `G.send codec Msg`, `G.sendWith codec Msg @Client.q`,
  `G.bind @Client.q`, `G.setTo @Client.open "1"`. The message VALUE travels;
  the codec stays explicit because that is how std/view types it. `*With`
  forms (`vstackWith`, `cardWith`, `pageWith`) take std/view attributes for
  keys, locals and `showIf`.
- **Theme**: `page light` owns the token scope (std/ma's day or night
  tokens: `tx-1`, `bg-surface`, `bd-subtle`, `ac`, `danger`, ...), so a
  page built here and Ma components in it share one palette during the
  move. `UI.css tree` is the stylesheet.

## How it lowers

Every node becomes the `std/view` tree the hand-written utilities give:
`Ma.element` (the per-node box reset) with one `utilities` list of typed
declarations, variants as `narrow`/`wide`/`hover` utilities, and nothing
else. `tests/std/ui.fpr` renders a page and checks the declarations per
property (each is its own atomic class), that a `text` is a dynamic slot,
that no class string or raw property reaches the stylesheet, and that
`UI.vstack { UI.stack | gap = 3, pad = 4 } kids` renders, statics,
dynamics and stylesheet, identically to the hand-written column. The
generator, the live diff, keys and the wire format are untouched.

## What it does not do yet

- Icons, images, links, tables, select and checkbox inputs: added when an
  app's rewrite needs them, not before (step 3's list).
- A theme as a value of its own (palette and scale chosen by the
  application): the tokens are std/ma's for now, by name.
- Retiring std/ma: its components stay until no application uses them;
  std/ui is its successor, with records where Ma has positions and
  without the duplicate class strings.

## What the first two rewrites taught (2026-10-15, step 3)

**todo** is a terminal application (std/term), so std/ui does not apply to
it; its goal was persistence. Its list is now a durable field,
`Live.field Live.Always @Model.items`, restored with `Live.restore`, taken
as a snapshot with `Live.start` and written by the save command with
`Live.flush` into an append-only kvlog: every change is one record, the
file is the list's history, and no path or handle lives in the model (the
command closes over the store). The terminal check reads the field's last
record. The descriptor machinery (`field`, `restore`, `start`, `flush`)
lives in std/live, which a terminal app has no other reason to import: it
wants a module of its own (`std/durable`), with std/live using it.

**logbook**'s view is std/ui end to end: `page`, `vstackWith` (the client
state declared on the reading column), `hstack`, `card`, `label`/`text`,
`input`, `button`, `keyed`, `space`, `none`. Its own `element`, `input`,
`inputAppearance` and `btn`-with-fourteen-declarations helpers are gone;
`btn` is one line over `UI.button`. The page serves with 133 atomic
utilities and no class string. Its durable field (`nextId`) and the store
were already as the design says.

What std/ui was missing, added for logbook:

- `Fill.Reading`: the reading column (capped, centred), a layout word for
  what was `MaxWidth 640, MarginX Auto, Width 100%` in the app.
- `Field.placeholder`, and the input's focus ring, resize and outline as
  part of the lowering, not the app's.
- `Txt.pre` (keep line breaks) and `Txt.hideEmpty` (hide while the slot is
  empty, std/view's `data-hide-empty`).
- `Btn.tall` (a 44px target for a phone's thumb) and `Kind.Chip` (a tag).
- `none`: the node a branch renders when it has nothing to show.

What std/view is missing, seen from here: a typed send that carries TWO
client fields (`"tags,draft"` is still a raw `G.OnClick (G.wireOpen ..)`
with a comma list, the one string left in logbook's view); a typed
`placeholder`/`rows` attribute (std/ui lowers them to `G.Att`).

Not verified in a browser: `tests/std/logbook_ws.py` fails on the
committed logbook as well (a decode error on the first frame, after the
wire change of 2026-10-14), so logbook was checked by serving it, fetching
the page (every section, input and button present, no `btn`/`inp` class,
keyed `entries`) and `--replay`. The websocket harness is the next thing to
repair.

## What inventory taught (2026-10-15, step 3 continued)

Inventory's panes (sign-in, header with tabs, items with search, sort,
chips, pager and editor, the item card with its delete confirmation, the
household pane, the admin pane with its tiles and console) are std/ui.
Its `element`, `field`, `labelled`, `btn` and `primary` helpers and the
duplicate class strings are gone; `btn`, `primary` and `tab` are one line
each over `UI.button`.

What std/ui gained for it:

- **A look as a value** (`Look`; `UI.day`, `UI.night`): the colours of the
  roles a page uses, the type face, size and line height, a backdrop.
  Inventory's `look light` is `{ UI.day | ... }` from std/appearance's
  palettes; `page` turns a look into the token scope.
- **State variants**: `OnState "pane" "items" [Inverted]` is std/view's
  `localStyle`, so a tab or a sort button shows which is current with no
  server round trip; `Always [..]` for unconditional tweaks; the tweaks
  `Inverted`, `Dimmed` (a pager at its end), `Rigid` (a chip in a
  scrolling row), `Stacked` (a row that stacks on a phone).
- **Fields that say what the browser may do**: `kind` (text, password,
  search, hidden), `suggest` (the autocomplete token), `maxLength`,
  `caps`, `spell`; and an input is never under 16px (a phone zooms into a
  smaller one). `labelled` puts a small label over an input.
- `badge`, `toast` (a tone, hidden while empty), `Kind.Pill`,
  `Scale.Overline`, `Txt.tabular`, `Txt.fill`, `Stack.scrollX`,
  `Panel.tile`, `Fill.Broad`, `textWith`/`labelWith` for a node a script
  finds by id.

What is still raw in inventory's view, each a named gap:

- The autocomplete prototypes and the feedback prototypes: nodes with
  `role`, `aria-*` and `data-ac-*` attributes whose appearance the browser
  module clones. They belong in std/browserautocomplete and
  std/browserfeedback as typed nodes that take a look; the app should only
  place them.
- The browser hooks (`data-console-scope`, `data-console-run`,
  `data-pager`, `data-sync-now`, `data-device-token`, `data-on`, `id`s
  for scripts) are `G.Att` strings the std browser modules also name as
  strings; they want to be values those modules export.
- The console's bounded scrolling box is the one raw declaration list on
  the page (a minimum and a maximum height).
- The two-field send (`"user,pw"`, `"mname,mpw"`), as in logbook.

## What pos1 taught (2026-10-15, step 3 concluded)

pos1's disk code is std/journal (`openLog`, `boot o path`, `flush j m`, the
journal threaded through `update`, the console and `rebuild`, which reads
`Journal.lines`); the seed still goes in as the first lines of an empty
shop. `Journal.open` now creates a file the path does not name yet, so the
owner's first write finds the file it expects instead of reading it as
fresh (pos1's first start on a new log hit this).

Its view (sign-in, the nav with its tabs and badges, four toast slots, the
register with its product cards and the cart the page computes, the
receipts with their opening lines, the inventory rows, the admin tiles,
console and profile) is std/ui. The 104 `G.Utilities` lists and every class
string are gone; the hooks the client and the checks read (`data-tax`,
`data-line`, `data-price`, `data-line-total`, `data-min`/`data-max`, the
`cart-*` and `pos-rtt` ids) are unchanged, and the register's arithmetic
still runs in the page. `tests/check_pos_reload.py` passes; the four panes
were driven in a browser on the day and night looks and at a phone's width
(the register stacks, the cart docks below). Of the view's sizes, the
columns of a row (`cell 96`), the cart's width and the card's are the ones
still said in pixels.

What std/ui gained for it:

- **Wrapped rows pack at the start**: a wrapping stack now sets
  `align-content: flex-start`, so cards of a fixed height in a tall area
  gather at the top instead of spreading over it.
- **`listRow` and `listItem`**: a row of a list (a hairline under it, a
  little room above and below, a height it keeps, never shrunk by the
  list), as a row or as a column that opens (a receipt and its lines).
- **`status`** is to `badge` as `text` is to `label`: a badge whose text is
  a model value; `badgeWith` takes attributes for a badge a script finds.
  The stock badge's tone now follows its text (sold out is danger, low is
  warning), which the comment had promised and the class string never did.
- **`local`**: the page's own value (std/view's `LTxt`, a local the page
  holds) shown in a text role, for the cart line's quantity.
- `Scale.Strong` (body size, heavy: a product name, a receipt number),
  `Fill.Slim` (a sign-in card's width), and a `Mono` field keeps its face
  and still gets 16px (a phone zooms into a smaller input).
- `Appearance.look light` is the household palette as a std/ui look, shared
  by inventory and pos1; the duplicate in inventory is gone. It has no
  signature: a record alias of another module (`UI.Look`) is not the
  record itself to the checker, so the value is checked where `UI.page`
  takes it.

What is still raw in pos1's view, each a named gap:

- The two-field sends (`"name,pin"` on sign-in, `G.OnBoth` on restock), as
  in logbook and inventory.
- The browser hooks (`data-tax`, `data-line`, `data-price`,
  `data-line-total`, `data-min`/`data-max`, `data-on`, `data-role`,
  `data-hide-empty` on a card, the `cart-*` and `pos-rtt` ids): strings the
  cart script (std/browsercalc) and the client also name as strings.
- The sizes: `cell w` for a row's columns, the cart's width and docked
  height, the card's width and height, the profile's maximum height.

Step 3 is complete: todo, logbook, inventory and pos1 are on std/ui, and
every durable field is a `Live.field` or a journal line. std/ma is now used
by std/ui alone (its element reset, spacing scale, tokens and stylesheet
generator) and by nothing else; folding those into std/ui and retiring
std/ma is the next move on this page.

std/ma was retired the same day: its element reset, spacing scale and
stylesheet are std/ui's own (`UI.element`, `UI.spacing`, `UI.css`); the
token names stay. qos pins an older fprisc; its `maapp` and `liveboard`
move onto std/ui when its lock advances.
