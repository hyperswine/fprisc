# Scalar F64 fast paths

Known saturated F64 `+`, `-`, `*`, `/` and all six comparisons now lower to native
instructions in the ordinary compiler path. Results and arguments retain the
existing raw IEEE bits in integer registers and frame slots; only each operation
uses caller-saved FP temporaries. No FP value stays live there over a C call or
scheduler safepoint. F64 literal splices with constant halves become immediate
raw-bit values rather than repeated calls to `f64frombits`.

The emitted operations do not fuse into FMA or enable fast-math. IEEE division
by zero still produces infinities/NaNs, and unordered comparisons are false
except `!=`. AArch64 reuses its float lowering. RV64 uses scalar D instructions.
The x86-64 lowering uses SSE2 moves/arithmetic and masks comparison results with
`!PF`: `ucomisd` sets equality and below flags for unordered input, so an ordinary
`sete`/`setb` alone would return the wrong answer for NaNs.

`FPR_NO_F64_INLINE=1` keeps arithmetic, comparisons and literal decoding on the
original C paths. The switch is part of the unit-cache tag. It is independent
of `FPR_NO_INLINE`, which controls helper-function inlining. F32 operations,
conversions, transcendentals and sqrt keep their existing C paths.

## Correctness gates

`tests/base/floatinline.fpr` compares against wrappers around the actual runtime
primitives in `tests/base/floatprobe.c`. The compiler cannot replace those
reference names with fast paths. Twenty inputs include both zeros, subnormals,
minimum normals, finite extremes, infinities, quiet NaNs and signaling NaNs.
Four arithmetic operations and six comparisons are checked on every input pair;
comparisons are tested both as Bool values and as direct branch conditions.
Finite/zero/infinity arithmetic is compared by exact result bits; NaNs by
classification because payload selection is target-dependent.

`tests/check_float_inline.py` runs all 400 pairs with helper inlining and F64
fast paths independently on/off, including warm-cache builds. It also compiles
ten functions through the real x86-64 generator, assembles the complete ELF
output, and executes the generated leaf bodies on native x64 or under Rosetta.
The Rosetta harness adapts symbol spelling and the hart TLS load only; generated
prologues, instructions and epilogues stay intact. An independent C probe checks
1,280 pairs (edge cases plus seeded random raw bits). This is a backend execution
check, not a complete x64 actor-runtime test.

The differential check is included in `tests/check_base.py` and QOS's full
sweep. QOS additionally runs the same FP-RISC/C-runtime probe on RV64 under QEMU.
The existing float regression checks wide arguments, generic calls, recursive
accumulation and float values held in structures.

## Performance

`tests/bench/floatcmp.fpr` adds a focused comparison benchmark, checking the
hand-derived result `floatcmp: 30000000`. In nine alternating paired executions
on the development macOS arm64 host with `FPR_HARTS=1`:

| Path | Best | Median |
|---|---:|---:|
| F64 fast paths | 59.9 ms | 61.3 ms |
| C reference paths | 90.1 ms | 94.7 ms |

That is a 1.50x improvement in the best times (1.54x by medians). These are
paired measurements with identical outputs, not a replacement for the existing
machine-specific benchmark baseline.

`nbody` showed only a small, noisy change in initial paired runs, approximately
1.03–1.06x. Its hot path still stages raw-bit values through frame slots and
calls sqrt. Removing primitive calls does not remove that memory traffic;
keeping locals in registers remains the next larger compiler performance step.
Do not infer a general 1.5x float-program speedup from the comparison workload.

## Verification

The final compiler builds with `make fpr`. The complete base and standard-library
suites passed. Differential edge cases passed on hosted AArch64 and RV64/QEMU;
the generated x64 leaf bodies passed under Rosetta. QOS's baseline compile gate
and two-client LiveView smoke check passed. Full-sweep outcomes and any platform
skips are recorded in QOS's matching dated baseline document.
