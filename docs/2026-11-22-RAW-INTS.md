# Raw Ints: versioned raw-word copies of Int loops

Date: 2026-11-22.
Kind: delivery record. Implements the raw-Int loop versioning sketched in
the [exact-Int review](2026-11-22-EXACT-INT-REVIEW.md) as the follow-up to
the v1.0 numeric slices (exact `Int` `1695e4de`, small immediates
`6d94bc23`).

## The problem

Exact `Int` lowers every `+ - * /` and ordering to `OArithVal`/`OCmpVal` on
tagged words, with a bignum slow path — so a running value is retagged at
every step, because that path may have made a bignum. A numeric loop pays
the tag/test round trip on every iteration even when every value stays
small for the whole run.

## The mechanism (`Codegen.RawInts`, pass `version-raw-ints`)

A loop's region (its header plus every block the header dominates) is
copied once. In the copy, the Int values the loop computes with are raw
`TInt` words:

- a value tagged from a raw Int is that Int;
- `+ - *` of two raw values is `OArithFits` then `OArithU`: the fit test
  branches away when the exact result leaves the small range, and
  `Codegen.Interval` removes the test where the operands' bounds prove the
  result fits (the existing no-overflow proof, which sees `TInt` again);
- any other Int the copy uses — a division's operand, a call's answer, a
  load, an operation on a value not known small — is computed as before and
  tested with `OIsInt`, then untagged;
- comparisons and equality of two raw values are `OCmp` on the words;
- a header parameter, or any value entering from outside the region, is
  tested once on the way in; failure enters the original loop instead.

A failed test leaves the copy mid-iteration. Each test point splits the
original block right after the same instruction, and the exit jumps there
with every live value retagged (the failing operation's exact result
computed on the generic path), so the original loop carries on from that
point: exact semantics, only slower. Original blocks a split reaches
without passing the header take their live values as block parameters, so
SSA dominance holds on the new edges.

**Soundness rests on one rule:** a value is raw in the copy only when it is
an Int that is small at run time. A tag of a `TInt` is small; a fit-tested
or tag-tested result is; a parameter is when every incoming edge passes a
raw value (the induction around the loop). Which `TVal` values are Ints is
inferred from their uses; a wrong guess fails a tag test and runs the
original loop — never a wrong answer.

Pipeline position: `version-raw-ints` runs in `Codegen.Simplify` after
loop-invariant motion and before `discharge-proven-checks` (the bounds
proof that drops the copies' fit tests), on W64 only, and only for
functions with exact-Int operations. A self tail call gets a new entry
block (stack check only) so the old entry can serve as a plain guarded
header; kept only when a copy is actually made. Regions are versioned
outermost-first, an inner loop copied within its outer loop's copy; a
region larger than 1200 instructions is not copied. `Simplify` gained
`OIsInt (OTag x) → True` folding and treats `OArithFits` as
cross-shareable; `Dump` prints it as `fits`.

Targets: A64 and RV lower `OArithFits` directly (A64 fuses it as a branch
condition — the exact operation then a 63-bit-fit compare, with a Mul
path that proves both operands 31-bit before falling to a divide check);
X64 selects it through the shared checked-arithmetic path. `Verify` and
the reference evaluator (`Codegen.Eval`) know the op: the evaluator still
computes the exact result and checks the fit, so a wrong proof shows as a
trap there.

## Gates

- `test:RawInts` (new): the four loop shapes (count-up with accumulation,
  doubling descent, mixed `k*i-1` step arithmetic, an equality-exit with a
  branch inside) lowered with `m2Policy`, versioned, simplified, verified
  by `verifyProgramWidth`, and **executed against the reference evaluator**
  — exact answers including a value that leaves the small range mid-loop
  and comes back; also asserts the fit tests survive where bounds do not
  prove them and disappear where they do. 12 checks, passing.
- `test:Interval`, `test:EncodingA64`: passing.
- `tests/run.sol`: back to its pre-slice verdicts (compile-budget green
  again after the baseline update below).
- The compile-budget acceptance: the versioning pass costs compile time
  (arm64: hello +13.0% allocation, std-live +12.6%, pos1 +11.8%
  allocation and +27.0% peak live vs the old baseline — stable to ±0.1%
  across runs). Accepted as the cost of the optimization and recorded in
  `tests/compile_budget.json` in this commit, per the check's own
  contract; the check then passes at ~0% deltas.
- The x86-64 Linux baseline (`ghc-9.6.6 x86_64-unknown-linux`, the CI
  key) was not re-recorded with it, so sol-checks' compile-budget failed
  on every push from c093f9af on (hello +13.1%, std-live +10.2% over the
  10% margin in CI run 44983604284; b63ab5a2 just before was -3.7% and
  -4.5%). Re-recorded on 23 Nov 2026 from CI run 45124465365 (main at
  9200fec3): hello 1742539856 B allocated / 47262816 B peak, std-live

  code it adds.

## Limits

- W64 only (`intervalWidth` gates the pass); the 32-bit targets keep the
  tagged path.
- The copy is only taken when the region is small enough (1200
  instructions) and the loop has an entry path to guard; a loop the
  analysis cannot guard runs tagged.
- Runtime benefit requires the bounds proof (or a run that never escapes);
  a loop whose values genuinely leave the small range pays the copy's
  tests and then the original loop — slower than before by the guard
  tests, exact as ever.
- Raw-Int inference is use-based; a value guessed Int that is not fails a
  tag test into the original loop (correctness never depends on the
  guess).
