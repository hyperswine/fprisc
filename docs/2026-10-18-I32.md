# I32: portable wrapping 32-bit integers

Implemented 2026-10-18. `I32` is a distinct integer type with the full
32-bit two's-complement range, `-2147483648..2147483647`. It supports the
same integer core in Base and manual Builtin on RV32, and in Base and
Builtin on 64-bit targets. The integer core also supports ARC64.

There are no I32 literals: construct values with `I32.ofInt` or `I32.parse`.
The compiler refuses implicit mixing with `Int`, `I64`, `Word` or floats.
For example, `I32.ofInt 1 + I32.ofInt 2` is valid; `I32.ofInt 1 + 2` is not.
Exponentiation (`^`) is refused for I32.

## Arithmetic and bits

`+`, `-` and `*` wrap modulo `2^32`. Signed comparisons use the usual
two's-complement ordering. `/` truncates toward zero, and `%`/`I32.rem`
have the dividend's sign. `I32.divU`, `remU`, `ltU`, `gtU`, `leU` and
`geU` interpret the same bits as unsigned integers.

All four division/remainder operations panic on a zero divisor with
`I32: division by zero`. Signed `INT32_MIN / -1` panics with
`I32: division overflow (INT32_MIN / -1)`. The corresponding remainder is
zero.

`I32.and`, `or`, `xor`, `not` and `neg` operate on all 32 bits. `shl`,
logical `shr`, arithmetic `sar`, `rotl` and `rotr` take an `Int` count
modulo 32, including negative counts. `clz`, `ctz` and `popcnt` return
`Int`; `clz 0` and `ctz 0` are 32.

`I32.str` renders signed decimal, `strU` unsigned decimal, and `hex`
lowercase hexadecimal without a prefix or leading padding. Generic
rendering, equality, containers and `keep` preserve I32 values, including
the pointer-like bit pattern `0x80000000`.

`I32.parse` accepts optional `+`/`-`, decimal or `0x` hexadecimal, and
underscores strictly between digits. Magnitudes through `4294967295`
are accepted as bit patterns; a leading minus negates modulo `2^32`.
Thus both `4294967295` and `0xffff_ffff` produce `-1`.
Larger magnitudes, missing digits, junk and misplaced underscores return
`Err`. This is a bit-pattern parser, rather than a signed-decimal-only
parser.

## Conversions

| API | Contract |
|---|---|
| `ofInt : Int -> I32` | Take the low 32 bits, wrapping |
| `toInt : I32 -> Result Int String` | Sign-extend, then check the target's tagged Int range |
| `toIntU : I32 -> Result Int String` | Zero-extend, then check the target's tagged Int range |
| `ofI64`, `toI64`, `toI64U` | Low 32 bits, signed extension, unsigned extension |
| `toF32`, `toF64`, `toF32U`, `toF64U` | Signed or unsigned numeric conversion, with the float type's normal rounding |
| `ofF32`, `ofF64`, `ofF32U`, `ofF64U` | Truncate toward zero, then check the signed/unsigned 32-bit range; return `Result I32 String` |
| `ofF32Bits`, `toF32Bits` | Reinterpret the 32-bit IEEE representation, preserving negative zero and NaN payload bits |

The `toInt` and `toIntU` Result signatures are the same on every target.
On 64-bit targets all I32 signed and unsigned values fit. On RV32 the
tagged Int range is `-1073741824..1073741823`; out-of-range conversions
return `Err` rather than dropping a bit. Their diagnostics identify
`I32.toInt` or `I32.toIntU` and the 31-bit limit.

Float range checks happen after truncation. For example,
`I32.ofF64 -2147483648.75` succeeds with `INT32_MIN`, and
`I32.ofF64U -0.9` succeeds with zero. NaN, infinities and truncated values
outside the appropriate range return `Err`. An unsigned conversion can
round up when producing F32: `I32.toF32U (I32.ofInt -1)` represents
`4294967296`, so
converting it back with `ofF32U` returns `Err`.

The I64 and float bridges are supported by Base. They are explicitly
refused in ARC because their ownership adapters have not been audited.
RV32 manual Builtin supports the integer-only I32 core and explicitly
refuses these wide bridges. Sol currently has no I32 runtime and refuses
I32 programs.

## Representation and allocation

On a 64-bit target, I32 is a tagged, sign-extended 32-bit integer. Its low
tag bit distinguishes it from pointers; arithmetic normalizes every
result back to 32 bits. Core arithmetic does not allocate.

On RV32 manual ownership, all 32 bits live in a `T_BITS` leaf with I32
variant 7. This differs from the 31-bit tagged Int representation and
keeps pointer-like bit patterns safe in generic object operations. RV32
I32 operations allocate boxes; this does not claim allocation-free RV32
arithmetic or RV32 ARC support.

## Executed checks

The shared integer suite is
[`tests/tangnano20k_i32_core.fpr`](../tests/tangnano20k_i32_core.fpr).
[`tests/i32.fpr`](../tests/i32.fpr) adds every wide bridge, float bounds,
NaN/infinity refusal, bitcasts, generic callbacks, mixed record vectors,
keep, equality and rendering. Large integer inputs come from strings so
the source runs unchanged with RV32's smaller Int range.

[`tests/check_i32.py`](../tests/check_i32.py) passed:

- Native 64-bit Base, plus five expected division/remainder panics.
- A native 10-million-step I32 linear-congruential loop: **zero allocated
  bytes**, final bits `0x586b8080`, checked against an independent affine
  reference. No printing, strings, Results or containers occur in the
  measured loop.
- The full Base suite in QEMU RV32IM and RV32IMC, plus five expected
  RV32 division/remainder panics.
- The integer-only manual Builtin suite in QEMU RV32IM. Its test host
  copies the production board host and substitutes only the 16550 UART
  registers; this is not FPGA proof.
- The ARC64 integer suite under QEMU with `ARC_CHECK=1`, including zero
  live allocations after the shared core returns.
- Independent consuming-adapter checks under native ASan/UBSan.
- Twelve mixed-type/exponentiation refusals across A64 and RV32.
- Explicit refusals for ARC wide bridges, RV32 Builtin wide bridges and
  Sol I32; a RAW64 integer arithmetic program compiles.

Final checks on the physical Tang Nano 20K at 48 MHz with RV32IMC passed:

- The 219,648-byte full Base image printed all integer, wide-bridge,
  generic-container and final board success markers, followed by
  `FPR EXIT 0` and ROM `DONE`.
- The 18,100-byte divide-by-zero image reported `I32: division by zero`,
  followed by `FPR EXIT 1` and `DONE`.
- The 18,156-byte signed-overflow image reported the explicit
  `INT32_MIN / -1` panic, followed by `FPR EXIT 1` and `DONE`.

Image hashes and logs are recorded in
`docs/evidence/2026-10-18-i32.json` and `build/i32-board/results.json`.
These physical checks are separate from QEMU and native evidence.

Run the checks after rebuilding the compiler and matching runtime:

```sh
python3 tests/check_i32.py --native
python3 tests/check_i32.py --qemu --builtin --arc64 --out build/i32/qemu-matrix
```

Native results are in `build/i32/results.json`; target results are in
`build/i32/qemu-matrix/results.json`. The driver saves each passed case
before continuing and marks its final report complete only after every
requested leg passes. Generated negative programs and their compiler or
runtime logs remain next to the results.
