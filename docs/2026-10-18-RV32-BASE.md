# RV32 Base on Tang Nano 20K, 2026-10-18

Later on the same day, [I32 was implemented and tested](2026-10-18-I32.md).
The initial-port I32 refusal recorded below describes the earlier checkpoint;
the current compiler accepts I32.

The existing Base compiler/runtime now supports the board's RV32IM/IMC
pipeline with F32, F64 and full-width I64, using the same single-threaded
capability boundary as the RV64 board host. This does not add scheduling,
processes, interrupt handling or automatic temporary reclamation.

## Representation and compiler

`V` and ordinary fields remain 32-bit. An Int is a signed tagged 31-bit
payload, -2^30 through 2^30-1. `Word` and `Addr` preserve all machine bits in
boxed leaves. `I32` is not implemented in this checkout: its API is a proposal
in `2026-10-12-MEMORY-I32-REFINEMENTS.md`, and compilation of `I32.ofInt`
explicitly fails. The tests distinguish that refusal from passing Int and
full-width Word operations.

I64 uses a fixed 24-byte leaf with a uint64 payload at byte 16 on both targets.
Its wrapping arithmetic, signed and unsigned operations, parsing, text,
bitcasts and checked conversions work on RV32. `hiWord`, `loWord` and
`fromWords` support complete unsigned 32-bit halves without squeezing them
into Int. Legacy `hi` and `lo` trap when their unsigned result does not fit.

F64/F32 are immutable boxed numeric leaves on RV32; RV64 keeps its existing
raw-bit ABI. Compiler revision 47 pools RV32 literal boxes in rodata, including
all sign and payload bits, so loop constants allocate nothing. Computed
floating results allocate boxes. Floating vector callbacks remain generic;
integer vector kernels remain enabled. Generic numeric rendering, retention,
vector copying and RV32 aggregate equality account for boxed leaves and NaNs.
Floating conversions refuse NaN/out-of-range values before a C integer cast;
the tagged range is checked after truncation toward zero.

The software floating-point library remains pinned to Berkeley SoftFloat
`a0c6494cdc11865811dec815d5c0049fba9d82a8`, RISCV specialization. RV32 uses
portable multiword primitives instead of the RV64 platform's GCC __int128
override, and links RV32IM libgcc helpers. The linked image checker refuses
A/F/D, wrong XLEN, hard-float ABIs and unrequested compressed instructions.
The shared C runtime also compiles for an RV32 F-only target without emitting
an unsupported double-precision square-root instruction.

## Board host and loader

The startup clears BSS using the target word size. RV32 reads mcycle using
a high/low/high retry sequence. Timeouts and sleeps keep 64-bit counters;
Int-returning clocks use the documented positive modulo-2^30 contract.

HaskPlayground's extended ROM adds Q/V/H/T to RV32. Q accepts a 32-bit word
count bounded to 2 MiB on SDRAM; V reads the uploaded words back through RAM
and returns their XOR. H enters high RAM; T probes UART without RAM access.
The SDRAM ROM stack is at 0x80800000, outside accepted images. A separate
BRAM ROM limits Q to 65,280 bytes and reserves 256 bytes for the loader stack.
Legacy P/R/M/X remain; legacy P's exact-64-KiB BRAM stack overlap is unchanged.

The tested image is RV32IMC, 48 MHz, a 2 KiB cache and all 8 MiB SDRAM:

```

SHA256 c0008784680cb6a0cd6cdba59d0d6541304d72ae42e74ccaf232a982510d82cf
```

Gowin reports 50.987 MHz Fmax, +1.221 ns worst setup slack, and zero setup/hold
violations. These are internal checks; the physical runs below are functional
evidence, not SDRAM I/O/PVT signoff. Only volatile SRAM was programmed.

## Validation

Reproducible checks:

```bash
make fpr
FPR_XLEN=32 machine/tangnano20k/build-softfloat.sh
python3 tests/check_rv32_base_codegen.py
python3 tests/check_rv32_numeric_runtime.py
python3 tests/check_tangnano20k_rv32_base.py
python3 tests/check_tangnano20k_virtual.py
python3 tests/check_tangnano20k_softfloat_vectors.py
python3 tests/check_tangnano20k_clock.py
```

The direct C/QEMU probe tests numeric ABI independently of generated FP-RISC:
full-bit floats, I64 operations, nested copies, float-vector copies, NaN and
signed-zero equality, and expected failures for oversized I64 halves and
invalid floating conversions. The FP-RISC/QEMU checks cover both IM and IMC:
numeric primitives, Int limits, 32-bit Word operations, mixed record vectors,
and real framed UART file/environment/input/time services. Native I64 and
numeric tests pass; existing RV64 software-float vector and clock/refusal RTL
checks pass. Compile checks cover cold/warm caches and explicit I32 refusal.

Physical runs at 48 MHz passed Int limits, wide numeric arithmetic and UART
services. The UART-service image is 315,928 bytes, well above the old 64 KiB
upload limit. The runner verified RAM XOR before execution and required
`FPR EXIT 0` followed by `DONE`.

The classifier uses its existing entropy, binning, training and prediction
algorithm. Only its data generator was ported from machine Int state to I64
so its original modulo-2^31 LCG still produces exactly the same dataset.
Both physical successes match an independent Python reference, including
every prediction digest and root split:

| train / test | bins / depth / minimum leaf | nodes | train hits | test hits | board training and scoring time |
|---|---|---|---|---|---|
| 32 / 16 | 4 / 3 / 2 | 11 | 27/32 | 15/16 | 1.188413 s |
| 128 / 64 | 8 / 5 / 2 | 23 | 124/128 | 61/64 | 4.760035 s |

The 512/128-row, 16-bin configuration exhausts the 8 MiB heap in both QEMU and
on the physical board, with `Base panic: Builtin: out of memory` and
`FPR EXIT 1`. This is not a classifier success. Boxing computed floating values increases temporary
allocation, even though ordinary fields are smaller. The current allocator
does not automatically reclaim those temporaries; this is a capacity boundary
for a future memory-management change, not evidence of arithmetic failure.

Detailed hashes and execution outputs are retained in

directories. Source changes remain reviewable in the two repositories; unrelated
printer and POSIX network work is outside this experiment.
