# RV32 scalar generation and private indexed memory

The scalar generator now applies normalization, private-slot promotion into
`s1` through `s5`, frame-slot forwarding/dead-store cleanup, direct branch
conditions and checked primitive expansions to RV32 as well as RV64. This is
code generation revision 43. RV32 still uses four-byte values and fields,
eight-byte object headers, and tagged Int range `-2^30 .. 2^30-1`.

The expansions are parameterized by the target: `lw/sw` frame accesses,
31/63 sign shifts in overflow guards, 15/31-bit small-multiply guards and
12/16-byte String byte offsets. Wider multiplication, arithmetic overflow,
division by zero, invalid character indexing and invalid shift counts retain
the runtime slow path and its diagnostic. Hardware F64 expansions remain
64-bit only. ARC, raw exports, F64 and I64 support on RV32 are unchanged.

The shared bit runtime now refuses indexes/counts outside `0..XLEN-1`,
including the BITMASK offset. It previously accepted `32..63` on RV32,
which invoked undefined C shifts. The RV32 diagnostics now say `0..31`;
the existing RV64 `0..63` diagnostics are preserved.

`FPR_NO_RV32_FAST=1` keeps the previous RV32 scalar path for differential
checks. `FPR_NO_REGISTERS=1` independently disables register promotion. The
assembly unit caches and executable cache distinguish these modes.

Inline expression and branch dispatch require the canonical primitive
identity. A user function named `charAt`, `+` or `<` keeps its own behavior;
recognizing its spelling does not license builtin instructions. Revision 43
fixes this shadowing defect on RV32 and the existing RV64 fast path, with a
fresh unit-cache namespace.

## Indexed manual memory operations

In manual Builtin code the compiler recognizes a private address that is
used for exactly one memory access and immediately released:

```fpr
get p i = a = Addr.add p i; v = Mem.read8 a; _ = Rc.release a; v.
put p i v = a = Addr.add p i; _ = Mem.write8 a v; Rc.release a.
```

The result calls an internal checked indexed primitive, with the same base
and offset evaluation order, alignment check, volatile HAL access and result
representation. The temporary address is never allocated; its release still
yields Unit. Read/write widths 8, 16, 32 and Word are covered. A 32-bit/Word
read still boxes its returned Word in the manual ABI.

The pattern declines escaped/retained/aliased addresses, shadowed primitives,
intervening actions and effectful write arguments. Reused variable names can
conservatively decline too. The function's occurrence ledger is built once;
the pass does not repeatedly scan the rest of a long block. This is not a
general escape analysis or an ownership ABI change. Removing the temporary
allocation reduces memory requirements and can avoid an otherwise exhausted
heap. `FPR_NO_INDEXED_MEMORY=1` preserves the previous boxed operation for
comparison and uses a separate unit/executable cache key.

This pass applies to manual Builtin on both widths. The separate Tang Nano
RV64 Base host does not acquire the manual memory API or actor regions from
this change.

## Executable checks

```sh
make fpr
python3 tests/check_riscv_scalar.py
python3 tests/check_builtin.py
python3 tests/check_registers.py
python3 tests/check_tangnano20k.py
```

The new gate executes RV32 and RV64 under QEMU with a test-only `virt` machine
adapter. It compares fast/indexed, previous/boxed, fast/boxed and warm-cache
fast modes; each positive execution also checks 285 arithmetic results
against independently written C arithmetic. The source fixture checks integer
boundaries, higher-order calls, CAF effects, static and allocated Strings,
bit operations, all indexed access widths, allocation-count recovery and
patterns that must remain boxed. Separate negative programs check arithmetic
overflow, division by zero, negative character indexing and misalignment in
both modes, plus shift/index/bitmask-offset refusals at the word boundary.
An imported helper makes the warm unit-cache checks non-vacuous. The RV32
assembly is checked for illegal XLEN instructions and shift immediates;
linked ELF ISA attributes confirm integer-only IM/Zicsr/Zifencei.
An additional fixture executes recursive `charAt`, arithmetic and comparison
definitions that shadow builtins, including comparison values and direct
branch conditions, plus a local function parameter named `charAt`. Both
widths run it with ordinary inlining enabled and disabled; RV32 also compares
the previous scalar path.

The same positive fixture also executes as RV32IMC and RV64IMC under QEMU.
ELF attributes permit C only in this explicit mode, and disassembly must
contain actual 16-bit instructions. Its linked text measures 23,972 to
18,998 bytes on RV32 and 24,804 to 20,050 bytes on RV64, with identical
checked output. This measures code density; physical processor and throughput
results are recorded in the [board checkpoint](2026-10-16-TANG-NANO-PERFORMANCE.md).
The default test remains IM.
These are execution/ISA checks, not FPGA timing qualification.

The existing Builtin gate passed its RV64 QEMU and sanitizer checks. The
register gate passed effect/call differential checks, three-backend emission
and 285 independently checked x64 executions. The Tang Nano host gate covers
the linked RV32 ISA/ABI, refusals and UART driver; physical tests require its
explicit `--port` argument.

On the current board workload sources, linked RV32 text size changes below
compare the old scalar/boxed mode against the default mode, using the same
current heap and test machine adapter:

| Workload | Previous bytes | Default bytes | Address-add sites replaced |
| --- | ---: | ---: | ---: |
| sieve | 12,812 | 12,204 | 7 |
| sort | 14,620 | 15,300 | 12 |
| matrix | 13,744 | 15,384 | 9 |
| compute | 9,892 | 10,252 | 0 |

Inlining checked arithmetic can increase text size even while eliminating
runtime calls, slot traffic and temporary allocations. These are static
instruction/code-size observations; board execution time must be measured
on a matching FPGA image before claiming a speedup.
