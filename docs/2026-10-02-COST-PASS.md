# The cost pass: work and alloc equations for every function

Date: 2026-10-02. Kind: implementation record. Stage 1 of
[2026-10-02-RESOURCE-BOUNDS.md](2026-10-02-RESOURCE-BOUNDS.md).

```
fpr build --cost prog.fpr
```

prints, for every function in the root unit, two upper bounds in the
function's own parameter names:

```
  count     work  <= 5·(n + 1)
            alloc <= 0 bytes
  lsum      work  <= 6·(len l + 1)
  twice     work  <= 2·work f + 2
            alloc <= 2·alloc f bytes
  view      work  <= ω(filterGo@5cc2…) + 14·ω(str) + 20·ω(strcat) + 86
            opaque: filterGo@5cc2…, str, strcat
```

Units: `work` is abstract operations (each arithmetic, comparison,
projection, tag test, call and allocation is one). `alloc` is the bytes a
constructor cell asks the allocator for, `8 + 8·fields` exactly as
`runtime/fpr.h` lays it out; nullary constructors are statics and cost 0.
The allocator's block preheader and rounding belong to the target manifest
(stage 3), not to the program.

## What it is

[`Cost.hs`](../compiler/Cost.hs) runs over the Core every unit is generated
from (`compileTop` plus `liftFix` of the whole typed program), after
inference, safety and linearity, and before code generation. One transfer
function per construct:

| Core | work | alloc |
|---|---|---|
| literal, local | 0 | 0 |
| `CMk` with n fields | 1 + fields | `8 + 8n` + fields (0 for n = 0) |
| `CTagEq`, `CProj` | 1 + inner | inner |
| `CIf` | 1 + cond + max(arms) | cond + max(arms) |
| `CLet` | sum | sum |
| saturated call to a global g | 1 + args + g's equation with the arguments substituted | likewise |
| partial application | 1 + args | a closure cell |
| call within the recursive group | 1 + args | args |
| call through a parameter p | 1 + args + `work p` | args + `alloc p` |
| a primitive in the small declared table (arithmetic, comparisons, Word ops, `error`, `drop`) | 1 | 0 |
| any other primitive | ω(name) | ω(name) |

Functions are processed in dependency order over the Core call graph. A
recursive group whose every member has a frontend-verified measure
(`Safety.measureCheck`, stage 0) costs `(measure/step + 1) · max(per-call
bodies)`; partners' parameters are opaque in that max, as a Fold callee's
are in stdcheck. A group without a complete set of measures is ω(f) for
both quantities. Nothing is guessed.

Substitution: an argument that is linear in the caller's parameters (`n - 1`,
`2 * k + 3`) substitutes into the callee's equation; a parameter's length
substitutes for `len`; a function-valued argument that is a known global
substitutes that global's equation with its own parameters made opaque;
anything else is `?`. A literal list has a known length. The clause lowering
binds each pattern variable to its argument, so a let-bound alias of a
parameter is the parameter.

The simplifier is one bottom-up pass of smart constructors: constants fold,
like terms collect (`3·ω(strcat)`), max arms that differ only by a constant
keep the largest, a constant added to a lone max moves into its arms, and a
zero arm never wins. A first version re-simplified subtrees at every level
while distributing and did not finish on `examples/todo.fpr`; it now reports
in under three seconds.

## What the first real report says

`examples/todo.fpr` closes `changed`, `codec`, `save`, `subs` to numbers.
`update` and `view` are sums of ω terms: `lengthGo`, `mapGo`, `filterGo`,
`imapGo`, `revOnto` in the prelude are recursive helpers with no measure, and
`str`, `strcat`, `strlen`, `substr`, `print` are primitives with no declared
cost. That is the honest state of the prelude, and it is exactly the list
stage 2 has to work through: measures on the prelude's recursion, declared
bounds on its primitives. The pass is information only; nothing is checked
against a declaration yet.

Not covered: Sol (the bytecode profile has no cost pass); `live` memory
(stage 4); `Apply` through a computed head is `?`.

## Tests

`tests/check_cost.py`: `tests/measure.fpr` closes `fact` to `5·(n + 1)`,
`lsum` to `6·(len l + 1)`, `sumTo` to `6·((-1)·i + lim + 1)`; the mutual pair
to `5·(n + 1)` each; `tests/cases/cost_ho.fpr` gives `apply` `work f + 1`,
`twice` `2·work f + 2`, and `useIt` the number 11 once `inc` is supplied; a
two-field cell is 24 bytes; `todo.fpr` reports within the time bound.
