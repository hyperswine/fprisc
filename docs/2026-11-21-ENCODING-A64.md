# A64 encoder slice: the shared instruction vocabulary

Date: 2026-11-21.
Kind: delivery record for slice 1 of the
[merge plan](2026-11-21-MERGE-PLAN.md) (finding 1 of the
[architecture review](2026-11-18-COMPILER-ARCHITECTURE-REVIEW.md)), after
the decision to keep the JIT tier permanently.
Host: macOS arm64 (darwin 27.2.0), GHC 9.8.2. Encoding oracle: the system
assembler (`as`), words cross-checked by `objdump`.

## What landed

`Compiler/Encoding/A64.hs` — one description of each A64 instruction form
both native tiers emit, with two interpreters:

- `encode :: Insn -> Either String Word32` — byte assembly with real field
  range checks (imm9/imm12/imm14/imm19/imm26, ldp/stp imm7, movz half/hw).
  The pre-conversion hand encoder **silently masked** branch deltas to
  their field widths; out-of-range is now a named error
  (`a64 encode: field out of range in <rendered instruction>`).
- `render :: Insn -> String` — the GNU-as dialect the AOT .s path speaks,
  ready for the AOT emitter's per-family adoption (slice 2).
- `movImm64`, condition codes, little-endian `insnBytes`.

`Sol/AsmA64.hs` (the JIT assembler) now builds `Insn`s instead of packing
words: its 188 lines keep the register plan, label/fixup machinery and
KIR-to-instruction lowering, and carry zero instruction definitions. Every
previously-inline magic word became a named constructor — including the
full decode of the floored-division correction sequence, which the old
file's inline comments never stated:
`sdiv; msub; cbz` (remainder 0) `; eor` (sign compare) `; tbz #63`
(same sign skips the floor adjustment) `; sub; mov`.

## Byte-identity evidence

- `test:EncodingA64` (new, in `make unit-tests`): **49 constructors pinned
  to GNU-as words** (each literal was assembled from the matching spelling
  and `objdump`-verified; several of my first-draft expectations were
  wrong and the oracle corrected them — the pinning is genuine, not
  transcribed), 9 range checks asserting `Left`, 7 render checks.
- End-to-end differential, pre-change binary vs new: `tests/run.sol` full
  suite outputs differ ONLY in compiler-GC allocation counts (±0.01%), one
  wall-clock line and the reactor fixture's temp-dir nonce; all 23 check
  verdicts identical. `linreg`, `physics`, `mandel` (the JIT-heaviest
  examples — Numeric gradient descent, integration, escape-time) stdout
  byte-identical. REPL session smoke: JIT-compiled arithmetic and a
  transactional write/read commit behave identically.

## Decisions recorded

- `assembleA64` keeps its `Unit -> [Word8]` signature: encode failures are
  `error` with the rendered instruction named (the old behavior for
  unknown labels; previously-impossible diagnostics for ranges). Kernel
  functions are far below any branch range; plumbing an Either through
  `HandJIT` is deferred until a consumer exists.
- `TbzX`'s bit field is 0..63 (b5 folds bit ≥ 32 into the encoding base) —
  the first draft's `bit > 62` guard wrongly rejected the DivI sequence's
  own `tbz x9, #63`.
- `MulX` = MADD with Ra = xzr; `MSubX` carries the real 4-register form;
  `EorXReg` (not `ands` — the DivI sign trick is an XOR of remainder and
  divisor) — all pinned by the oracle rather than by reading comments,
  three of which the oracle proved wrong or missing.
